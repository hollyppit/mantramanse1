# Agentic RAG 실행 기능 — 배포 전 검증 보고서

## 구현 결과

외부 자동 연구, 예산 예약·정산·차단, KST 일일 실행, 저위험 자동 게시, 관리자 승인, 개별 롤백을 코드와 로컬 테스트에 연결했다. 기존 `ik:d:*`, `src:*`, R2 원본 파일 및 승인·게시 상태를 자동 연구가 덮어쓰는 경로는 없다. 운영 배포·운영 SQL 적용·실제 유료 API 호출은 수행하지 않았다.

### 구성

| 파일 | 역할 |
| --- | --- |

## 원본 보존과 버전 관리

- 원본 지식 및 자료는 읽기만 한다. 연구 실행 상태와 보강본은 `ik:agentic:runtime`에 별도로 저장한다. 1단계 진단·후보 키도 보존한다.
- 기존 ID의 보강본은 기존 ID를 유지하며, 원본 승인/게시/reviewedAt를 덮어쓰지 않는다. AI 승인과 실제 보강본 게시를 `approval`, `publication`으로 분리한다.
- 원본 전체 레코드 해시가 달라지면 해당 보강본을 사용하지 않는다. 관리자의 원본 수정·승인·게시 변경이 우선한다.
- 동일한 결론·조건·예외·학파의 지식은 기존 ID에 근거를 연결한다. 조건/예외/결론이 달라지면 별도의 미게시 변경 후보로 보관한다.
- 자동 근거 보강 시 원본 제목·본문·조건·챕터·기존 출처를 그대로 보존하고 출처만 추가한 서비스 버전을 만든다.
- 이전 버전·신규 버전·출처·변경 이유·실행 주체·시각·검색 버전을 이벤트에 기록한다. 롤백 이후에도 후보와 과거 이벤트는 삭제하지 않는다.
- 개별 롤백은 해당 ID의 현재 보강본만 이전 보강본 또는 원본으로 복원한다. 다른 지식의 게시본에는 영향을 주지 않는다.
- 원본 지식 자체의 기존 편집 이력 20개 제한은 이 구현의 변경 대상이 아니다. **신규 연구·게시 이력은 자르지 않는다.**
- 런타임 상태는 공개 읽기 20초 메모 캐시에서 제외하고, 연구 버전을 AI 검색/합성 캐시 키에 포함한다. 롤백 후 새 요청은 복원된 지식과 출처로 검사한다. 이미 실행 중인 요청의 응답을 소급 변경하지는 않는다.
- `legacyOnly` 설정은 보강본 사용을 중단하고 기존 지식만 사용한다. 기존 게시 지식을 비공개 처리하지 않는다. 저장 장애 시에도 서비스는 원본 읽기로 복귀한다.

## 외부 연구 및 검증

1. 진단 결과의 근거 부족·충돌·출처·조건 항목을 우선순위로 정렬하고 기존 과제의 완료 이력을 확인한다.
2. 원자적으로 예산을 예약한 뒤 Brave Web Search를 호출한다. 재시도도 과제의 최대 검색 요청 수에 포함한다.
3. 관리자가 승인한 **정확한 HTTPS origin**만 수집한다. 차단 호스트, IP·로컬·내부 호스트, URL 사용자 정보, 임의 포트, 리다이렉트는 거절한다. 출처 allowlist는 신뢰할 수 있는 공개 문헌 서버만 등록하는 정책이다. DNS 핀닝이나 임의 웹 크롤러는 구현하지 않았다.
4. 저자·분류 A~D·이용 조건·권리 확인 링크와 상업 이용/인용/저장 권한을 등록해야 본문을 수집한다. AI 생성 자료는 근거로 등록하지 않는다. 권한을 알 수 없는 자료는 자동 본문 저장·게시에 사용하지 않는다.
5. 텍스트/HTML만 지원한다. 응답을 최대 100KB로 제한하고, 원문에서 사용할 구간을 제한한다. PDF/OCR 연구 수집은 현재 지원하지 않으며 실패 원인을 기록한다. 기존 PDF 업로드 기능은 유지한다.
6. 외부 문서의 명령, 일부 개인정보/위험 표현을 차단하고, OpenAI 호출에 외부 텍스트는 자료임을 명시한다. 출력은 JSON으로 파싱하고, 원문 인용문·URL·적용 조건·중복·충돌을 서버에서 검사한다.
7. 원문에 없는 인용, 미지원 조건, 빈 적용 조건, 불완전한 모델 응답, 위험 표현은 게시하지 않는다. AI 점수만으로 원문 검증을 대체하지 않는다.
8. `kind`로 근거/조건/예외/해석/기본 개념/방법을 구분한다. 방법·계산·핵심 규칙 변경은 별도 회귀 검증 배포 경로가 필요하므로 이 게시 API에서 거절한다.

자동 게시는 원문에 기존 결론이 그대로 존재하고, 조건과 결론이 유지되며, 출처의 자동 근거 사용이 허용되고, A~C 자료이며, 충돌이 없는 보강에 한정한다. 단순히 AI가 `evidence`라고 출력하는 것으로 허용하지 않는다. 새로운 설명은 보수적으로 검토 대상으로 남긴다. 기본 개념도 엄격한 직접 인용·조건·중복 검사를 통과해야 한다. 관리자 승인이 필요한 해석은 UI에서 이전/신규 조건과 결론·출처를 비교할 수 있다.

## 예산과 일일 실행

- 금액 단위 USD. 단가는 관리자 설정이며 모델별 실요금은 하드코딩하지 않았다. 기본 예산 0, 자동 연구/자동 게시 OFF.
- 일일·월간·과제당 예산, 일일 과제 수, 검색 수, 문서 수, 출력 토큰, 입력 바이트, 최대 재시도 2회를 제한한다.
- 유료 호출 전 과제 전체의 보수적 최대 비용을 원자적으로 예약한다. 동시 실행이 예약 비용을 초과 사용할 수 없다. 검색/문서/AI/설정된 저장 비용을 포함한다.
- 토큰 비용은 UTF-8 바이트 기반 입력 상한과 출력 토큰 상한으로 예약하고, 응답 usage로 집계한다. 응답 모델이 설정 단가 모델과 다르면 연구를 중단한다. 검증되지 않은 모델 별칭을 요금 추정에 사용하지 않는다.
- 응답 유실·타임아웃 등으로 비용을 확인할 수 없으면 예약 상한을 회계 비용에 반영하고 불확실성을 기록한다. 실제 청구액을 확정했다고 표시하지 않는다. 호스팅 사업자의 실제 스토리지·트래픽 청구와의 별도 대조는 필요하다.
- KST 날짜·월 경계에서 이미 사용한 비용과 남은 예약을 구분해 다음 날짜/월로 이월한다. 새 예산이 부족하면 호출 전에 중단한다.
- 스케줄러는 1분마다 체크포인트 하나를 진행한다. 서버의 KST 실행 시각 이후 하루에 한 번 새 예약 연구를 시작한다. 완료 과제의 재연구 대기 기간은 기본 30일이다.
- 중복 실행 잠금, 저장 충돌 검사, 단계별 저장을 사용한다. 중지 도중 완료된 호출은 체크포인트를 보존하고, 재개 시 다시 수집하지 않는다.
- 만료된 실행 단계는 외부 비용 발생 여부가 불명확할 수 있으므로 자동 재호출하지 않는다. 관리자 복구가 해당 단계 비용을 보수적으로 정산하고 실패 처리한 뒤 나머지 과제를 진행한다.
- 전체 진단은 기존 설계대로 동기 수행한다. 대규모 운영 DB에서 진단 시간과 subrequest 제한은 검증 환경에서 측정해야 한다. `planning` 단계의 프로세스 중단도 관리자 만료 복구에서 정리하고 새 계획을 시작할 수 있다. 계획 단계에는 유료 호출이 없다.

외부 제공자는 테스트용 HTTP 응답을 모의했다. 실제 Brave/OpenAI 유료 연구를 수행했다고 주장하지 않는다. 현재 실행 환경에 해당 API 키와 Supabase 검증 DB 설정이 없으며 PostgreSQL 실행기도 없어, SQL은 정적 검사 및 RPC 계약 검사까지만 했다. 실제 Supabase의 함수 권한·RLS·원자성 및 제공자 실호출은 배포 전 검증 환경에서 확인해야 한다. 기존 영상/PDF 전체 브라우저 회귀를 새로 전부 실행한 것은 아니다.

## 배포 전에 필요한 연결

비밀 값은 채팅이나 소스에 붙이지 않고 Cloudflare의 서버 Secret/보호된 환경 변수에 설정한다.

- Pages: 기존 `GLOSSARY_KV`, `ADMIN_PASSWORD`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`.
- 신규 Pages Secret: `BRAVE_SEARCH_API_KEY`, `OPENAI_API_KEY`, `RAG_SCHEDULER_SECRET`.
- Scheduler Worker: `RAG_API_ORIGIN`(승인된 대상 Pages origin), 동일 `RAG_SCHEDULER_SECRET`. 관리자의 비밀번호를 스케줄러에 배포할 필요가 없다.
- 관리자 설정: 정확한 AI 모델과 계약 단가, 출처 권리 등록, 일간/월간/과제별 예산. 값이 누락되면 연구를 시작하지 않는다.
- 기존 SQL 스키마를 초기화하지 않고 별도 migration의 RPC만 추가한다. 함수는 서비스 역할에서만 실행 가능하고 `ik:agentic:runtime`만 변경할 수 있다.
- Supabase가 없거나 CAS migration이 적용되지 않으면 유료 연구 실행을 거절한다. 단순 KV의 read-then-write를 잠금으로 가장하지 않는다.

## 승인 후 배포 절차 (아직 실행하지 않음)

1. 검증 환경에 원본 자료·승인·게시 지식의 ID/관계를 복제하고 인벤토리 및 실제 화면 숫자를 대조한다. 원본·R2·KV/Supabase 백업을 확보한다.
2. 검증 DB에 `20261017_rag_cas.sql`을 적용하고 service_role/anon/authenticated 권한, 실제 동시 실행 및 롤백을 확인한다.
3. 유료 API 키/신뢰 출처/단가/낮은 예산으로 1개 과제의 실제 검색·원문·추출·비용을 확인한다. 자동 게시는 먼저 OFF로 검토한다.
4. 검증 원국에서 게시·롤백 전후 동일 검색/검수 경로, 기존 관리자·무빙툰·PDF 동작을 확인한다.
5. 변경·실제 비용·원본 불변 검사·복구 결과를 제시하고 **별도 운영 배포 승인을 받는다.** 승인 전 운영 SQL이나 Worker/Pages 배포를 실행하지 않는다.
6. 승인 후 원본 재적재 없이 추가 migration과 코드만 배포한다. 자동 연구/게시를 OFF로 시작하고 검증 결과에 따라 활성화한다.

## 제한과 안전한 복귀

- 한 런타임 상태의 크기는 약 7.5MB에서 중단한다. 무제한 이력 축적은 지원하지 않는다. 기존 운영 백업 내보내기에 연구 상태가 포함되며, 장기 운영은 이력 아카이브/분리 테이블 확장을 별도 구현해야 한다. 제한 시 이력을 자동 삭제하지 않는다.
- 명리학적 주장과 적용 조건의 의미 판단을 완전 자동으로 증명하는 시스템은 아니다. 자동 게시 범위를 좁히고 불명확한 후보는 관리자에게 남긴다.
- 사용 이력의 완전한 운영 계측 및 과거 전체 자료/R2의 무결성 감사는 아직 후속 작업이다. 사용 이력이 없다고 기존 지식을 삭제/비공개하지 않는다.
- 운영 장애 시 관리자에서 연구 중지 및 기존 지식만 사용을 선택한다. 원본 데이터는 복원이나 재승인이 필요 없다. 개별 보강 오류는 게시 이력에서 해당 지식의 현재 보강 버전을 롤백한다.
