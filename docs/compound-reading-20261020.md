# 복합 조건 사전 풀이 (2026-10-20)

사용자 조회는 기존 계산값과 검수된 문장만 사용하며 AI 제공자를 호출하지 않는다. 일반 풀이 76개에 항목별 기존 32개 문안과 복합 조건 문안 110개를 함께 저장한다. 창작 8개는 기존 별도 서사 경로를 유지한다.

- 일간 10종: 접근 방식을 설명하는 전통 비유와 생활 실천을 선택한다.
- 신강·중화·신약: 기존 가중 계산 분류로 감당할 분량과 실행 방식을 구분한다. 통근 판단으로 바꾸어 쓰지 않는다.
- 개별 십성 10종: 일간을 제외한 십성 비중이 14% 이상인 후보 중 큰 비중을 우선한다. 기존 그룹 비중과 분모가 달라 서로 더하지 않는다.
- 식신·정재, 상관·편재, 정관·정인, 편관·편인, 비견·겁재: 두 조건이 모두 맞는 검수된 쌍을 단독 십성 설명보다 우선한다. 위험·보완 문안은 강약까지 동시에 일치하는 판본을 우선한다. 나머지 쌍을 별도로 집필했다고 주장하지 않는다.
- 조건이 없으면 추측해서 채우지 않는다. 시각을 모르면 주어진 기둥의 계산값만 사용한다.

`_reading-compound-copy.js`의 문안은 `compound-`로 시작하는 일반 라이브러리 항목이다. 관리자에서 본문과 when/unless 조건을 수정·검증·게시할 수 있다. 해당 ID의 family 부분(capacity/stem/god/pair)은 조합기의 역할이므로 유지한다. 새 문안을 편집할 때도 기존 존댓말 정규화와 검수 규칙을 적용한다. 출처에 연결된 개인 판단과 편집한 조건별 생활 조언은 구분한다.

반환 문단의 components에는 실제 사용한 문안 ID와 조건 평가가 남는다. 기존 원문과 출처는 근거 영역에 보존한다. 이름은 클라이언트에서 호칭으로 넣으며 공유 응답이나 다음 요청의 이력에는 보내지 않는다.

`tests/compound-reading-sim.cjs`: 실제 계산된 20개 가상 사주로 모든 110개 문안의 양성 조건을 확인하고, 76개 항목 × 20개 사주 = 1,520건에서 같은 기본 비중 구간의 다섯 본문 역할이 복합 조건에 따라 달라지는지 확인한다. 교차 조건의 반례, 누락값, 화면에서 문장이 기술 용어로 오인되어 숨는 문제도 검사한다. 이는 계산 조건 일치와 동작 검증이며 외부 명리 전문가 승인이나 실제 사건의 검증을 뜻하지 않는다.

DB 업그레이드는 `tools/prepare-compound-reading-upgrade.cjs`로 준비한다. 버전·초안 일치·원래 검증 차트 확인과 CAS를 통과한 항목만 갱신한다. 기존 32개 문장, 304개 검증 사주와 이전 판본을 보존하고 새 조건 문안의 기대·배제 ID를 추가한다.

본문 조합은 이후 [연결된 본문 흐름](coherent-reading-flow-20261020.md)으로 대체했다. 이 문서의 조건 문안은 기존 판본·조건 자료로 보존하며 사용자 본문에 덧붙이지 않는다.
