## 실제 구조와 보존 경계

- 루트 `index.html`은 만세력이며 `engine.js`의 기존 `Manse` 계산을 사용합니다. `report/v2/index.html`은 별도 사주 읽기 진입점입니다.

- `functions/api/movingtoon-reading.js`의 기본 경로는 검수 문안 조회·조건 조합입니다. 서버 조회와 생성형 AI 호출은 별개이며, 기본 검수 라이브러리 테스트에서 provider/네트워크 호출 0회를 확인했습니다. 신규 봉인 모듈 자체에는 fetch·AI 호출이 없습니다.
- 저장소는 기존 `GLOSSARY_KV`, `CLIPS_R2`, `_store.js`의 Supabase `public.kv` 어댑터입니다. 새 DB나 테이블을 만들지 않았습니다. 장면 메타데이터는 기존 원자적 `readingCAS`가 허용하는 `ik:blocks:chapter:seals.presentation`에 독립 저장합니다. 실제 운영에서 이 RPC의 배포 상태를 확인하거나 변경하지 않았습니다. CAS 없는 환경에서는 쓰기를 503으로 거부합니다.
- 원래 검수 문안과 계산 모듈은 그대로 두고 표시층을 추가했습니다. 기존 문체 정규화가 새 메타데이터의 검수 digest를 바꾸지 않도록 해당 메타데이터 키만 저장 변환 대상에서 제외했습니다.

## 구현한 읽기 경험

`seal-reader.js`·`seal-reader.css`는 기존 ReadingText의 HTML을 보존한 채 질문이 담긴 봉인, 즉시 개봉, 한 봉인 전체 읽기, 전체 봉인 바로 펼치기, 상태 목록, 실천 기록, 원문·계산 근거 펼치기를 추가합니다. 개봉과 읽기 완료 표시는 별개입니다. 정답 맞히기·드래그·강제 대기는 없습니다. 기존 안내·세계·타로 진입부도 유지합니다.

- 안정적인 챕터/역할 장면 ID, 질문, 문단 역할·순서, 원문 경로, 근거 참조, 본문/배경 ID, 레이아웃·대체 규칙, 문안/미디어 버전이 `SealReader.plan()`에 있습니다.
- 게시 상태인 장면 메타데이터만 적용합니다. 질문·훅·실천 안내, 문단별 연결/순서와 초점·안전영역을 적용하며 계산값이나 선택 원문을 바꾸지 않습니다. 챕터 순서는 봉인 목록에 반영하고, 기존 viewer의 문서·세계 인덱스는 유지합니다.
- DOM 밖 상태와 localStorage를 사용합니다. 입력·보정 조건과 챕터를 분리하고 문안 내용 fingerprint가 바뀌면 안전 초기화합니다. 같은 버전에서는 개봉, 읽기 표시, 실천, 읽던 장면, 근거 펼침을 복원합니다. 저장 실패 시 메모리로 계속 읽습니다.
- 비동기 본문 교체 전에 영상/관찰자/이벤트를 정리하고 이후 상태·키보드 초점·입력 선택 위치를 복원합니다. 장면 직접 링크, 재읽기, 목록으로 나가기, 전체 펼치기를 제공합니다. 기존 챕터 별칭 앵커도 유지합니다.
- 로딩·통신 오류·빈 문안을 봉인 연출로 감추지 않습니다. 기존 재시도 경로를 유지하며 빈 문안은 별도 안내합니다.
- 한국어 본문은 HTML입니다. 이미지 위에 문장을 굽거나 덮지 않습니다. 본문 밖에 글을 배치하여 얼굴/상징과 충돌하지 않게 하며, 이미지는 기본 contain·초점 좌표를 지원합니다. 불필요한 강제 자동 진행을 끕니다. 감소 모션 CSS와 기존 reduce/saveData 영상 옵션을 사용합니다.

## 미디어 계획

ReadingMedia의 전역 누적 사용 이력을 제거했습니다. 풀의 정렬·방문 순서와 무관한 순수 선택이며 전체 `plan()`도 제공합니다.

1. 승인·활성·게시 상태, 안전한 URL을 확인합니다. 미승인·초안·폐기 상태와 타로 풀은 제외합니다.
2. 챕터 전용 연결과 사용자 성별·오행 조건을 확인합니다. 다른 오행 컷으로 장면 수를 채우지 않습니다.
3. 장별 의미, 문단 역할/phase, 본문/배경 역할을 확인합니다. risk 컷을 daily에 돌려 쓰지 않습니다.
4. 의미가 맞는 후보 안에서 안정적인 순서로 선택하고 같은 자산의 불필요한 중복만 억제합니다.
5. 적합한 그림이 부족하면 정적인 화면과 원문으로 이어집니다.

`panel-`과 `panelbg-`는 별도로 선택·합성합니다. 초점·안전영역·크롭·문단 역할은 서버 저장 왕복에서 유지됩니다. 배경 실패는 본문 이미지까지 숨기지 않습니다. 화면 밖 영상은 정지하며 교체/이탈 시 자원을 해제합니다. 미디어 선택·제외 사유는 관리자 미리보기와 공개 문안의 근거 정보에서 확인할 수 있습니다.

## 관리자

## 남은 검증과 범위의 한계

- 운영의 개인별 검수 조회 POST, 실제 DB/RPC 쓰기, 운영 게시 결과는 실행하지 않았습니다. 관리자 API는 격리된 모의 저장소로 검증했습니다. 실제 환경의 readingCAS 지원 및 권한·binding은 배포 전 확인이 필요합니다.
- 문안 원문·조건·참조를 모두 보존했지만 모든 운영 문안의 의미적 함의를 사람이 전수 재검수한 것은 아닙니다. 새 메타데이터의 실제 게시도 하지 않았습니다.
- 실제 기기 성능 수치·LCP/CLS·NVDA/VoiceOver·OS의 감소모션/데이터절약 설정·최신 원격 영상 재생·실제 PDF 파일 다운로드·OS 공유는 측정하지 않았습니다. CSS/옵션 처리와 순수 함수/모의 전송 검증을 이들 실측으로 대체해 보고하지 않습니다.
- Cloudflare Functions 번들 컴파일 및 preview 배포는 이 실행에서 수행하지 않았습니다. 후보 파일 생성과 JS 구문/로컬 테스트 통과를 운영 배포 성공으로 간주하지 않습니다.
- 과거 엔진 기준선 불일치는 원인 추적이 필요한 선행 문제입니다. 기존 계산 정책이나 baseline을 임의로 고치지 않았습니다.

## 배포 후보와 복구 절차

`node tools/seal-release.cjs`는 네트워크 호출 없이 새 후보 디렉터리를 만들며, 기존 디렉터리를 지우거나 재사용하지 않습니다. 최신 후보 위치는 `output/sealed-webtoon/latest-release.json`에 있습니다.

- `site/`: 실제 정적 소스와 Functions. .env·.git·.wrangler·원본 백업·output·테스트를 제외합니다.
- `manifest.json`: 모든 배포 파일의 SHA-256/크기, 기준 커밋, 변경 전 파일과 신규 파일 목록.
- `before/`: 수정한 기존 배포 파일의 변경 전 소스. 이미지 원본을 복제·덮어쓰지 않습니다.
- `output/sealed-webtoon/source-inventory.txt`: 전체 Git 관리/미추적 소스 목록(ignored 운영 백업 제외).

운영 반영 전 다음 순서로 검토합니다.

1. `node tools/seal-check.cjs`, 원본 감사 manifest, 소스 diff와 후보 manifest를 확인합니다.
2. 기존 승인된 Wrangler 버전에서 `pages functions build --help`를 확인한 뒤 후보 `site/`를 프로젝트 루트로 Functions를 로컬 번들링합니다. 새 credential·binding을 후보에 넣지 않습니다.
3. 별도 승인 후 기존 Cloudflare Pages preview 파이프라인으로 올리고, 운영과 분리된 동일 구조 binding에서 실제 입력·조회·관리자 CAS·읽기/타로·PDF·영상·성능을 검증합니다. 환경설정/DB 스키마는 자동 변경하지 않습니다.
4. 운영 배포는 검토한 파일 해시와 현재 기준 배포를 대조한 후 별도 승인으로 수행합니다. 원본 R2·기존 검수 게시본 변경은 포함하지 않습니다.
5. 장면 게시가 필요하면 별도 검수한 메타데이터 초안을 저장→검증→검수→게시하고, 재조회와 공개 응답을 확인합니다. 코드 배포와 문안/메타데이터 게시를 하나의 성공으로 묶지 않습니다.

Cloudflare의 Functions 배포/명령 근거: [Pages Functions 시작](https://developers.cloudflare.com/pages/functions/get-started/), [Wrangler Pages 명령](https://developers.cloudflare.com/workers/wrangler/commands/pages/). 이 문서의 배포 명령은 실행하지 않았습니다.

복구: 화면 문제라면 변경 전 프런트 소스를 `before/`에서 복원하는 후보를 만들고 검증한 뒤 승인된 이전 배포로 되돌립니다. 원본 보호 서버 코드는 가능하면 유지합니다. 새 파일은 참조를 제거하면 비활성화되므로 즉시 삭제할 필요가 없습니다. 새 게시 메타데이터는 관리자의 게시 철회로 원문·초안·이력을 보존하며 기본 표시로 복귀할 수 있습니다. 이전 게시 내용을 복원할 때는 이력→초안 복원→재검수→게시를 거칩니다. DB 마이그레이션과 기존 검수 문안 변경이 없으므로 이 작업 자체에 대한 DB 역마이그레이션은 없습니다. `report.zip`, 원본 자산, 기존 작업 파일을 초기화하는 명령은 사용하지 않습니다.
