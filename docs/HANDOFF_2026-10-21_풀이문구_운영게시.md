## 3. 핵심 문제: 운영 DB 상태가 가정과 다름
운영에는 `ik:blocks:chapter:library.<chapter>` 키로 게시 라이브러리가 있고, **이 게시본이 시드보다 우선**한다. 사용자가 실행한 요약 쿼리 결과:

| seed | version | 챕터 수 | 비고 |
|---|---|---|---|
| complete-84-20261020-1 | 1 | 8 | 창작(creative) — 변경 없음, 제외 |
| everyday-all-84-20261020-13 | 11 | 7 | career_01 등 focus 챕터 |
| everyday-all-84-20261020-13 | 13 | 1 | wealth_02 |
| multi-chart-84-20261020-10 | 10 | 68 | 나머지 전부 (예전 판) |

- 지금 만든 `output/blunt-copy-20261021/sql/*.sql`은 "게시 문장이 **직전 시드(HEAD~) 문장과 같을 때만** 교체"하는 방식이다. 버전 10 챕터(68개)는 더 오래된 판(커밋 `2a68d32` 시드)이라 `nothing to replace`로 **중단된다(DB 변경 없음, 안전)**. focus 7개와 wealth_02도 일부만 맞을 수 있다.
- 사용자가 처음 실행했던 건 설명용 요약 코드(문법 에러, DB 변경 없음)였고, 이후 `verify.sql` 계열 읽기 쿼리만 실행했다. **지금까지 DB에 쓰기는 한 번도 일어나지 않았다.**

## 4. 다음 작업 (권장 설계)
76개 비창작 챕터를 **게시본 전체 교체** 방식으로 올린다. 참고 구현: `tools/prepare-multi-chart-upgrade.cjs`(이전 v9→v10 때 같은 방식).
1. 챕터별 새 게시본 = 현재 `seedPassages(c)` 전체(`output/blunt-copy-20261021/new.json`에 이미 덤프됨).
2. **가드**: `draft == published`(미게시 관리자 수정 없음) + 현재 게시본 md5(id+text)가 알려진 시드 판의 md5 중 하나일 것. 후보 판: 커밋 `2a68d32`, `258271f`, `1641282` 시점 시드(`git archive <커밋> functions report/v2/*.js` → `node tools/dump-seed-passages.cjs <dir> <out.json>`로 각각 덤프해 md5 계산). 어느 후보와도 안 맞으면 `raise exception`(관리자 수정 의심).
3. **시나리오(검증 케이스)**: 새 passage id 집합이 달라지므로 `scenarios`를 재작성. 케이스 풀 = `output/multi-chart-review-20261020/{matrix,prior-coverage-charts,prior-scenario-ids}.json`, `output/attached-chart-review-20261020/new-pack/library-pack.json`, `output/batch-adjustment-audit-20261021/samples.json`, `output/frank-reading-20261021/review.json`. 조건부 passage마다 **긍정·반례 케이스가 각각 1개 이상**, 총 20개 이하(관리자 게시 검증과 동일 규칙). focus 챕터(프로필·대운)는 풀에 긍정 사례가 없을 수 있어 `tests/reading-focus-eight-sim.cjs`·`reading-detail-profiles-sim.cjs`처럼 엔진으로 차트를 탐색(루프 n≈24000)해 보충. 기존 시나리오는 `history`에 보존하고 새 케이스는 `{sampleId, sd, expectedPassageIds, forbiddenPassageIds}` 형식(sd에 birth/name 없음).
4. 저장 형식: `version+1`, `draft=published=새 passages`, `scenarios`, `review`(seedVersion `everyday-all-84-20261021-14` 등), `updatedAt`, `history`에 직전 판 스냅샷을 앞에 추가. 마지막에 `public.reading_compare_and_swap(key, prior, next::text, null)`이 true일 때만 성공.
5. 롤백 SQL도 같이 생성(직전 판 복원). 파일 크기는 챕터당 약 130KB(이전 업그레이드와 비슷)라 SQL Editor에는 챕터 1~3개씩 묶어 붙여야 한다.
6. 사용자 실행 순서: ① `timeline_self_01`만 → ② 읽기 쿼리로 `seedVersion`·`version` 확인 → ③ `https://mantramanse.pages.dev/report/v2/`에서 문구 확인 → ④ 나머지.

## 5. 환경·제약
- Supabase 접속 정보(`SUPABASE_URL`, `SUPABASE_SERVICE_KEY`)는 Cloudflare Pages에서 비밀 값이라 API로 읽으면 **빈 문자열**. 로컬에도 키 파일·환경변수 없음 → 에이전트가 DB에 직접 쓸 수 없고, 사용자가 대시보드(프로젝트 `mantramanse1`, PRODUCTION)에서 실행한다. 로컬에 PostgreSQL이 없어 SQL을 실행 검증하지 못한다(문법은 눈으로만 검토).
- 클립보드 전달: PowerShell `Set-Clipboard`로 파일을 복사해 주면 된다(채팅에 SQL을 붙이면 요약본을 복사하는 실수가 났음).
- `output/`은 git 제외. 생성물: `output/blunt-copy-20261021/{old,new}.json`, `sql/`, `rollback/`, `batches/`, `plan.json`, `verify.sql`(현재 SQL은 폐기 예정).
- 테스트 실행 시 `docs/` 일부 JSON이 덮어써질 수 있으니 실행 후 `git status`로 확인해 되돌릴 것.
- 창작 8개 장, `deep.js`·`life-doc.js`의 신살 한 줄 설명, 경금·신약 프로필 묶음(`_reading-coherent-bundles.js`)은 이번에 손대지 않았다.
