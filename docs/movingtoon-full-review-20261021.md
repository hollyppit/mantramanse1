## 원고 검수와 수정

1. 첫 문장이 질문이나 추상적 비유로 결론을 대신하는 경우, 실제 경험을 알고 있는 것처럼 묻는 문장, 비교 근거 없는 과찬, 행동 뒤 결과를 보장하는 표현을 점검했다.
2. 문제 원문 **135개**에 개별 수정안을 작성했다. 고정 단어 치환 방식이 아니라 해당 챕터의 핵심 판단·장면·주의·실행 방법을 다시 적었다. 해당 원문을 참조하는 flow 본문에도 같은 수정안을 적용했다.
3. 원문과 수정안을 `functions/_reading-editorial-revisions.js`에 함께 보존했다. ID와 원문 일치 여부를 확인한 뒤 새 시드 후보에만 적용하며, 예상 원문이 다르면 생성을 중단한다. 이 수정안은 승인·게시되지 않았다.
4. 복합 본문의 연결 표현을 복원해 같은 주된 비중 구간에서도 십성 조합과 일간별 조정 방식이 본문에 반영되게 했다. 사용한 구성 문안·계산 조건은 components에 남긴다. 근거 없는 개인 사실이나 새로운 명리 규칙을 만들지 않았다.
5. 전체 84챕터의 288개 실계산 명조·챕터 조합에서 운영본/후보를 비교했다. 후보 출력 2,304문단의 미해결 토큰·길이·조건 일치·근거 ID 생성을 검사했다. 출생시각 미상 사례를 포함했다.
6. 별도의 검수 자료에는 핵심 판단·생활 행동·위험·강점 활용·실제 적용 조건·행동 제안을 연결했다. 이는 검수용 자료이며 자동 승인 데이터가 아니다.

최종 검사: 조건·형식 오류 0건, 설정한 표현 검사에 걸린 후보 문안 0건, 표본 출력에서 역할별 동일 본문이 여러 챕터에 반복된 그룹 0건, 네트워크 호출 0회. 현재 운영본에는 같은 표현 기준의 점검 표시 23개가 남지만, 승인 전 운영 보존 요청에 따라 수정하지 않았다.

**검사 해석의 범위:** 정규식 검사 0건이 모든 의미상 모순이나 추상적 문장을 판별했다는 뜻은 아니다. 288개 출력 비교는 모든 가능한 명조를 전수 실행한 결과가 아니다. 현재 시드는 생활 참고 guide 14,796개와 fiction 96개로 구성되며, 새 `personal` 근거 문안으로 승격하지 않았다. 독립 문헌·명리 전문가의 의미 검수와 최종 서비스 품질 승인은 관리자가 해야 한다.

## 실패했던 두 테스트의 원인과 해결

### 조건부 라이브러리 검사

`tests/conditional-reading-library-sim.cjs`는 단일 비중 구간의 `condition-*` 문장이 항상 선택돼야 한다고 가정했다. 실제 서비스에는 일간·강약·여러 십성 조건을 모두 충족한 `bundle-*` 상세 문안이 먼저 선택되는 경로가 있다. 유효한 복합 문안의 우선 선택을 실패로 보던 기대값이었다.

검사를 바꿔 선택 문안의 ID와 실제 계산 조건을 확인하고, 기본 구간 문안을 대체할 때는 유효한 복합 조건 문안인지 확인한다. 세 구간 본문 차이·경계값·시각/계산값 누락·무AI 검사는 유지했다. **76챕터 × 3구간 = 228검사 PASS.**

### 복합 본문 다양성 검사

`_reading-flow-copy.js`의 새 완성 문안이 복합 연결 표현 없이 사용돼 같은 주된 비중 구간 안에서 본문이 같아졌다. 새 연결이 구형 템플릿의 이행 패턴과 같으면 다시 평문으로 치환되는 문제도 있었다. 현재 후보는 이행 규칙과 구분되는 연결 문안을 사용한다.

테스트의 표집에도 결함이 있었다. 구성요소가 처음 등장한 명조만 수집해 어떤 구간은 3표본밖에 없는데 4종 이상 본문을 요구했다. 기준을 낮추지 않고 구간별 일간·강약·십성 조합이 다른 실제 명조를 추가했다. **43명조 × 76챕터 = 3,268검사, 134구성요소, 다섯 본문 역할의 같은 구간 내 다양성·반례·JSONB 왕복·조건 일치 PASS.**

## 관리자 검토 방법

로컬 코드의 검수 풀이 화면에 **「운영본·개편 후보 비교 · 저장 없음」** 버튼을 추가했다. 동일 명식으로 현재 게시본과 코드에 포함된 신규 후보를 각각 미리보기로 요청해 문단과 선택 근거를 나란히 보여준다. 편집 중인 초안·게시본은 바꾸지 않는다. 인증·버전 일치 검사를 거치며, 비교 동작에는 게시 요청이 없다. 이 UI 변경 역시 아직 배포하지 않았다.

지금 바로 읽을 자료는 로컬 `output/overhaul-review-20261021/full-review.html`이다. 84챕터별 실제 운영본/후보와 성립 조건을 볼 수 있다. 원고 전체와 세부 대조 결과는 아래 파일에 있다.

- `all-source-passages.json`: 운영·후보 원고 29,704개와 적용/제외 조건.
- `verified-live-copy.json`: 문안·조건 해시를 검증한 운영 원고 복원본.
- `db-comparison.json`: 챕터별 운영 버전·해시·달라진 ID·추가 ID.
- `full-output-comparison.json`: 288개 출력 전후 비교와 구성 조건.
- `six-element-review.json`: 여섯 요소에 연결한 검수 자료. 승인 여부는 전부 미승인.
- `manuscript-audit.json`: 검사 요약·표현 표시·실제 출력 검사 내역.
- `live-unchanged-verification.json`: 작업 전후 84개 운영 저장값 동일 확인.

승인 후 게시할 때는 기존 초안과 게시본·버전이 여전히 같은지 다시 확인하고, 챕터별 정례와 반례를 재검증해야 한다. 이번 작업은 승인·게시·배포를 대신하지 않는다. 기존 준비 SQL은 이전 시드용이므로 이 최종 후보를 게시하는 데 그대로 사용하지 말아야 한다.
