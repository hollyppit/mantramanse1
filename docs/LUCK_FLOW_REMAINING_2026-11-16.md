# 운세 흐름 남은 과제 처리 결과 (2026-11-16)

기준: [LUCK_FLOW_FULL_AUDIT.md](LUCK_FLOW_FULL_AUDIT.md) 남은 과제, [LUCK_FLOW_YONG_FINAL_2026-11-16.md](LUCK_FLOW_YONG_FINAL_2026-11-16.md) 6절.
원칙: **흐름 점수(대운·세운·월운·일진)는 바꾸지 않는다.** 바뀌는 점수는 분야 지수(3번)뿐이며, 엔진 기준선(`tests/engine-baseline.txt`)에서도 `domain` 지문만 달라졌다.

## 1. 만세력·타임라인 분류 기준 통일
- 문제: 만세력은 변동 55·방어 부담도 40, 타임라인 6분류(`report/v2/luck6.js`)는 변동 65·흐름 점수/작용 강도로 따로 판정 → 같은 시기 대표 분류가 30% 달랐다.
- 수정:
  - 엔진 `FLOW_CONFIG.overlay.volatility` 55 → **65**(`engine.js`). 타임라인이 이미 근거를 두고 쓰던 값(변동 33% → 18%, `report/v2/VOLATILITY_ANALYSIS.md`)으로 하나로 맞췄다. 일지 충 하나(약 55)만으로는 변동이 붙지 않고 충·형이 겹칠 때 붙는다.
  - `Luck6.of()`는 엔진이 정한 overlay(변동·방어, 둘 다면 `topOverlay`)를 그대로 읽는다. overlay 가 없는 옛 값에만 예전 규칙을 쓴다.
  - 해석 상자 대응 전략의 "큰 결정 주의" 문장도 같은 변동 기준(`ev.overlays.volatility.active`)을 쓴다.
- 결과: 6분류 변동기·방어기 = 만세력 변동·방어 표시 **4,200/4,200 일치**(`tests/luck6-compare.js`를 이 불변식으로 갱신). 변동기 비율 17.5% 유지.
- 무빙툰 영향(배포 후 확인, 사용자 결정 "65로 유지"): 무빙툰(`report/v2/saju-data.js seasonOf`)도 엔진 변동 판정을 그대로 읽어 '전환운'을 정한다. 기준이 65가 되면서 전환운이 약 33% → 18%로 줄고, 그 시기는 확장운·축적운 등 주 흐름 이름으로 나온다. 만세력·타임라인·무빙툰 세 화면이 같은 기준.

## 2. 관계 카드 사건 단정 완화
- 문제: 운세 흐름 상세의 관계 카드(`LUCK_EVENT`)가 충·형을 "이별·수술·퇴사" 같은 사건으로 단정하고, 그 자리가 기신이어도 늘 나쁘게 썼다.
- 수정(`index.html` luckEffects):
  - 문구를 "~로 나타날 수 있어요"로 바꾸고 이별·수술·퇴사·이직 같은 결과 예고를 없앴다. "구체적으로" → "이런 모습으로".
  - 충·형·파·해·천간충은 **건드리는 자리 오행**, 합은 **합으로 생기는 오행**의 통합 용신 역할(흐름 점수의 관계 성분과 같은 기준)을 보고 "이 사주에서는" 줄을 붙인다: 기신 자리를 흔들면 "막혀 있던 것이 정리되는 변화", 용신 자리를 흔들면 "조금 더 조심", 기신으로 묶이면 "끌림이 부담으로 바뀌지 않게". 기신 쪽이면 카드 색도 중간 톤.
  - 사주 원국 패널이 함께 쓰는 `REL_HEAD`는 건드리지 않았다.

## 3. 분야 지수 억부·조후 중복 제거
- 문제: 분야 지수 적합도 = `own×흐름 점수(통합 용신 포함) + eokbu×억부 단독 + johu×조후 단독` — 같은 판단을 세 번 더함(상관 0.72).
- 수정(`engine.js`): `DOMAIN_COMMON.fitDedup = true`, `fitCore()` — 같은 가중치 합(own+eokbu+johu)을 흐름 점수 하나에 준다. 애정·재물과 하위 12개 지수 모두. 근거 문장 "억부·조후 보완/부담" → "통합 용신 기준 보완/부담". 끄면(false) 이전 계산.
- 영향: 세운 1,260건 기준 지수 점수 변화 평균 0.4~1.1점, 최대 6점. 건강·사고수 변화 0.
- 기준값: `tools/domain-cuts-measure.cjs`로 같은 표본을 수정 전·후 엔진으로 재측정 → 신호등 구간(SIG_CUTS) 차이 0~1점, 등급 구간 차이 0~1점이라 **기준값은 그대로 둔다**. `tests/signal-sim.cjs` 분포 검사 통과.
- 재물의 "신약에 재성"(weakBurden·재다신약 패턴)은 분야 고유 판단이라 이번에는 그대로 두었다.

## 4. 교운기
- 문제: 세운은 그해 중반(입춘+180일)의 대운 하나만 상위 운으로 써서, 대운이 바뀌는 해의 42%가 이전 대운 기준인데 화면에 아무 표시가 없었다.
- 수정(표시 전용, 점수 불변):
  - 엔진 `M.gyoungi(ch, 연도)`: 그해 안에서 대운이 바뀌면 바뀌는 시각, 이전·새 대운, 그해 점수가 기준으로 쓴 대운, **다른 대운을 기준으로 했을 때의 흐름 점수**, 새 대운이 그해를 차지하는 비율. 바뀌기 1년 전·후는 `near`.
  - 세운 타일에 "교운기" 배지(누르면 용어 설명), 세운 상세(타일·지금의 운)에 안내: 예) "2027.02.16부터 己酉 → 庚戌 대운. 이 해의 흐름 점수 −32는 庚戌 대운 기준이고, 己酉 대운 기준으로 보면 −27(주의)입니다." 전후 1년은 "교운기 전후" 안내.
