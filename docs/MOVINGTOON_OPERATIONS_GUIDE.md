# 운영 관리 방법과 후속 검증 결과

2026-10-13. 사용자에게 권장한 관리 방법을 실제 로컬 코드에 구현했다. 이 문서는 운영 배포 완료 보고가 아니다.

## 권장 운영 방식

기존 관리자 계정과 비밀번호를 그대로 사용한다. 관리자 → 운영·설정 → 운영 관리에서 상태, 백업, 복구, AI 검사를 한곳에서 처리한다. 평상시 Cloudflare와 Supabase 콘솔을 오갈 필요를 줄였다.

1. 코드 배포 후 기존 관리자 로그인으로 운영 관리에 들어간다.
2. 콘텐츠나 영상 연결을 수정하기 전에 **원본 포함 폴더 백업**을 선택한다. 폴더 저장을 지원하는 데스크톱 브라우저에서 저장 위치를 고른다. 생성된 폴더의 `backup.json`과 `files`를 함께 보관한다.
3. **누락 영상 연결하기**로 기존 일주·일간 관리 화면을 열어 실제 원본을 확인하고 연결한다. 파일 이름만 보고 남녀·일주를 임의 배정하지 않는다.
4. 풀이 수정은 기존 콘텐츠·해석 규칙 화면에서 하고 **풀이 생성 테스트**, **전체 서비스 점검**으로 확인한다. **AI 실제 생성 점검**은 가상 명식으로 실제 제공자를 호출하므로 생성 비용이 발생할 수 있다. 캐시 재사용과 원본 생성 토큰을 구분해서 표시한다.
5. 복구할 때 **백업 폴더 복구**를 선택하고 변경 목록을 확인한다. 적용 버튼은 복구 전 서버 데이터 백업을 먼저 내려받는다. 현재 다른 원본이 있으면 덮어쓰지 않는다. 누락된 원본만 먼저 복원한 다음 서버 데이터를 적용한다.
6. 서버 데이터 변경을 되돌리려면 내려받은 `mantra-before-restore-*.json`을 복구 파일로 선택한다. 복구 중 새로 추가한 원본은 이 되돌림으로 삭제하지 않는다.

비밀번호를 소스나 대화에 적을 필요가 없다. 운영 작업을 이어가려면 배포 권한이 연결된 환경과 인증된 관리자 세션이 필요하다. 현재 작업에서는 인증된 운영 접근을 확보하지 못했으며 운영 설정·사용자·원본을 변경하지 않았다.

## 백업·복구 범위와 한계

- 빠른 JSON 백업: 물리 KV와 Supabase의 영속 데이터, 자산 연결과 R2 객체 명세. 원본 바이너리는 포함하지 않는다.
- 원본 포함 폴더 백업: 위 데이터에 R2 원본 파일과 SHA-256 검증값을 추가한다. 원본 저장 중 오류가 나면 `backupComplete:false` 파일이 남고 복구가 거부된다.
- 서버에 저장된 사용자 데이터는 포함하며 브라우저에만 저장된 프로필은 포함하지 않는다. 사용자 데이터가 든 백업 폴더의 접근 권한은 운영자가 관리한다.
- 빠른 캐시·속도 제한·운영 미리보기 키는 제외한다. 비밀 환경 변수는 내보내지 않는다. Supabase의 null 값과 KV 만료 시각을 보존한다.
- 복구는 백업에 명시된 키만 적용한다. 다른 키를 지우지 않는다. 미리보기 이후 편집된 키는 거부한다. 40개씩 적용하고 실패한 현재 묶음은 되돌린다. 이전에 완료된 묶음은 복구 전 백업으로 되돌릴 수 있다.
- 미리보기 유효 시간 1시간. 서버 JSON 12MiB, 영속 레코드 6000개, 원본 명세 6000개, 개별 파일 복구 90MiB 제한. 초과 규모의 분할 백업·대용량 복구는 별도 구현이 필요하다.
- 원본 복구는 SHA-256 검증과 R2 조건부 생성으로 기존 객체 덮어쓰기를 막는다. 동일 파일은 건너뛴다. 다른 버전 원본의 교체는 이 도구에서 수행하지 않는다.
- 편집을 멈춘 시간대에 백업한다. 여러 저장소를 한 트랜잭션으로 묶는 시점 일치 백업은 아니다. 브라우저의 다운로드 완료 자체는 웹 앱에서 확정할 수 없으므로 복구 전 파일이 실제 저장됐는지 확인한다.
- 폴더 저장 기능이 없으면 빠른 JSON 백업을 사용할 수 있다. Windows 실제 폴더 선택 창은 이번 자동 검사 대상이 아니며, 폴더 API 핸들을 모사한 브라우저 검사와 실제 서버 모듈 검사를 각각 수행했다.

## 검증 결과

- 전체 시뮬레이션: 79개 중 78개 통과, 브라우저가 필요한 달력 1개는 별도로 실행하여 통과. 엔진 기준 명식 120개 회귀 통과.
- 해석 모델: 600개 샘플에서 통근/강약 조합, 학파 차이, 조후 없음, 극단 강약, 시간 미상 분기 확인. 외부 명리 전문가의 승인 검증은 아직 아니다. 원전과 구현 비교는 `MOVINGTOON_SCHOOL_REVIEW.md` 참조.
- 운영 API: 430개 KV 페이지 백업/복구, 실패 묶음 되돌림, 새 키 되돌림, 무관한 사용자 키 보존, Supabase null과 405개 페이지 처리 통과.
- 원본 복구 API: 인증, 누락 원본 우선 복원, 변조 SHA 거부, 조건부 생성, 반복 적용, 같은 크기의 다른 파일 거부, 원본 변경·미완료 백업 거부 통과.
- 관리자 실제 로컬 브라우저: 로그인→미리보기→복구 전 다운로드→복구→빠른 JSON 백업→되돌림 통과. 원본 폴더 흐름은 모사된 폴더 핸들과 API 응답으로 별도 검사하여 바이트·해시·완료 표식·복원 순서 확인.
- 운영 공개 영상: 일주 120칸 중 8개 개별 매핑, 112칸 공개 매핑 미확인. 이는 원본 112개가 없거나 삭제됐다는 뜻이 아니다. 일간 및 인트로를 포함한 서로 다른 영상 주소 30개 모두 Range 응답 206.
- 영상 재생: 실제 영상 2개를 모바일 브라우저 에뮬레이션의 정상/저속 네트워크에서 검사, 4건 모두 재생 진행 확인. 물리 휴대전화 검사는 아니다.
- 실제 운영 AI: 가상 명식 경오·임자·신해 3건 모두 생성 성공, 6개 문단의 로컬 계산 일관성/임의 명칭 검사 통과. 기존 배포본의 호출이며 신규 프롬프트의 운영 반영 검증은 아니다. 관리자 원문 참조 일치까지 재조회하지 못했다.
- 실제 앱 PDF: CDN 라이브러리를 사용한 다운로드, 38쪽 A4 파일 확인, 전체 페이지 렌더링과 육안 검사 완료. 공유 거부 시 다운로드·취소 유지 분기 별도 통과.
- `git diff --check` 통과.

## 아직 남은 운영 작업

신규 코드 배포, 인증된 운영 DB/원본 전체 백업과 복구 리허설, 112개 미확인 매핑의 실제 원본 대조, 신규 AI 프롬프트의 운영 확인, 물리 휴대전화 검사, 외부 전문가의 학파별 해석 검토. 공개 서버의 `reading-flow.js` 요청은 HTML 대체 응답이므로 이번 로컬 변경이 이미 반영됐다고 판단하지 않았다.

새 데이터 구조의 호환 경로와 복구 도구는 마련했지만 운영 데이터 복구를 직접 수행했다는 의미는 아니다. 원본과 사용자 데이터 보존을 우선하여 인증 없는 매핑 변경이나 배포는 수행하지 않았다.
