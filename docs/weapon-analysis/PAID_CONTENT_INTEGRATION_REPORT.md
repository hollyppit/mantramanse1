## 2. 주무기 공통 데이터 연결 구조

```
/weapon.js  MantraWeapon.analyze(M, ch)   ← 만세력 네 탭과 같은 판정(명식마다 캐시)
            MantraWeapon.timeline(M, ch)  ← 대운·세운·월운 활성도(+유형·제약·활용 방향)·유리도(엔진 흐름 등급)
     │
report/v2/weapon-chapters.js  (R.WeaponChapters)
     │  설정 rows: 장ID → { on, topic(해석 템플릿), use{11개 데이터 항목} }  ← 기본값 + /api/weapon-links
     │  주제별 빌더: self · wealth · career · love · remedy  (문안 weapon-chapters-data.js)
     ▼
reading-feature.js build(c) → custom:'wp:장ID' → WeaponChapters.render → 장 끝 블록(.dp-wp)
```

공통 데이터 항목(지시문 2절)은 모두 `analyze` 결과에 있다: 1·2순위 오행·명칭·대표 능력(`weapon-data.js` el/elGroup)·형성 근거(`reasons`)·오행별 세력·병존·간여지동·통근·투간·관련 십성·십성 역할(통합 용신 역할)·강점·과잉 주의·신뢰도·미확정. 운 데이터: 대운·세운·월운 활성도·유형(강화·지원·발산·조정)·지원(운 글자의 용신 역할)·유리도·제약·활용 방향. **활성도와 유리도는 다른 필드이고 더한 값이 없다.**

## 4. 주제별 개선 결과

- **종합풀이**: 나의 핵심 주무기(오행 — 대표 주무기, 대표 강점) → 형성 근거(실제 글자·자리: "년간 庚(편인) · 월간 辛(정인)", "월지 巳의 중기 庚", 합충) → 강점이 발현되는 방식(오행 + 십성 조합 25칸) → 보조 주무기와의 결합 → 과잉 작용 시 주의(오행 + 십성 왜곡, 기신·구신이면 추가 경고) → 장기 발현 환경 → 지금 대운·다음 발현 대운·발현 세운 2개 → 용신과의 관계·신뢰도. 주무기가 없거나 미확정이면 이 장에만 안내.
- **재물운**: 경제활동의 주무기 → 주무기 십성과 재성의 관계 5가지(비겁 쟁재·식상생재·재성 자체·재생관·재극인) → 이 명식 재성 세력·상태 → 수익 창출 구조(성과형·결과물형·운용형·직급형·지식형) → 강점 → 시기(대운·세운 최대 3·월운 2) → 재물 주의점. 수익 보장 표현 없음.
- **커리어운**: 직업적 주무기(독립형·창작기술형·운영사업형·조직형·전문가연구형) → 업무 수행 방식 → 기존 관성·식상·재성 비율과의 결합 → 리더십·협업 → 시기 → 이직·창업 첫 기준·과잉 신호. "직업은 주무기 하나로 정하지 않아요" 고정 안내.
- **인연운**: 관계에서 드러나는 주무기 → 애정 표현·소통(주도권) → 다른 주무기를 가진 상대와의 상호작용 → 배우자 자리·배우자성 사실(결혼 시기·배우자 성향 단정 없음) → 관계 과잉 → 시기.
- **개운법**: 십성별 강화 루틴 3개 → 보조 주무기 우회 → 과잉 조절 규칙(기신·구신이면 강조) → 부족한 기능 보완(용신 쪽 십성 행동) → 지금 대운·올해·다음 3개월 실천 방향. 색·물건 추천 아님.

같은 시기라도 주제마다 다른 문장틀을 쓴다(지시문 9절): 예) 같은 2030년 庚戌 — 종합 "삶의 무게중심이 …", 재물 "돈 버는 방식도 …", 커리어 "업무도 … 넓히기 쉬운 때", 인연 "관계에서도 … 마음이 움직이기 쉬워요". 시기 문장은 활성도 단계(켜짐·준비·지킴)에 맞춰 고르고, 조용한 시기를 '좋은 때'로 쓰지 않는다.

## 5. 관리자 질문별 주무기 연결 설정 (지시문 10절)

- 위치: 관리자 → 운세 환경 탭 → "운명의 타임라인 주무기 상세풀이 연결" 카드(`report/admin/v2-weapon-links.js`).
- 전체 공개: `/api/luck-flags` `weaponChapters` 켜기/끄기(기존 스위치 방식 그대로).
- 질문별: 장 ID마다 사용 여부 · 주제(해석 템플릿) · 1순위 · 2순위 · 오행 세력 · 병존·간여지동 · 통근·투간 · 십성 작용 · 대운 · 세운 · 월운 · 활성도 · 유리도 — 11개 체크. 질문 추가·빼기·기본값으로·저장(버전 충돌 시 409).
- 저장: `/api/weapon-links`(KV `GLOSSARY_KV` 키 `weapon:links`) 하나만. 기존 질문·장 ID·템플릿·상품을 바꾸지 않는다. 주무기 변수는 기존 풀이 템플릿과 분리된 별도 블록.
- 미리보기: 생년월일·시(모름 가능)·성별·질문을 고르면 사용자 화면과 같은 모듈로 블록을 그린다. 주무기 없음·미확정 명식은 "이 주제에서는 블록이 생략돼요"로 보인다.
- 로컬 확인: 카드 렌더·체크 변경 표시·건강 장 거부·질문 추가·미리보기 동작 확인. 실제 저장은 서버 API 검사(아래 7)로 확인.

## 6. 운명의 타임라인 연동

- `report/v2/index.html`: `/weapon-data.js`·`/weapon.js`·`weapon-chapters-data.js`·`weapon-chapters.js` 스크립트 추가, `reading-feature.js`·`viewer.js` 캐시 꼬리표 갱신.
- `viewer.js`: 첫 풀이 조립 전에 `WeaponChapters.readyWithin(2500)` 한 줄(스위치·장별 설정 수신). 장을 새로 끼우지 않는다.
- `reading-feature.js`: `wp:` 조각을 `WeaponChapters.render`로 넘기는 한 줄. 기존 중복 제거(FactOnce)가 그대로 적용된다.
- 대운·세운·월운 구조·그래프는 그대로. 블록 안 시기 줄은 `MantraWeapon.timeline` 값(대운 간지·세운 연도·월운 절기)을 그대로 쓴다.

## 8. 완료 보고 (지시문 14절 8개 질문)

1. **연결된 주제**: 종합풀이·재물운·커리어운·인연운·개운법(각 1장, 관리자에서 장 추가·변경 가능). 건강·사고수·전생은 연결하지 않음.
2. **주제별 근거**: 종합=세력·투간·통근·병존·간여지동·십성 전체 / 재물=주무기 십성 ↔ 재성 관계·재성 세력 / 커리어=주무기 십성 + 관성·식상·재성 비율 / 인연=주무기 십성 + 배우자 자리·배우자성 비율(사실만) / 개운=주무기 십성 + 용신 쪽 십성(부족 기능). 운 줄은 모두 운 천간 십성(활용 방향)·운 글자의 통합 용신 역할(지원)·합충·극(제약).
3. **대운·세운·월운**: `MantraWeapon.timeline` 하나에서 주제별로 골라 씀 — 종합(지금·다음 발현 대운 + 발현 세운 2), 재물·커리어(대운 + 세운 3 + 월운 2), 인연(대운 + 세운 3), 개운(지금 대운·올해·다음 3개월). 줄마다 활성도와 유리도를 따로 표기.
4. **개인화 변화**: 이전에는 이 다섯 장에 주무기 관련 내용이 없었다. 이제 장마다 1,000~1,700자의 명식 고유 문단(실제 천간·지장간·자리·비율·간지·연도)이 붙고, 같은 시기도 주제마다 다른 해석으로 나온다. 다만 문장 틀은 십성 5갈래 × 주제별 사전이라, 같은 십성 묶음 주무기를 가진 사람끼리는 해석 문장이 같고 근거·시기 줄만 다르다.
5. **관리자 제어**: 가능 — 전체 스위치 + 질문별 사용·주제·11개 데이터 항목, 미리보기.
6. **결제·유료 콘텐츠**: 결제·잠금·상품·질문 ID 코드는 손대지 않았고, 잠긴 장에는 기존 구조상 블록이 그려지지 않는다. 결제 관련 테스트 통과.
7. **발견한 예외**: ① 시기 문장이 활성도와 무관하게 '좋은 결'로 나오던 문제 → 활성도 단계별 문장으로 수정 ② 주제 사이 문장 중복 22,621 → 0 ③ 조사 오류("금을(를)", "정재이(가)", "인성(…)로", 대운에 "해예요") 수정 — **이 중 "금을(를)" 수정은 이미 배포된 `/weapon.js` 문구(만세력 운세 흐름 상세 카드 두 군데)도 바꾸므로, 다음 배포 때 만세력에도 반영된다** ④ 기존 블록의 `data-sc` 번호가 호출마다 늘어나는 비결정성(기존 문제, 이번 작업과 무관) ⑤ 시간 모름 64%가 미확정이라 그 명식은 종합 안내만 보임.
8. **운영 반영 권고**: 코드 배포는 권고 가능 — 스위치 꺼진 상태에선 화면이 그대로임을 검사로 확인했다. 단 **스위치 켜기 전에** ① 관리자 미리보기로 실제 명식 몇 개의 문장 검수 ② 실제 결제된 계정으로 운영 화면에서 다섯 장 확인(로컬 서버에는 풀이 API가 없어 전체 읽기 화면 안에서의 확인은 못 했고, 같은 조립 함수를 운영 페이지 스크립트·CSS로 직접 그려 확인함)을 권한다.
