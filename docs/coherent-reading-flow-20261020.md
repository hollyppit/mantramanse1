# 연결된 사전 풀이 본문 (2026-10-20)

기존의 `질문 본문 + 강약 해설 + 십성 조언 + 일간 비유` 결합을 중단했다. 일반 풀이 76개는 질문별 생활 장면에서 선택의 이유를 설명하고, 같은 장점이 부담으로 바뀌는 지점과 질문에 맞는 실천으로 이어진다. 창작 8개는 별도 기존 서사를 유지한다.

`_reading-flow-scenes.js`에는 76개 질문의 생활 장면과 대상을 둔다. `_reading-flow-copy.js`는 기존 계산의 기본 비중, 개별 십성/검수된 쌍, 신강·중화·신약과 일간을 함께 읽는다. 문장은 코드에 사전 작성한 종속절과 편집 가능한 본문 템플릿으로 완성하며 네트워크 생성이나 AI 호출을 하지 않는다. 새로 만든 문안 ID는 항목당 15개(`flow-주제-번호-구간-역할`)다.

- 생활 예시·강점·위험·보완·실천마다 연결된 문단 하나만 반환한다. 독립적인 조건 해설을 뒤에 추가하지 않는다.
- 일간의 나무·햇빛 등 별도 비유는 붙이지 않는다. 일간과 강약은 같은 실천을 어느 범위와 방식으로 할지에 반영한다.
- 실천은 기존 질문에 맞춘 구체적 행동 하나를 중심으로 한다. 일반적인 추가 숙제를 여러 개 덧붙이지 않는다.
- 부족한 계산값을 추정하지 않는다. 완전한 조건을 고를 수 없으면 검수된 질문별 기본 본문으로 돌아간다.
- 출처에 연결한 개인 판단은 기존 게이트를 유지하며, 생활 조언을 명리 근거인 것처럼 새로 만들지 않는다. 이름은 기존 클라이언트 처리만 사용한다.

관리자에서는 연결된 본문 템플릿을 우선 표시하고 기존 문장과 조건 자료는 별도 보기로 보존한다. `〔동기〕`, `〔선택〕`, `〔역량〕`, `〔주의시작〕`, `〔수정〕`, `〔부담〕`, `〔실행〕`을 본문 안에서 편집할 수 있다. `〔역량:은〕`처럼 은/는, 이/가, 을/를, 과/와 조사를 지정할 수 있다. 알 수 없는 기호나 닫히지 않은 기호는 게시 검증에서 차단한다. 미리보기는 실제 계산값으로 기호를 채운 완성 문단을 표시한다. 더 구체적인 적용 조건을 가진 템플릿을 우선한다.

검증은 `tests/compound-reading-sim.cjs` 다음 `tests/coherent-reading-flow-sim.cjs`를 실행한다. 계산된 가상 사주 20개 × 76개 항목에서 원래 조건 문단이 덧붙지 않는지, 문단이 하나씩 표시되는지, 긴 문장이 한 책 안에 반복되는지, 실천이 중복되는지와 관리자 편집 반영을 확인한다. `tests/health-narrative-flow-sim.cjs`는 사용자 화면·PDF의 같은 문안 사용과 이름/생년월일의 비전송을 확인한다.

DB 갱신 도구는 `tools/prepare-coherent-reading-upgrade.cjs`다. 기존 304개 검증 사주와 142개 기존 문안을 보존하며 본문 템플릿을 추가한다. 실제 계산한 익명 검증 사주에서 필요한 사례만 골라 804개 사례를 추가했다. 항목당 최대 16개로 기존 관리자 한도(20개) 안에서 모든 조건 문장에 적용·반례가 있도록 했다. 문장과 검증 사주, 이전 판본은 CAS와 버전 검사로 보존한다. 이 검증은 조건 일치와 구현 검증이며 외부 명리 전문가 승인이나 실제 사건 확인을 의미하지 않는다.

공개 조회는 `reading_published_library` RPC로 현재 게시본의 version/published만 가져온다. 별도 복제본을 두지 않아 기존 CAS 게시와 일치한다. 관리자 목록은 `reading_library_summaries`로 개수만 가져온다. 실제 측정에서 평균 전달량은 전체 판본 1,071,610바이트에서 게시본 57,028바이트로 줄었다. 초안·검증 사주·이력은 DB와 관리자에 보존하면서 Worker 처리 한도 오류를 피한다. `tests/reading-public-projection-sim.cjs`는 공개 조회와 관리자 목록이 전체 KV 판본을 읽지 않는지 검증한다.

두 RPC는 SECURITY INVOKER와 빈 search_path를 사용하고, 기존 service_role만 호출할 수 있다. anon/authenticated에는 실행 권한이 없다. 변경 전후 보안 점검에서 새 경고는 없었다. 기존 서버 전용 kv의 RLS 무정책 INFO는 공개 접근을 막기 위한 의도된 설정으로 유지했다. [관련 Supabase 설명](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).
