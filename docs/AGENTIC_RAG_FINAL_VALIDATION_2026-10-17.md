# 전체 연구 및 격리 Supabase RPC 검증 결과

## 완료한 검증

실제 Brave 검색과 Wikisource 고전 원문 수집 → 실제 OpenAI 구조화 추출 → 원문·조건·위험도 검증 → 격리 PostgreSQL 17.5에서 자동 게시 → 지식 1개 롤백을 확인했다. 최종 상태는 `rolled_back`이며 다른 지식은 유지됐다. 모든 지식은 테스트용 합성 레코드이며 운영 386개 지식에 연구 결과를 쓰지 않았다.

초기 시도에서 검색·원문 수집은 성공했지만 API JSON 입력 조건, 인용 공백, 본문 속 URL 선택 때문에 추출·검증이 거절됐다. 실제 오류를 바탕으로 JSON 입력 표시와 문서 URL 목록을 사용하는 응답 스키마를 추가했다. 기존의 문자 단위 원문 일치 검사는 유지했다. 최종 추출은 앞서 실제 수집한 문서를 그대로 재사용했고 응답을 수정하지 않았다. 따라서 이는 여러 시도에 걸친 실제 단계별 검증이며, 수정 후 새 검색부터 한 번에 다시 실행한 검사는 아니다.

격리 Supabase 브랜치에서는 PostgreSQL 17.11의 실제 PostgREST/RPC를 검사했다. JWT와 추가 임시 토큰을 요구하는 검증 함수 안에서만 서비스 키를 사용했고, 앱의 실제 `_store.js` 어댑터를 연결했다. 동시 CAS·오래된 값 거부·익명 RPC 거부·일반 로그인 역할 실행 권한 없음·원본 승인/게시 값 보존을 확인했다. SQL 함수는 호출자 권한으로 실행하며 `search_path=pg_catalog`다. 운영 자료는 복사하지 않았다.

브랜치 `rag-validation-20261017` (`xovunlsvhpthkhjsnhzt`)는 검사 후 삭제했고, 브랜치 목록에서 제거된 것을 확인했다. 검증 함수도 브랜치와 함께 제거되는 임시 자원이다. 운영 `main`은 유지했다. 연구 전체 실행은 로컬 PG17, 호스팅된 Supabase RPC는 별도 검사였으며 전체 연구를 한 실행으로 호스팅 DB 위에서 돌린 것은 아니다.

## 실제로 수정한 것

- JSON 추출 입력에 명시적 `json` 표시 추가.
- 출력 스키마의 `sourceUrl`을 입력 문서 URL 목록으로 제한하고, 인용의 공백·문자 보존 지시 강화. 서버의 원문 검사는 그대로 유지.
- AI가 별도 판본 URL을 인용하면 허용 출처·문서 수 상한·비용 예약 안에서 실제로 수집한 뒤에만 검증. 허용되지 않은 출처와 상한 초과는 차단. 이 경로도 회귀 검사했다.
- 실제 유료 검사 도구는 전송 전 누적 비용 상한을 확인하고, 성공하지 못한 검증은 실패 종료 코드로 반환.

## 비용

사용자가 승인한 API 예산은 최대 **US$0.05**였다. 검색 추정 비용, 실패 요청의 미확정 비용 예약까지 보수적으로 유지한 최종 누적 상한은 **US$0.0495256**이다. 성공 응답에서 받은 사용량으로 확인한 미사용 예약분만 정산했다. 이 값은 실제 청구액이 아니라 상한이며, 운영자 청구 원장까지 조회한 것은 아니다. 검사 중의 자동 재시도는 껐고, 코드 수정 후 명시적으로 실행한 시도만 있었다. 추가 유료 호출은 중단했다.

Supabase 견적은 **US$0.01344/시간**, 생성 시각은 2026-10-17 21:00:44 KST다. 검사 후 1시간 이내 삭제했고 별도 프로젝트(월 US$10)는 만들지 않았다. 세금·청구 반올림을 포함한 최종 브랜치 청구액은 확인되지 않았다.
