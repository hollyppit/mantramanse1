## 도수 자료 조사 결과 (미승인 후보 — 코드에 넣지 않음)
- 《회남자·천문훈》(위키문헌 https://zh.wikisource.org/wiki/淮南子/天文訓): 角12 亢9 氐15 房5 心5 尾18 箕11¼ 斗26 牛8 女12 虛10 危17 室16 壁9 奎16 婁12 胃14 昴11 畢16 觜2 參9 井**30** 鬼4 柳15 星7 張18 翼18 軫17 → 합 362¼ (365¼가 아님. 井 30은 판본 문제 가능성, 비평본 대조 안 함)
- 《한서·율력지》(위키문헌 https://zh.wikisource.org/wiki/漢書/卷021): 井 **33**, 나머지 동일, 분수(¼) 표기 없음. 방위별 합 동75·북98·서80·남112 = 365
- 두 문헌 모두 **적도 기준 천문 도수(古度)** 이며, 건물의 지평 방위각으로 바꾸는 규칙은 없다. 나경(羅經)의 28수 고리(24산과의 정렬)는 신뢰할 만한 출전을 찾지 못했다.
- 그래서 `DEGREE_SYSTEMS`, `LINK_SYSTEMS` 는 비워 두었다. 화면은 '분류형' 원형(사신별 7수 묶음)과 '데이터 미확정'만 보여 준다.

### 승인 체계를 넣는 방법
`mansions-data.js` 의 `DEGREE_SYSTEMS` 에 항목 하나를 추가한다(필수: 출전·sourceVersion·좌표 체계·한 바퀴 도수·기준점·단위·28수 도수, 승인 `approved: true`). 건물 방위 판정까지 하려면 출전 있는 `conversionRule: { offsetDeg, direction, source }` 가 필요하다. 검증 규칙을 통과하지 못하면 엔진이 계산을 막는다(균등 분할·합 불일치·출전 없음·미승인).

## 값일수(날의 28수)
- 28일 주기, 각 수의 요일(칠요) 고정. 기준일 **2026-11-21(토, 己亥) = 女수**.
- 출처 교차: lunar-javascript(6tail) `getXiu()` 표(일지+요일), 중국 노황력 https://wannianli.tianqi.com/laohuangli/2026-11-21.html ('北方女土蝠 值日星宿'), 2026-11-22 = 虛 동일 확인. 2000-01-01 = 胃.
- 원전(《협기변방서》 등) 대조는 아직 하지 않았다. 행사별(이사·개업·혼례·계약·건축·장례) 길흉은 **판단 보류**.
- 택일 점수(engine.js `pickDays`)는 손대지 않았다.
