# 타임라인·일진 캘린더·주제별 상세풀이에 오늘 변경 반영 (2026-11-20)

사용자 요청: 지장간 정정, 계절·월령 오행 세력, 암합, 오행별 실전 전략을 운명의 타임라인·일진 캘린더·주제별 상세풀이에 모두 적용하고, 상세풀이는 전수 검토해 고친다.

## 1. 계산(지장간·계절 세력)은 이미 같은 엔진

- 세 화면 모두 같은 `/engine.js`를 쓴다. 서버 `functions/`도 같은 엔진을 쓰거나, 클라이언트가 보낸 `sd`만 읽는다.
- 그래서 지장간 표, 오행 세력, 강약, 용신, 운 점수는 엔진이 바뀐 순간부터 세 화면에 같이 반영된다.
- 상세풀이 원국 표(`report/natal-table.js`)의 지장간도 엔진 `cells.hidden`을 쓴다.
- 다만 **엔진과 따로 계산하던 곳**과 **새 정보를 보여 줄 자리**가 문제였다. 전수 조사로 찾아 아래처럼 고쳤다.

**오행 전략 블록의 내용**

- 재물 장(`esBlock`): 힘이 되는 기운(용신)과 수익화 예, 확장(희신)과 수익화 예, 조심할 돈 버는 방식(기신)
- 커리어 장(`esBlock`): 강점을 쓰는 방식(십성 연결 문장), 확장(희신), 지금 대운의 일 전략(엔진 흐름 점수 반영), 조심할 일하는 방식(구신)
- 서사 문단(`plainNote`)과 블록은 같은 문장을 쓰지 않는다. 커리어 서사 문장에서 주의 문장을 빼고, 주의는 블록이 맡는다.

### 문구

- `reading-depth.js`: '글자 수가 가장 적은 쪽은 {g}이에요'라는 문구를 바꿨다. 실제 값은 세력 %라서 '계절과 뿌리까지 따졌을 때 힘이 가장 작은 쪽은 {g}이에요'로 고쳤다.
- 바뀐 지장간과 어긋나는 하드코딩 문장(子 속 壬, 酉 속 庚, 午 속 丙, 亥 속 戊 등)은 주제 풀이 코드·편집 원고·서버 문안에서 찾지 못했다.

### 캐시

- `report/v2/index.html`에서 고친 파일 10개의 `?v=`를 `20261120-rv`로 올렸다.
- 서버 저장 결과(KV)는 사주 데이터 전체의 해시를 키로 쓰므로, 엔진 값이 바뀌면 자동으로 새로 계산된다.

## 4. 그대로 둔 것 · 더 볼 것 (→ 앞의 세 항목은 6절에서 바꿨다)

- `compat-pair.js`의 궁합 오행 분포는 자체 산식이다(월지 ×1.5, 투간 ×1.3). 바꾸면 궁합 점수가 바뀌므로 이번에 손대지 않았다. 궁합 챕터를 만드는 다른 세션과도 겹친다.
- `wealth-career.js scan()`은 십성 투출·통근 레벨을 자체 가중치로 매긴다(직업·수익 유형 순위의 기반). 지장간 순서는 맞게 읽는다. 계절 모델과 합칠지는 별도 결정이 필요하다(순위가 바뀜).
- 용신 출처: 상세풀이 공통 데이터는 `ch.yong`, 서사·전략 모듈은 `ch.unified`를 쓴다. 학파 자동(기본)이면 둘이 같다. 사용자가 학파를 직접 고른 경우에만 다를 수 있다.
- 공유 문단 저장소(`_reading-block-store.js`)는 장 단위로 저장된 문단을 다시 쓴다. 조건 판정은 실행할 때 새 `sd`로 하지만, 저장된 문장 자체는 옛 엔진 시절에 만든 것일 수 있다.
- `_interpretation-engine.js`의 `ENGINE_VERSION`, `engine.js`의 `ADJUSTMENT_VERSION`은 올리지 않았다(값 해시로 무효화는 된다).

## 5. 테스트

- 새 테스트 `tests/topic-reading-sync-sim.cjs`(사주 150명)가 다음을 확인한다.
  - 세운 간지·흐름 점수가 엔진 값과 같다.
  - 해마다 운 칸 색이 흐름 점수를 따른다(모든 사주에서 그려짐).
  - 교운기·재물 뿌리·강약 단어가 엔진 기준이다.
  - `sd.seasonal`이 엔진 값과 같다.
  - 오행 전략 블록이 용신·희신과 일치하고 서사 문장과 겹치지 않는다.
  - 개수 표현이 없고, 캐시 버전이 올라갔고, 버전 표기가 깨지지 않았다.
- `tests/timeline-consistency-sim.cjs`: 서사에 덧붙는 문단으로 오행 전략(재물·커리어, 렌즈별 한 번)도 허용하도록 고쳤다. 사주 200명 모두 재물·커리어 각 한 번, 전문 용어·단정 표현 없음을 확인했다.

| 항목 | 이전 | 지금 | 결과 변화(사주·쌍 300) |
|---|---|---|---|
| 궁합 상대 글자 세력(`compat-pair.js glyphPower`) | 자체 산식(뿌리 없는 천간 0.6, 월지 정기 1.5, 투간 1.3, 지장간 일수) | 엔진 최종 세력(계절·월령 왕상휴수사·뿌리·충형파해·합화)에서 상대 일간 몫만 뺀 비율. 엔진 계절 모델이 없으면 옛 셈법 | 궁합 점수가 바뀐 쌍 223(중앙값 2점, 최대 11점), 등급이 바뀐 쌍 43(14%) |

다음 두 가지는 확인한 뒤 바꾸지 않았다(바꾸면 손해).

- **공유 문단 저장소(`_reading-block-store.js`)**: 문단은 조건 서명으로 골라 쓰고, 조건은 매번 새 사주 데이터로 다시 판정한다. 그래서 엔진이 바뀌어도 맞지 않는 문단이 나가지 않는다.
- **`ENGINE_VERSION`**: 올리면 검수를 마친 문단 저장소 전체가 무효가 되어 AI로 다시 만들어야 한다(비용). 값 해시로 이미 새로 계산되므로 올리지 않았다.

테스트 `tests/engine-single-source-sim.cjs`가 다음을 검사한다.
- 직업 재료 단계·투출·통근이 엔진 값과 같다.
- 궁합이 엔진 최종 세력을 쓴다. 결과는 결정적이고 엔진 결과를 바꾸지 않는다.
- 용·희·기·구가 통합 용신과 같다.
- 엔진 결과 JSON이 그대로다.
