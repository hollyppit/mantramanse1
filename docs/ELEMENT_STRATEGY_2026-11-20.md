# 오행별 실전 전략 · 직업·수익 콘텐츠 통합 (2026-11-20)

## 1. 기존 구조와 재사용

| 영역 | 기존 구현 | 이번 작업 |
|---|---|---|
| 오행·강약 탭 SECTION 01 '나의 돈 버는 방식' | `wealth-career.js` — 원국 십성 구조 11종 → 수익 유형 6종 → 대표·보조 유형, 핵심 역량, 수익 방식, 근거 | 그대로 두고, 용신·희신·기신·구신 전략 블록을 덧붙임 |

| 용신·희신·기신·구신 | 엔진 통합 용신 `ch.unified.roles`(억부·조후·통관·격국·제화 종합), 학파별 `ch.yongAll`, 충돌 `ch.unified.conflicts` | **읽기만 함**(재판정 없음) |

새 모듈 `element-strategy.js`(`MantraElementStrategy`)가 번역 계층이다.

- 오행 세력, 계절 왕쇠, 지장간, 통근, 합충, 억부·조후, 용신은 다시 계산하지 않는다.
- 엔진의 최종 결과를 받아 전략 문장으로 옮긴다.

## 2. 오행별 전략 데이터 (`ELS`)

| 오행 | 유형 | 데이터 항목 |
|---|---|---|
| 목 | 성장·기획·육성형 | 다섯 오행 모두 같은 항목을 둔다: 키워드, 수익 방식 6가지, 핵심(용신)·확장(희신)·주의(기신·구신) 문장, 직업 안 활용 방향, 운 분야별 문구(지원처 환경, 이직 준비, 사업 검토 대상, 주목할 귀인 유형, 횡재 점검 방법) |
| 화 | 노출·표현·확산형 | (같음) |
| 토 | 안정·운영·축적형 | (같음) |
| 금 | 전문성·분석·정밀형 | (같음) |
| 수 | 연결·유통·정보형 | (같음) |

- 문장은 "검토해 보세요·유리할 수 있어요"처럼 쓴다. "○○업을 하세요" 같은 단정은 쓰지 않는다.
- 이 분류는 전통 상징을 현대 경제활동에 옮긴 것이라는 안내를 화면에 함께 둔다.

## 3. 생성 방식

### 3-1. 원국 `natal(M, ch)`

| 출력 | 기준 |
|---|---|
| 핵심 전략 | 용신 오행 |
| 십성 결합 문장 | 용신의 십성 묶음(예: 화 = 인성 → "배움과 지식을 쌓는 힘을 밖으로 알리고 전달하는 방식으로") |
| 확장 전략 | 희신 오행 |
| 주의 전략 | 기신·구신 오행 — 금지가 아니라 일하는 방식에서 조심할 점 |
| 부족·과다 참고 | 최종 세력 10% 미만 / 30% 이상. 각 오행의 역할을 그대로 적고, "부족하다고 채울 필요는 없고 많다고 나쁘지 않다"를 안내 |
| 판단 근거 | 억부 용신, 조후 용신, 최종 판단 기준, 억부·조후 일치 여부, 엔진의 충돌 설명 |

### 3-2. 직업 `job(M, ch, j)`

- 순위와 추천 이유(십성 구조·업무 환경·활동 분야)는 기존 계산 그대로다.
- 용신 활용: 그 오행의 '직업 안 활용 방향'을 붙인다.
- 희신 확장: 희신 오행의 확장 문장을 붙인다.
- 기신·구신 주의: 직업에 쓰이는 오행이 기신·구신이면, 피하라고 하지 않고 일하는 방식에서 조심할 점을 붙인다.
- 판단 근거: "용신이 들어 있다고 순위를 올리지 않음"을 명시하고, 쓰이는 오행별 역할을 적는다.

### 3-3. 운 `luck(M, ch, x, kind, key)`

- 들어오는 오행: 그 운의 천간 오행과 지지 본기 오행, 각각의 엔진 역할.
- 판정: 역할만으로 정하지 않는다.
  - 용신·희신이어도 엔진 흐름 점수(계절 왕쇠·통근·생극·합충·희기 반영)가 −10 미만이거나 원국과 충·형·파·해가 생기면 '조건부'로 보고 "서두르지 말고 단계를 나눠"를 덧붙인다.
  - 용신·희신 기운이 들어오지 않는 시기에는 "장기 강점(용신)을 지키는 방향"으로 안내한다.
  - 기신·구신이 들어오면 그 오행의 주의 문장을 붙인다.
- 분야별 문장 틀(7개 모두 서로 다름):

| 분야 | 문장 틀 |
|---|---|
| 취업 | 이력서·포트폴리오에서 앞세울 강점, 찾아볼 업무 환경 |
| 이직 | 경력을 더 높은 가치로 쓸 직무인지, 옮기기 전 준비 |
| 직업 | 긴 흐름의 업무 방식 |
| 사업 | 먼저 검토할 사업 방향, 현금 흐름 점검 |
| 귀인 | 주목할 관계 유형과 주고받는 법 |
| 대인·구설 | 기록과 조건 확인. 원국과 충돌이 생기면 계약·협의 문서 확인을 덧붙임 |
| 횡재 | 기회 점검 방법, 당첨·투기 신호가 아님, 지출 한도 |

- 근거: 천간·지지 오행과 역할, 흐름 점수, 원국과의 충돌.
- 장기 전략(용신)과 시기 전략이 다를 수 있다고 함께 적는다.

## 5. 테스트 (`tests/element-strategy-sim.cjs`, 사주 300명)

- 수익 유형(대표·보조)과 직업 목록·순위가 모듈이 있을 때와 없을 때 같다.
- 핵심 = 용신, 확장 = 희신, 주의 = 기신·구신이 엔진 통합 용신 역할과 일치한다. 용신과 희신을 구분한다.
- 부족·과다 오행은 역할을 바꾸지 않는다. 확인한 사례:
  - 부족 화·토·금, 용신 수
  - 과다 수 = 한신
- 억부·조후 근거를 보존한다. 억부 토·조후 화인 명식에서 최종 판단(화)을 그대로 쓴다.
- 금지·단정 표현이 없다.
- 직업 문장의 용신·희신이 역할과 일치한다.
- 취업·이직·직업·사업 문장이 서로 다르다.
- 대인구설: 원국과 충돌이 있을 때 문서 확인 문장이 붙는다(1,801건).
- 횡재: 당첨·투기 아님과 지출 한도 문장이 늘 있다.
- 용신·희신이 들어와도 조건이 나쁘면 '서두르지' 문장이 붙는다.
- 대운·세운에 따라 전략이 달라진다(300명 모두).
- 엔진 결과(오행·강약·역할·대운 점수)가 그대로다.
- 만세력과 타임라인이 같은 공통 계산 데이터를 쓰는 것은 `tests/timeline-consistency-sim.cjs`가 검사한다.

## 7. 더 검토할 쟁점

- 귀인운은 지금 오행 역할과 간지·점수 근거로만 문장을 만든다. 천을귀인 같은 신살과 직접 연결하지는 않는다(엔진의 귀인 점수에는 이미 들어 있음).
- 직업 데이터의 `els`(쓰이는 오행)는 기존 값을 그대로 쓴다. 직업별 십성 메타데이터를 더 세분화할지는 별도 검토가 필요하다.
- 운 판정의 '조건부' 문턱(흐름 점수 −10)은 기존 서사 엔진의 '어려운 시기' 문턱과 맞춘 값이다. 조정이 필요하면 모듈 상단에서 바꾼다.
- 무빙툰·타임라인(`report/`) 화면에는 아직 연결하지 않았다(만세력 화면만).
