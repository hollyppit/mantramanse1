# 합성 규칙(composer) · 2026-10-22

상태: **로컬 오프라인 구현.** editorial/rebuild-20261022/compose.mjs, tests/rebuild-compose-20261022.cjs. 운영 DB·서비스 라우트·관리자 화면에 연결하지 않았다. AI/네트워크 호출 0.

## 흐름
조건 계산(deriveFacts) → 후보 선정(engine.simulate: 복수 조건·unless·draft 차단) → 순위(rank) → 선택(pick) → 문단 구성(sections) → 문장 중복 제거 → 출력.

## 규칙
1. **순위:** priority → 일치한 조건의 구체성(COND_FIELDS 가중치 합) → 동점일 때 차트별 고정 해시. 해시는 동일 근거의 후보가 모든 사용자에게 사전순 첫 문안으로만 나오는 것을 막는 변주이며 운세 신호가 아니다. 같은 차트는 항상 같은 결과.
2. **최대 2개.** 1순위는 전체 구조(핵심 진단·근거·현실 사례·잘 쓰이면·손해 보기 쉬운 곳·실천·상황별), 2순위는 "겹쳐 보이는 단서"(핵심+사례)와 "함께 챙길 점"(조언)만 붙인다.
3. **의미 중복 제거:** 같은 의미 계열(meaningTags 앞 두 마디)은 함께 나오지 않는다. 명시적 conflicts 관계는 함께 나오지 않는다. 핵심 문장 단어 겹침(자카드) 0.6 이상이면 2순위에서 제외한다. 리포트 전체(composeReport)에서는 앞 장에서 쓴 계열·핵심 문장·문장도 반복하지 않는다.
4. **근거가 없으면 빈 결과:** coverage `missing-evidence`, 본문 빈 문자열. 분량을 채우지 않는다.
5. **draft 차단:** preview 옵션 없이는 초안이 나가지 않는다.
6. 각 선택에 일치한 조건(키·기대값·실제값)을 `picks[].matched`로 남겨 관리자 추적에 쓸 수 있다. 제외된 후보와 사유는 `suppressed`에 남긴다.

## 검증 (600개 실제 계산 원국 × 12개 장 전체 리포트)
결정성, 장당 최대 2개, 계열 중복 0, 모든 선택이 복수 조건 일치, 리포트 내 반복 문장 0건(18자 이상), `undefined` 류 출력 0건, draft 차단, 근거 없음→빈 출력, conflicts 존중, 유사 핵심 문장 제외, 1개 한정(max=1) 확인. 묶음 1·2 문안 검증과 파일럿 테스트도 그대로 통과. 결과는 output/rebuild-20261022/compose-tests.json.

노출되는 문안 수 (선택된 원국 중 2개 표시 비율): 01·03 0%(축이 하나), 04 60%, 08 96%, 09 87%, 11 81%, 12 36%. 출력 길이 중앙값은 장당 약 540~910자이다.

## 한계
- 서로 다른 장의 의미가 겹치는지는 계열 키와 문장 단위만 본다. 장 간 의미 중복(예: 05 겉과 속과 06 가장 강한 무기)은 사람이 검수한다.
- 2순위 연결 문구는 고정 라벨("같은 원국에서 겹쳐 보이는 단서")이다. 두 문안이 서로 모순되는지는 conflicts에 선언된 것만 걸러 낸다. 선언되지 않은 내용상 모순은 자동 감지하지 못한다.
- 같은 문안 안의 반복(일간의 힘만 다른 변형이 사례·장단점을 공유)은 이번 규칙으로 해결되지 않는다.
- 응용(직장·사업·프리랜서) 3줄은 항상 모두 보여 준다. 사용자 상황에 맞춘 선택은 아직 없다.
- 서비스 코드(movingtoon-reading, 게시 라이브러리 normalizePassages)는 수정하지 않았다. 이 composer를 실제 출력에 연결하려면 passage 메타데이터가 소실되지 않도록 별도 후보 키와 변환기가 필요하다.
