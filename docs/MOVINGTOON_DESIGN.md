# 개선 설계와 작업 순서

## 원칙
엔진과 저장 데이터는 변경하지 않는다. 기존 ID·관리자 저장본·영상·이미지·온보딩·인트로·귀인 호칭·자동 스크롤/속도 설정을 유지한다. 레거시 상세 챕터는 15개 주제에 귀속해 재배치하며 원본 문서는 보존한다. 특화 상품은 종합 순서를 강제하지 않는다.

## 단계
1. 현황 보고와 120명식 기준선 검증.
2. 15주제 매핑 계층 추가: 핵심 요약 → 성향 → 강점/취약점 → 승화 → 직업 → 재물 → 연애/결혼 → 관계/궁합 → 건강 → 인생 → 대운 → 10년 세운 → 올해/월별 → 환경 → 실천. 기존 상세 및 상징 이야기는 해당 주제 안에 유지한다.
3. 공통 8요소를 계산된 조건과 편집 규칙으로 구성. 계산 사실·모델 해석·생활 조언을 별도 표시. 근거가 부족한 결론은 명시적으로 보류한다.
4. AI 입력에 요소 역할과 챕터 소유 주제 전달, 새 신살/격국 거부, 생성 문장 중복 검사. 판단은 기존 계산/학파 후보를 유지.
5. 관리자 공통 요소 누락·중복 검사 및 지식 DB의 장점 강화/약점 보완 필드 확장. 기존 actions 폴백으로 이전 데이터 호환.
6. 웹과 같은 공통 설명을 PDF에 페이지별 출력해 잘림 최소화.
7. 복수 명식, 시간 미상·절기/야자시·회귀 테스트; 결과와 제한 기록.

## 저장/복구
DB 스키마 마이그레이션은 필요하지 않다. 새 필드는 선택 항목으로 기존 actions와 함께 저장하며 읽을 때 폴백한다. 운영 저장/배포는 수행하지 않는다. 운영 적용 전에 Supabase kv 전체 export(만료 정보 포함), Cloudflare KV 각 키/값 export, R2 객체와 메타데이터/영상 매핑을 별도 백업하고 복제 환경에서 복구 검증한다. 저장 키 v2:content, ik 및 src 계열, worlds:config, 문체/에셋 매핑을 함께 보존한다. 복구는 이전 코드 재배포와 원래 키/값 복원으로 수행하며 캐시는 재생성한다. 삭제/일괄 덮어쓰기 마이그레이션은 사용하지 않는다.

## 검증의 한계
기준선·경계 테스트는 내부 일관성 검증이다. 독립 역법 데이터와 학파별 전문가 검수, 모바일 스크롤·실제 영상 및 PDF 브라우저 렌더링·운영 DB 복구는 별도 확인이 필요하다.
