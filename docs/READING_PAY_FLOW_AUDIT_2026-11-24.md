# 상세풀이 문안·패널·결제 뒤 흐름 전수 점검 (2026-11-24)

## 확인 방법
- 운영(mantrafortune.com) 읽기 전용: `/api/reading-editorial`(장 64개 게시), `/api/media`(패널 366개), 무료 장 열기·구매 전 장 잠금 안내·구매 창 표시를 예시 생년월일로 확인(입력 폼 제출·결제는 하지 않음).
- 로컬(prod-readonly): 입력 → 각성 → 타임라인 → 주제별 상세풀이 진입, 문안 API(`movingtoon-reading`) 200, 새로고침 복구 동작 확인.
- 오프라인: 상세풀이 본문 검사(사주 12명 × 107장 그리기, 오류 0), 결제 서버 모의 검사(`commerce-sim`), 결제 화면 모의 검사(새 `paywall-return-sim`), 패널 배정 검사(`panel-repeat-sim`).
- 결제 흐름 코드는 별도 감사(주문 → 결제창 → 복귀·웹훅 → 권한 → 잠금 해제)를 거쳐, 보고된 항목을 코드에서 다시 확인한 뒤 고쳤어요.
- 운영 DB 읽기 전용: 최근 60일 '결제 완료인데 권한 없음' 주문 0건.

## 문안
- 64개 장 모두 게시돼 있고, 무료 장은 문안이 올라와요. 구매 전 장은 근처로 가면 "이 장은 로그인하고 구매하면 열립니다"로 바뀌고 구매 창이 떠요.
- "검수된 문안을 불러오고 있습니다"로 남은 장은 아직 요청하지 않은 장이에요(지금 장과 다음 2장만 미리 불러오는 설계). 멈춘 것이 아니에요.
- 같은 주소 새로고침은 `mt_v2_restore`로 복구돼요.

## 패널 — 고친 것
- 리포트 전체 배정(2edcf2c) 뒤에도 같은 그림이 두 장에 나왔어요(운영 확인: 인연 01장과 `timeline_love_flow`).
  - 원인: 패널 목록·장 목록이 늦게 도착하면 다시 배정하는데, 이미 그린 장이 예전 그림을 들고 있었어요.
  - 고침: 이미 그린 장의 그림을 고정(`viewer.js` mediaFixed)하고, 다시 배정할 때 먼저 '쓴 그림'으로 쳐요(`reading-media.js` planReport의 fixed). 검사에 다시 배정하는 경우를 더했어요.
- 패널 그림 주소는 운영에서 모두 200(webp)으로 받아져요.

## 결제 뒤 흐름 — 고친 것
1. 모바일 결제창으로 이동할 때 이어 읽기 값을 지워 버려, 돌아오면 생년월일 입력 화면이 나오던 것 (`paywall.js`: 결과가 없으면 지우기 전에 끝냄)
2. 결제 확인이 '처리 중(202)'·서버 오류(5xx)면 아무도 다시 확인하지 않던 것
   - 모바일: 답이 정해지기 전에는 주소의 결제 값을 지우지 않아요.
   - PC·모바일 모두: 탭에 주문번호(`mt_pay_pending`)를 남겨 다음에 열 때 다시 확인해요.
3. PC에서 결제 뒤 확인 요청이 끊기면 "결제를 시작하지 못했습니다"가 뜨고 구매 버튼이 다시 살아나 이중 결제가 날 수 있던 것 → "결제 확인 중 연결이 끊겼습니다" 안내, 주문번호 남김, 버튼은 다시 살리지 않음
4. 이미 '결제 완료'인 주문에서 권한 기록이 실패해도 성공으로 답해 웹훅 재시도가 멈추던 것 (`_commerce.js` settlePortone, `confirm.js` 토스 경로) → `grant-failed`(500/503)로 답해 재시도가 이어짐
5. 웹훅 서명 실패가 기록되지 않아 관리자 점검표의 '서명 불일치' 경고가 뜰 수 없던 것 → `portone-webhook-bad` 기록, 점검표가 이를 봄

## 운영에서 꼭 확인할 것(코드로는 못 고침)
- **포트원 웹훅 수신 기록이 최근 30일 동안 없어요**(Cloudflare KV `commerce:signal:portone-webhook` 없음). 11-23 테스트 결제는 결제창 복귀 확인으로 처리됐어요.
- 웹훅이 오지 않으면, 사용자가 결제 직후 창을 닫았을 때 결제는 됐는데 권한이 안 생길 수 있어요(이번 수정으로 같은 탭을 다시 열면 다시 확인하지만, 다른 기기·새 탭은 못 해요).
- 포트원 콘솔 → 결제알림(Webhook)에 `https://mantrafortune.com/api/commerce/webhook` 이 테스트·실연동 탭 모두 등록돼 있는지, 시크릿이 `PORTONE_WEBHOOK_SECRET`과 같은지 확인이 필요해요. 배포 뒤 서명이 틀리면 관리자 판매 준비 점검표에 경고가 떠요.

## 확인하지 못한 것·남은 것
- 실제 결제(돈이 나가는 결제창)는 하지 않았어요.
- 감사에서 '확실하지 않음'으로 나온 것: 모바일 복귀 때 로그인 SDK가 두 번 실리는 문제, 잠금 정보 응답 순서 보호 없음, 결제 중 이미 요청한 장이 잠금으로 남을 수 있음(다시 확인 버튼으로 풀림).
