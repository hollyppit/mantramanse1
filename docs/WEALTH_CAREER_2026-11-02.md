**Supabase(SQL) 스키마 변경 없음 → 마이그레이션 없음.** 기존 `GLOSSARY_KV` 에 **키 1개** `wealthcareer:doc` 만 추가합니다(다른 키는 읽지도 쓰지도 않음 — 테스트로 확인).

```
{ version, enabled(공개 스위치, 기본 false),
  phrases:{ <문구ID>:{ fields:{text,on,pri,when,unless,basis,tag}, status(draft|reviewed|published), version, history[최대30], by, at } },
```

## 4. 판정 로직

**① 십성의 힘(단계):** 천간 투출(년·월·시간) × 지지 통근(지장간 정기1.0/중기.55/여기.35 × 궁위 가중) → 없음/약함/보통/강함. 월지 정기는 미투출이어도 강함, 지장간에만 있는 것은 누적 0.9 이상이어야 보통, 십성 비율 3% 미만은 재료로 세지 않음.

**② 구조 11종 × 5상태** — “십성이 있다”와 “구조가 성립한다”를 분리합니다.

| 상태 | 의미 |
|---|---|
| 성립 | 양쪽 요소가 보통 이상 + 한쪽은 강함 + 방해 요소 없음 + 실제 비율 충족(예: 식신생재는 식신 8%·재성 10% 이상) |
| 부분 성립 | 양쪽이 모두 보통 이상이나 힘·비율·방해(도식·합·재극인·관살혼잡 등) 때문에 미완성. **사유(`miss`)를 항목별로 기록** |
| 관련 요소 존재 | 한쪽만 있거나, 한쪽이 약함 수준이라 구조를 이루기엔 부족 |
| 불성립 | 필요한 요소가 모두 없음(위험 구조는 한쪽만 있는 경우 포함) |
| 판정 보류 | 시주 미상으로 빠진 요소가 있을 수 있는 경우, 극약+재성 과다(종격 가능성, 앱은 종격 미판정) |

살인상생은 인성의 양이 관살 압력의 절반 이상이고 인성이 천간에 드러나거나 강해야 성립, 식신제살은 식신:편관 비율 0.6~2.5·식신 투출·합으로 묶이지 않음이 필요합니다.

**③ 수익 유형 6종:** 유형마다 *근거 요소 점수*(힘=단계와 실제 비율의 평균, 구조 성립/부분만 가산, 관련 요소는 가산 없음)에서 *감점*(관살혼잡·상관견관·군겁쟁재·도식)을 빼고, **관문(gate)** 을 따로 요구합니다(구조 부분 이상 또는 실제 비율을 갖춘 십성 조합). 점수 0.50 이상 + 관문 통과 시에만 대표/보조 후보(보조는 대표의 75% 이상, 최대 2개). **통과한 유형이 없으면 확정하지 않고** ‘유형 미확정 + 가까운 후보 + 부족한 조건’을 보여 줍니다. 근거 수준(solid/mid/low)과 대표·보조 근접 여부도 표시합니다.

**④ 업무 환경 5축:** 기존 `careerWorkStyle` 값을 입력으로 쓰되 **숫자를 화면에 내지 않고** 범주(조직/혼합/독립 등, 임계 62/38)와 강도(뚜렷/약간)로 변환. 관인상생·재생관·식신생재 성립 시 ±4~8 보정. 기존 ‘독립 4 / 조직 96’ 은 십성 비율에 임의 가중치(scale 30)를 곱해 4~96 으로 포화시킨 값이라 통계적 근거가 없어, 신규 화면에서는 숨기고 기존 상세 영역에도 “검사 점수가 아님” 안내를 달았습니다.

**⑤ 직업:** 직업을 오행 하나로 고정하지 않음(오행 2개 이상 필수 — 테스트·관리자 검증). 점수 = 수익 유형 연결 0.40 + 업무 환경 일치 0.25 + 기존 활동 분야 점수 0.35 − 부담 환경 노출 감점. **대표·보조 유형과 연결된 직업만 먼저 채택**, 분류당 최대 2개, 5~8개. 진입 조건(자격/경력/자유)은 명리 적합도와 별도로 표시. 자격·경로는 일반적으로 알려진 국가자격 위주이며 확실하지 않으면 비워 둠.

**⑥ 취약점 10종+기본 점검:** 각 항목이 구조 판정·십성 힘·유형에서 점수를 계산하고 0.5 이상 상위 2~3개 선택(부족하면 0.3 이상, 그래도 부족하면 ‘기본 점검’). 화면에 “구조상 가능성이며 실제 행동이 아님”을 명시하고, 무재 사주에는 ‘가난 아님’ 안내 문구를 붙임.

**⑦ 문구 조합:** 조건 평가 → 같은 tag 중 우선순위 최고 1개만(충돌 제거) → 섹션 간 같은 문장·유사 문장(2-gram 유사도 0.82↑) 제거 → 이름 치환({who}). 추적(trace)에 적용 ID·배제 사유·중복 제거 ID 기록. 섹션 간 모순 점검(`validate`): 조직형 대표인데 독립 환경이면 맥락 설명 필수, 상위 직업은 대표·보조 유형과 연결되어야 함 등. **AI 호출 없음**(테스트에서 `fetch` 차단).

## 6. 남은 한계와 위험 (솔직한 정리)

1. **가중치·임계값은 이 앱의 해석 모델**이며 명리학계 합의값도, 통계적으로 검증된 값도 아닙니다. 사용자 화면에도 그렇게 고지합니다.
2. **유형 분포가 고르지 않습니다**(생산·창작 27% vs 전문기술 6%). 식상이 대부분 원국에 있어 생기는 쏠림으로, 관문·가중치를 추가 조정할 여지가 있으나 ‘정답 분포’ 기준이 없어 임의로 맞추지 않았습니다.
3. **취약점 선택이 일부 항목에 몰립니다**(가격 책정 43%·확장 39%·경쟁 34%). 문구 검수와 함께 임계 조정이 필요할 수 있습니다.
4. 대표·보조 유형이 **근접한 경우가 30%** — 화면에 근접 표시는 하지만 ‘하나로 단정하는 결과’를 기대하는 사용자에게는 모호하게 느껴질 수 있습니다.
5. **종격은 판정하지 않습니다**(극약·극왕은 안내 + 일부 구조 보류).
6. **직업 DB 41개**, 문구 254개는 초안 수준입니다. 사용자별 문구 변형은 조건 분기 정도이며, 같은 유형의 사용자에게는 비슷한 문장이 나옵니다. **문구·직업·자격 경로는 사람의 검수 전에는 게시하지 않았습니다**(기본 문구는 코드 내장 상태이며, 공개하면 기본 문구가 그대로 노출됩니다 → 공개 전 검수 필요).
7. 자격·경로 설명은 일반 정보이며 최신 응시 요건은 시행 기관 확인이 필요합니다.
8. 실기기(실제 스마트폰) 확인은 하지 못했고 모바일은 375px 에뮬레이션과 가로 넘침 검사만 했습니다. 관리자의 ‘새 문구 추가’ 폼은 API 테스트로만 검증했습니다.
9. 기존 `patterns()`(기존 화면의 구조 표시)와 신규 판정은 **기준이 달라 같은 구조의 이름이 다르게 표시될 수 있습니다**(예: 기존은 존재만, 신규는 5단계). 기존 화면은 그대로 유지했습니다.
