# Agentic RAG — 운영 적용 전 남은 일

> 최신 API/DB/PDF 결과: `AGENTIC_RAG_LIVE_CONNECTION_VALIDATION_2026-10-17.md`. 두 공급자 인증, PostgreSQL 17 로컬 검증, 실제 36쪽 PDF 다운로드까지 완료했다. 실제 생성 연구와 격리 Supabase RPC 연결은 미검증이다. 운영은 변경하지 않았다.

> 최신 결과: 실제 DB 읽기 연결 확인과 R2 920개·KV 146개 전체 백업/해시 검증을 완료했다. 상세 범위와 아직 남은 API 인증·PostgreSQL 17 격리 검사는 `AGENTIC_RAG_CONNECTION_BACKUP_REPORT_2026-10-17.md`를 우선 참고한다. 아래 이전 단계의 ‘미확인/필요’ 표시는 최신 보고서로 갱신된다.

## 지금 어디까지 됐나요?

기존 지식 옆에 보강 버전을 저장하고, 필요할 때 한 지식만 되돌리는 기능까지 구현했다. 로컬의 실제 PostgreSQL에서 SQL·권한·자동 게시·롤백·원본 보존을 검사했다. 기존 자료와 승인·게시 상태를 초기화하는 기능은 넣지 않았다.

아직 **실제 서비스에 적용된 상태는 아니다.** 검색과 AI는 테스트 응답으로 검사했으며, 실제 외부 API와 운영 DB에서의 연결 검사는 남아 있다. 사용자가 선택한 추가 비용 없는 범위에 맞춰 유료 API 호출이나 유료 테스트 DB 생성은 하지 않는다.

## 이번에 추가로 준비한 것

- 예약 실행의 기본 설정은 OFF(`crons = []`). 파일을 배포하는 것만으로 매분 연구가 시작되지 않는다.
- 첫 적용용 안전 설정 파일 `config/agentic-rag.production-safe.json`: 연구 OFF, 자동 게시 OFF, 기존 지식만 사용, 연구 예산 0. 이 파일을 만든 것뿐이며 운영 설정에 적용하지 않았다.
- SQL 함수는 호출자의 권한으로만 실행한다(`security invoker`). 서버 역할만 실행할 수 있고 연구 상태 키 하나만 갱신한다. 소유자의 높은 권한을 빌리지 않는다.
- 검색 요청 한도를 모두 사용한 실패 과제를 정상 종료하도록 수정하고 재현 테스트를 추가했다.
- 무료·오프라인 사전 검사 도구 `tools/prepare-rag-release.cjs`. 관련 소스·SQL·테스트만 모으고 파일별 SHA-256과 검사 결과를 남긴다. 키·백업 데이터는 포함 대상에서 제외하고 알려진 비밀 키 형식도 검사한다. 패턴 검사는 모든 민감정보가 없음을 완전히 보증하지 않으므로 배포 전 사람이 최종 확인한다.

검토용 묶음은 **그대로 사이트에 올리는 완성 배포 파일이 아니다.** 현재 서비스 소스와 변경 내용을 검토·통합하기 위한 자료다. 자동으로 배포하거나 DB에 연결하는 명령은 없다.

## 운영 적용에 남은 일 — 쉬운 설명

| 남은 일 | 왜 필요한가요? | 현재 상태 |
| --- | --- | --- |
| 기존 자료를 복구할 수 있게 백업 | 문제가 생겨도 원래 자료·연결·상태를 복원하기 위해 | 운영 전체 백업과 복구 확인 필요 |
| 실제 검색·AI 연결 | 테스트 응답 대신 진짜 자료를 찾아 읽을 수 있는지 확인하기 위해 | 키 설정·이용 출처·단가·작은 예산 결정 필요 |
| 운영과 같은 DB에서 확인 | 서버의 권한·SQL·동시 실행이 실제 설정에서도 맞는지 확인하기 위해 | 로컬 PostgreSQL 18 검사 완료, 운영 PostgreSQL 17/실제 Supabase 연결 검사 미실행 |
| 실제 풀이·PDF 확인 | 지식 보강이 기존 무빙툰·풀이·다운로드를 망가뜨리지 않는지 확인하기 위해 | 기존 자동 회귀 통과, 운영 조건의 최종 확인 필요 |
| 결과 보고와 배포 승인 | 적용 범위·예상 비용·복구 방법을 사용자에게 먼저 알리기 위해 | 아직 운영 배포 승인 요청 단계가 아님 |

### 최신 진행 결과 — 실제 자료 백업 및 진단 완료

사용자가 RAG 원문 159개 행(약 2.5MB)의 로컬 복사와 복원 검사를 명시적으로 승인한 후, 기존 Supabase 연결로 `mantramanse1`의 `ik:*`, `src:*`를 읽기 전용으로 내보냈다. 백업은 `output/protected-backup/mantramanse1-rag-20261017.json`에 있으며 Git/배포 묶음에서 제외된다. 이 폴더 이름만으로 OS 암호화가 제공되는 것은 아니다.

별도의 빈 로컬 PostgreSQL에 복원한 결과 159개 행 전체의 값·갱신/만료 시각·ID·연결·승인·게시 상태가 일치했다. 지식 386건, 승인 382건, 게시 333건이다. 새 SQL 함수를 복원 DB에 두 번 적용하고 실제 자료 진단까지 실행해도 기존 행이 그대로였다. 실제 Supabase에서는 조회만 했으며 SQL 함수를 설치하지 않았다. 실제 DB의 RAG 행 해시는 작업 전후 동일했다.

실제 DB는 PostgreSQL 17.11, 복원 엔진은 PostgreSQL 18.6이다. 공개 역할의 테이블 조회는 차단되어 있고 서버 역할 권한은 있다. Cloudflare 운영 사이트의 Supabase URL은 비밀 설정이어서 `mantramanse1`이 현재 사이트에 연결된 DB인지는 아직 확정되지 않았다.

전체 지식 건강 진단 결과: 저장 원문으로 인용 확인 불가 272건, 출처 불명확 1건, 적용 조건 부족 105건, 충돌 검토 후보 4건, 중복 후보 0건, 챕터 미연결 34건. 항목은 중복될 수 있다. 게시 333건의 사용 이력은 미측정이며 미사용으로 단정하지 않았다. 기존 승인·게시·원문은 변경하지 않았다. 상세 진단은 백업 옆의 비공개 로컬 JSON에 저장했고, 집계는 `AGENTIC_RAG_REAL_HEALTH_2026-10-17.json`에 있다. 운영 관리자에 진단을 표시하는 것은 아직 배포 전이다.

**이제 남은 일:** 실제 사이트의 DB 연결 대상 확인, R2/KV 및 DB 전체의 백업 범위 보완, 무료 호출이 가능한 테스트 API 인증 설정, PostgreSQL 17의 격리 환경에서 SQL/REST 실연결 검사, 운영 조건 브라우저 PDF 확인, 최종 운영 배포 승인. 실제 원문 백업·로컬 복원 단계는 완료했지만 전체 서비스 복구 백업이 완료된 것은 아니다.

재실행(네트워크·운영 쓰기 없음):

```powershell
node tools/verify-rag-backup-local.cjs output/protected-backup/mantramanse1-rag-20261017.json
```

실제 검색·AI를 계속 돌리면 외부 사업자의 비용이 발생할 수 있다. 무료 검증만으로 이 비용이나 실제 연결 성공을 확정할 수는 없다. 추가 비용이 필요한 시험은 별도 동의 전 진행하지 않는다.

## 승인 후 적용한다면 어떤 순서인가요?

1. 원본·지식 ID·승인·게시·챕터·출처 연결을 내보내고 복구 확인. 자료 수와 승인·게시 지식 수를 기록한다.
2. 운영과 분리된 검증 대상에서 실제 연결과 권한을 확인한다. 유료 테스트 자원이나 호출이 필요하면 비용부터 확인받는다.
3. 새 SQL 함수와 소스 변경을 검토하고, 적용할 정확한 파일 목록·검사 결과·비용 상한을 보고한다.
4. **사용자의 운영 배포 승인을 받는다.** 승인 전 운영 SQL 적용, Pages 배포, Worker 배포, 예약 활성화를 하지 않는다.
5. 승인 후에도 첫 시작은 연구 OFF·자동 게시 OFF·기존 지식만 사용하는 상태로 한다. 기존 지식을 다시 승인하거나 재등록하지 않는다.
6. 소수 지식에서 결과를 확인한 뒤 연구를 켜고, 검토가 끝난 저위험 보강에 한해 자동 게시를 별도로 켠다. 예약 실행은 마지막에 활성화한다.

## 잘못 보강되면 어떻게 하나요?

- 한 지식만 잘못되면 관리자 ‘AI 자동 연구’의 게시 이력에서 그 지식만 롤백한다. 다른 지식에는 영향을 주지 않는다.
- 연구 전체를 멈추려면 ‘자동 연구 중지’를 사용한다.
- 서비스에서 보강본을 모두 제외하려면 ‘기존 지식만 사용’을 켠다. 기존 게시 지식은 그대로 제공된다.
- 연구 기록과 이전 버전은 삭제하지 않는다. 기존 원본 자체를 되돌려야 하는 별도 문제가 있으면 확인된 백업·복구 절차를 사용한다.

## 무료 사전 검사 재실행

### 추가 완료: 복원·풀이·PDF 연결 검사

로컬 실제 PostgreSQL에서 연구 실행 전 백업을 별도의 빈 DB로 복원한 뒤 `public.kv`의 모든 행을 비교했다. 값뿐 아니라 만료 시각·갱신 시각도 포함해 해시를 비교한다. 자동 게시·개별 롤백 후의 백업도 다시 복원해 원본과 연구 이력이 동일한지 검사했다. 손상된 값·승인/게시 상태·챕터 연결·출처 청크·메타데이터·삭제 표식 변경은 비교 검사에서 실패한다.

자동 게시된 보강본을 실제 출처 인덱스와 판단 엔진에 전달하고, PDF 템플릿에 원칙·해석·인용이 표시되는 것을 검사했다. 개별 롤백 후 해당 근거는 판단에서 제외된다. 외부 사업자의 응답은 모의 응답이며, PDF 검사는 템플릿 HTML 검사다. 실제 운영 브라우저의 PDF 다운로드를 새로 확인한 것은 아니다.

이 결과는 **운영 데이터의 백업 완료를 뜻하지 않는다.** 운영 백업 시에는 Supabase `public.kv` 전체(만료된 값과 null 삭제 표식 포함), Cloudflare KV의 원본/대체 저장분, R2 원본 파일과 객체 메타데이터를 각각 보호된 위치에 보관해야 한다. 서로 다른 저장소의 백업 시각을 기록하고, 편집이 진행 중이었다면 일관성을 재확인한다. 백업에 개인정보가 포함될 수 있으므로 Git이나 배포 묶음에는 넣지 않는다.

운영 DB에서 JSON 배열 형태로 내보낸 행과 격리 DB로 복원한 행을 확보하면, 아래 읽기 전용 도구로 비교할 수 있다. 이 도구는 파일만 읽으며 DB에 연결하거나 복원하지 않는다. R2/KV 백업 검사를 대신하지 않는다.

```powershell
node tools/rag-backup-audit.cjs output/protected-backup/before.json output/protected-backup/restored.json
```

실제 RAG 자료 백업은 위 최신 진행 결과와 같이 기존 Supabase 관리 연결을 사용해 완료했다. 현재 Cloudflare에 저장된 비밀 키는 값을 읽을 수 없으며 로컬에 복사되지 않았다. 키를 채팅이나 문서에 붙여 넣지 않는다. 격리 PostgreSQL 17 검증 환경이 없는 상태에서 운영 DB에 시험 SQL을 적용하지 않는다.

```powershell
node tools/prepare-rag-release.cjs
```

유료 API나 운영 DB에 연결하지 않는다. `docs/AGENTIC_RAG_RELEASE_CHECKS_2026-10-17.json`에 결과를 남기고, `output/rag-release-review-*`에 검토용 파일을 모은다. 로컬 PostgreSQL 검사에 필요한 PGlite는 이미 `output/rag-staging-tools`에 설치했다. 검사 도구가 없다고 유료 클라우드 자원을 대신 만들지는 않는다.

관련 상세 결과: `AGENTIC_RAG_LOCAL_SANDBOX_2026-10-17.md`, `AGENTIC_RAG_POSTGRES_TEST_2026-10-17.json`.

권한 점검 참고: https://supabase.com/docs/guides/database/functions (호출자 권한 및 함수 실행 권한).
