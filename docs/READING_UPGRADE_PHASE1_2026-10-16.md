# 만트라 무빙툰 고도화 진단·구현 기록 — 2026-10-16

## 완료 범위

이번 변경은 통합 지시서의 1단계 오류 처리와 진단 추적, 핵심 비유의 표현 보완이다. 전면 고도화·79개 챕터 게시·운영 배포를 완료한 변경이 아니다. 기존에 이미 구현된 기능과 이번 추가 기능을 구분한다.

## 현재 구조와 원인

지시서에 명시된 engine.js, rules.js, narrator.js, content.js, content-pro.js, content-pro2.js, content-v3.js, ik-deep.js, full-reading.js, deep-life.js, deep-time.js, deep-wealth.js, deep-love.js, consistency.js, chapter-policy.js, reading-flow.js, story-composer.js, reader.js가 존재한다. engine.js는 루트, 나머지는 report/v2에 있다.

| 계층 | 실제 역할·호출 |
|---|---|
| 계산 | engine.js → saju-data.js: 계산 원국·오행·십성·운·자미두수 정보를 읽기 모델로 전달. 원본 생년월일과 이름은 FullReading의 서버 전달 객체에서 제외 |

검수 실패 문구는 full-reading.deferredParagraphs가 직접 첫 본문 문단에 넣고 있었다. 모델이나 DB에서 같은 문장이 검색된 문제가 아니다. 각 장에 동일한 실패 문장이 들어가 사용자에게 정상 본문처럼 반복됐다. 또한 네트워크 예외·JSON 파싱 실패·문단 수 초과는 실패 개수만 늘리거나 처리 없이 끝나 기존 초안과 상태가 어긋날 수 있었다. no-ai/rate-limit 응답에서 작업 인덱스를 끝으로 이동시켜 나머지 장이 개별 미완료로 처리되지 않는 경로도 있었다.

검수 실패 자체의 원인은 서로 다르다. 기존 운영 검수 문서는 특정 일주·성별·배우자궁 등 원문 조건 불일치, 시기 규칙 부족, 자미두수 승인 규칙 부족, 공급자 시간 초과를 기록하고 있다. 해당 문서는 과거 기록이며 이번 실행에서 운영 DB 현황을 재조회한 결과는 아니다. 근거 부족은 안내 문구 교체만으로 해결되지 않는다.

## 변경 파일과 동작

- report/v2/full-reading.js: 안내를 readingNotice로 분리. 본문에는 실패한 개인 해석을 넣지 않는다. 계산표·일반 실천 점검을 보존하고 refs/claim_ids는 비운다. HTTP 실패·잘못된 JSON·네트워크·시간 초과·적용 실패를 장별로 처리하고 다음 장을 계속한다. 공통 no-ai/요청 제한/비용 제한은 불필요한 추가 호출을 멈추되 남은 장마다 미완료 상태를 설정한다. 새 세션으로 취소된 응답은 이전 문서를 수정하지 않는다.
- report/v2/viewer.js: 실패 안내를 제목 아래 상태 영역에 표시. 이미 읽는 장에서도 실패한 초안이 남지 않게 바깥 읽기 섹션을 유지한 채 안쪽 표시를 갱신한다. 스크롤 진행 정책은 변경하지 않는다.
- report/v2/pdf.js: 화면과 같은 미완료 상태를 사용한다. 일반 PDF 장에서도 미완료일 때 검증되지 않은 기존 결론을 출력하지 않고 계산표와 일반 점검만 사용한다.
- functions/_reading-diagnostics.js + api/movingtoon-reading.js: 매 응답에 새 UUID 요청 식별자를 부여한다. 캐시를 재사용해도 요청 식별자는 새로 생성한다. 계산 입력, 자료 조회, 근거 부족, 생성, 검수, 통신 제한, 콘텐츠 조합/설정을 분리한다. 고정된 코드·모듈·단계·검수 이슈 코드·공급자 시도 유형만 저장한다. 사용자 이름·생년월일·원국·풀이 문장·프롬프트·공급자 원문 메시지·API 키는 저장하지 않는다.
- functions/api/reading-diagnostics.js: 관리자 인증 후 최근 7일의 최대 100건 표본을 조회한다. 요청 ID·코드·챕터·실패 단계와 시도 이력, 표본 성공률·코드별 건수·챕터별 실패율을 제공한다. 잘림을 명시하므로 전체 서비스 성공률로 해석하면 안 된다.
- report/admin/v2-quality.js: 점검·테스트 → 서비스 점검 → 점검 실행에서 생성 진단을 표시하고 마크다운 내려받기에도 포함한다.
- report/v2/deep.js / deep-wealth.js: 자동차·재물 그릇·이미지 키·기존 산식은 유지한다. 자동차 비유를 교육용 설명과 개인의 선택으로 구분한다. 재물 내부 지표를 자산 규모·소득 상한·투자 수익률이나 실제 자금 감당 능력으로 읽는 문구를 수정하고 실제 가격·납기·회수일 / 고정비·부채·비상 지출 점검을 구분한다.
- .claude/report-dev.js: 메모리 DB에서 새 진단 GET API를 시험할 수 있게 연결한다. ERRLOG_ON은 로컬 실행 환경에서 명시할 때만 켜진다.

## 오류 기록 정책과 재현

서버 기록은 기존 ERRLOG_ON=1 설정을 따르며 기본 꺼짐이다. 이번 작업에서 운영 설정을 켜지 않았다. 저장 키는 err:reading:YYYY-MM-DD:UUID이며 보존 기간은 14일이다. 기존 KV/Supabase 어댑터의 err: 경로를 사용한다. 테이블 생성·기존 레코드 수정·삭제는 없다. 기록 저장 실패가 풀이 응답을 실패시키지 않는다. 브라우저 연결 단절로 서버에 도달하지 않은 오류는 로컬 장 상태에만 남으며 관리자 서버 기록에 있다고 주장하지 않는다.

- 유효하지 않은 계산 입력 → CALCULATION_INPUT
- 자료 읽기 실패 → KNOWLEDGE_UNAVAILABLE (+ rules/settings/source-index 등 하위 단계)
- 적용 가능한 승인 근거 없음 → EVIDENCE_INSUFFICIENT
- 공급자 응답/시간 초과 → AI_GENERATION_FAILED (+ 정해진 공급자 오류 코드)
- 근거·문체·의미 검토 거절 → CONSISTENCY_REJECTED (+ 검토 단계·허용된 이슈 코드)
- 통신 한도 → SERVER_RATE_LIMIT
- 비용 상한 → AI_COST_LIMIT
- 조합/설정 예외 → COMPOSITION_FAILED / COMPOSITION_CONFIGURATION

임의 재요청으로 모델 비용을 반복 발생시키지 않는다. 기존 서버의 제한된 공급자 재시도·재검수는 유지한다. 클라이언트 통신 단절은 모델 호출의 성공 여부를 알 수 없어 자동으로 다시 청구될 호출을 만들지 않는다. 검수 기준을 완화하거나 실패한 다른 장의 문장을 복제하지 않는다.

## DB·콘텐츠 보존과 백업

운영 DB·R2·계정·권한·설정·저장 리포트에 쓰기 요청을 보내지 않았다. 계산 엔진과 원문 지식은 수정하지 않았다. 과거 운영 백업이 있다는 문서만으로 이번 변경 시점의 복구 가능성을 확인했다고 주장하지 않는다. 실제 운영 DB의 최신 백업·복구 시험은 미실시다. 이번에는 마이그레이션이 없으므로 운영 데이터 변환도 수행하지 않았다.

운영 반영 전에는 기존 운영 관리의 백업 내보내기에서 KV/Supabase 레코드와 R2 명세를 보관하고 체크섬을 확인한다. R2 명세는 바이너리 백업과 다르므로 필요한 파일 원본도 별도로 보존한다. 복구는 별도 시험 환경에서 먼저 확인한다. 코드 롤백 시 이 변경 파일을 되돌리면 기존 기록은 TTL로 만료되며, 기존 DB에 삭제 작업을 수행할 필요가 없다.

로컬 기본 데이터 기준 모듈 678개, LifeDoc 53개 장 → ReadingFlow 54개 장이며 기존 53개 ID 누락은 0이다. 이는 운영 관리자 저장본의 전수 목록이 아니다. 전체 로컬 매핑은 READING_UPGRADE_INVENTORY_2026-10-16.json에 기록했다. 기존 장은 유지 및 심화 대상으로 보존했고 삭제·비활성화하지 않았다.

새 주제·챕터를 실제 서비스에 추가·게시하지 않았다. 요청하신 9개 주제·79개 챕터는 READING_UPGRADE_TOPICS_2026-10-16.json에 design-only로 보관했다. 기존 15개 읽기 섹션·6개 세계와의 최종 운영 매핑 및 개별 챕터 작성 규칙은 후속 구현 대상이다.

## 검증

- reading-failure-sim: 장별 실패 격리, 다음 장 성공, 네트워크/JSON 실패, 공통 설정 실패, 안내/본문 분리, 원국/이름 전송 제외, 로그 화이트리스트, 관리자 인증, 기록 기본 꺼짐 검증.
- metaphor-sim: 40개 원국에서 서로 다른 그릇/통로, 자동차 비유·재물 지표의 한계, 엔진 원본 보존, 수치 유효성 검증.
- 기존 chapter-interpretation-sim: 32개 계산 원국, 출처·원문 조건·근거 선택·독립 검토·중복·인증·설정/캐시 보존 통과.
- 기존 movingtoon-reading-sim, deep-sim, reading-renewal-sim 통과. 엔진 기준선 120개 원국 통과.
- Edge chapter-interpretation-browser: 관리자 설정 저장·재조회, 빈 DB 후킹 차단, 390px 모바일 선언/지연 갱신·자동 스크롤, 미완료 표시, 같은 PDF 상태 통과. 테스트 PDF 8쪽, 넘침 0, JS 오류 0. 생성 응답은 명시적인 테스트 픽스처이며 실제 운영 자료 품질 검수가 아니다.
- Edge reading-diagnostics-browser: 로컬 실제 API의 잘못된 입력 기록 → 인증 차단 → 관리자 메뉴 → 요청 ID/오류 코드 표 표시, 390px 가로 넘침 없음, JS 오류 없음. 메모리 DB에서만 실행했다.
- 최종 전체 회귀: 94 PASS / 1 SKIP / 2 FAIL. 달력 UI 검사는 기존 검사에서 playwright를 찾지 못해 건너뛰었으며, 별도 Edge 검사는 번들 playwright로 실행했다. 전체 회귀와 개별 결과는 MOVINGTOON_TEST_RESULTS.json에 기록한다. content-db-sim의 기존 조립 해시 기준선 불일치와 content-v3-sim의 10개 결론 길이 위반은 수정 전 HEAD 파일을 메모리에서 읽어 동일하게 재현했다. 통과를 만들기 위해 기준선을 덮어쓰거나 길이 제한을 늘리지 않았다.
- 공개 운영 URL은 웹 열기 도구에서 접근하지 못했다. 이번 작업의 운영 사용자/관리자 화면 점검과 배포 확인은 미실시다.

## 남은 필수 작업

1. 현재 운영 자료 백업·복구 가능성과 관리자 저장 주제/챕터의 실제 전수 목록 확인.
2. 원국별 승인 자료 커버리지와 충돌·예외 조건 보강. 과거 운영 기록의 자미두수·시기 규칙 부족은 현재 DB에서 다시 확인해야 한다.
3. 여섯 대표 챕터의 실제 자료를 연결한 자동 검수 + 전문가 검토 + 사용자 피드백을 각각 기록. 검증 전 79개 장을 일반 문장으로 채워 게시하지 않는다.
4. 9개 주제 및 약 79개 장의 운영 매핑, 챕터별 질문/근거/예외/중복 금지 규칙, 새 사례 DB와 편집 UI, 선택형 현실 확인 질문 및 사례·전략 개인화 구현.
5. 품질 대시보드의 전체 집계/완독/이탈/피드백 지표는 별도 구현. 이번 표본 진단을 전체 통계로 간주하지 않는다.
6. 기존 콘텐츠 해시 기준선과 긴 결론의 의도 확인 후 문장별 개선·회귀 기준 정비.
7. 운영 환경의 실제 AI·에셋·다운로드·모바일 전수 점검 및 배포 후 모니터링. 현재 작업은 로컬 구현과 검증까지이며 배포하지 않았다.
