# 명리학·자미두수 해석 엔진 재구축

2026-10-14. 신규 판단 파이프라인 및 연결 구현. 운영 전환 전 검증 단계.

## 감사 결과와 보존 범위

기존 흐름은 `engine.js` 계산 → `report/v2/saju-data.js` 변환 → 모듈/DB 지식 선택 → 무빙툰 초안 → `/api/movingtoon-reading` AI 본문 → 같은 리포트 객체의 화면/PDF 출력이다.

계산 엔진과 해석 책임은 이미 파일 단위로 일부 분리되어 있다. 기존 AI 본문은 원국·DB 규칙·초안을 직접 받아 새 판단을 서술할 여지가 있으며, `natal`·`draft` 참조만으로도 통과한다. 기존 충돌 처리는 구체성·편집 우선순위·신뢰도에 따라 한 규칙을 제외한다. 자미두수 계산은 존재하지만 리포트 데이터 변환기에 명반이 없었고, 명리학과 독립된 규칙 조건이 없었다.

재사용: 원국/역법/절기/명반 계산, Supabase/KV 어댑터, 원문 업로드·청크·자료 정책, 검수·게시·수정 이력, 챕터/미디어/영상 매핑, 기존 문체 편집기, 화면/PDF 문서 객체, 운영 백업 API.

교체·추가: AI 이전의 판단 객체 확정, 구조 조건, 자미두수 독립 매칭, 실제 인용 대조, 반대 판단 보존, 문단별 판단 ID 검증, 관리자 엔진 제어·검사, 모드별 캐시 분리.

기존 모듈은 삭제하지 않았다. `output/interpretation-rebuild-backup/`에 변경 전 계산·해석·문체 파일과 해시를 보관한다. 이 백업은 로컬 소스 백업이며 운영 DB나 R2 바이너리 백업을 의미하지 않는다. 이번 변경은 영구 DB·자료·미디어를 초기화하거나 삭제하지 않는다. 새 테이블·파괴적 마이그레이션은 없다.

## 새 파이프라인

1. **계산 정규화**: 기존 계산만 옮긴다. 계산 방식·시간대·시간 보정·야자시·대운 방향·학파·지원 한계를 전달한다. 명반의 12궁·별·밝기·사화·비화·삼방사정·대한/유년을 별도 필드로 옮긴다. 시간 미상은 명반을 만들지 않는다.
2. **구조 관찰**: 높은 식상/낮은 재성, 높은 재성/신약 모델, 관성·식상 공존, 높은 인성/낮은 식상, 무근, 억부·조후 차이, 합충 관계. 관찰은 고전 규칙이나 실제 성향의 확정이 아니다. 비중 기준은 기존 앱의 28/12 구간이다.
3. **명리학 판단**: 게시·검수된 지식, 구체적인 충족 조건, 실제 자료 청크·인용문, 해석 원리를 모두 요구한다. 일반 규칙·없는 자료·조작 인용·비활성 자료·예외 보정·계산과 모순되는 판단은 제외한다. 위치별 십성과 구조 관찰도 조건으로 사용할 수 있다.
4. **자미두수 판단**: `system:ziwei` 태그와 `ziweiConditions`를 별도 평가한다. 명리학 사실·템플릿·보정·제외 조건을 가져오지 않는다. 기존 명리학 검색도 이 태그를 배제한다. 명반만 있고 검수된 자미두수 자료가 없다면 근거 부족이다.
5. **통합**: `claim_id`, 주제, 판단, 조건별 실제 값, 전통 규칙, DB 자료 ID/인용 위치, 지식 버전, 반대 판단, 예외, 학파, 불확실성, 현실 점검·실천을 기록한다. 같은 주제의 반대 규칙을 보존한다. 체계 간 비교는 일치/다른 관점/충돌 관점/한쪽만 도출로 나눈다. 반대 stance는 검토 신호이며 사실적 모순의 완전한 증명이 아니다.
6. **작성**: 결정론적 카드/전문을 만들거나, 검증된 판단을 기존 OpenAI/Anthropic 작성 API에 전달한다. 이름과 원본 생년월일은 제외한다. 외부 전달은 이 채팅에서 사용자의 명시적 승인을 받았다. 기존 문체 편집 지시는 표현에만 사용한다.
7. **검증**: 계산 정합성·금지 표현·없는 명칭/숫자·문단 누락·중복·판단 ID·자료 참조를 검사한다. 관리자 카드 미리보기는 각 카드에 허용한 판단 ID 밖의 인용도 거부한다. 부족한 근거는 422로 반환하며 신규 모드에서는 해당 본문의 기존 초안을 검증된 새 풀이처럼 표시하지 않는다.

AI의 자유 문장 전체가 판단의 논리적 함의 안에 있는지는 이 검사만으로 증명하지 못한다. 실제 DB를 사용한 전문가 검수와 실패 사례 평가가 필요하다. 원문 인용 확인도 해당 전통 규칙의 학술적 정확성을 증명하는 것은 아니다.

## 코드와 저장 계약

- `functions/_interpretation-engine.js`: 정규화, 관찰, 독립 판단, 비교, 카드/전문, 검증.
- `functions/_interpretation-store.js`: 설정 및 실제 자료 청크 조회.
- `functions/api/interpretation.js`: 인증된 관리자 분석·규칙 기반 리포트·선택적 AI 카드 미리보기. 미리보기는 40문단 단위로 처리하며 자료 버전이 바뀌면 결과를 적용하지 않는다.
- `functions/api/interpretation-settings.js`: 설정 조회/저장, 기대 버전 검사, 변경 이력.
- `functions/api/movingtoon-reading.js`: 기능 플래그, 생성 전 판단 확정, 사후 검증, 모드·판단·설정별 캐시.
- `report/admin/v2-ik.js`: 엔진 설정, 자미두수 조건 편집, 독립 판단/출처/교차 분석/생성 비용 표시. 기존 지식 편집·이력·비공개 전환 기능을 재사용한다.
- `report/v2/full-reading.js`, `report/v2/pdf.js`: 채택한 동일 본문과 판단 근거를 리포트 객체에 보관해 공유한다.
- `functions/_style.js`: 새 기본값은 직설형 심층 감정. 이미 저장된 관리자 문체 설정을 강제로 덮어쓰지 않는다.

추가 키는 `ik:engine:settings`, `ik:engine:history`다. 기존 `ik:` 라우팅을 이용하므로 Supabase를 사용하는 환경에서도 같은 어댑터로 저장된다. 자료/프로필/결제/미디어 키는 변경하지 않는다. KV의 기대 버전 검사는 트랜잭션 수준의 동시 쓰기 보장을 제공하지 않는다. 여러 관리자가 동시에 엔진 설정을 저장할 환경이라면 조건부 갱신 저장소를 추가해야 한다.

## 검증 및 운영 전환

챕터 책임·후킹 확장 후 미설정 환경의 기본 모드는 `grounded`다. 이미 저장된 명시적 `legacy`/`shadow` 설정은 유지한다. 환경변수 `INTERPRETATION_ENGINE_MODE`가 있으면 관리자 저장값보다 우선한다.

1. 운영 백업 메뉴로 Supabase/KV 스냅샷을 확보하고 R2 원본 보존·복구 절차를 확인한다. 이번 로컬 작업에서는 운영 스냅샷을 취득하지 않았다.
2. 관리자 → AI 작성 설정 → 신규 해석 엔진에서 **비교 검증**(`shadow`)을 선택한다. 기존 생성 경로를 유지하면서 신규 판단을 반환한다.
3. 관리자 풀이 테스트에서 실제 자료·검수 규칙의 근거 누락, 규칙별 조건, 반대 판단, 자미두수 커버리지를 확인한다. AI 작성 체크 시 신규 엔진 카드 미리보기도 작성한다. 비용 단가를 모르면 비용은 미확인으로 표시한다.
4. `node tests/interpretation-quality.js <백업.json> <평가.json>`으로 48개 출생 조건의 실제 자료 커버리지·문장 반복·판단 차이를 점검한다. 출생시간 미상·야자시 선택·절기 주변 조건을 포함한다. 실제 자료가 없으면 근거 부족으로 평가한다.
5. 별도 환경에서 실제 AI·사용자 화면·PDF 레이아웃과 17개 요구 주제의 깊이를 검수한다.
6. 검증 후 **근거 기반 신규 엔진**(`grounded`)으로 전환한다. 출처 없이 기존 초안만으로 새 해석을 만들지 않는다. 기본값을 자동으로 운영 전환하지 않았다.
7. 문제 시 **기존 엔진**(`legacy`)으로 되돌리거나 같은 환경변수를 `legacy`로 설정한다. 저장된 기존 자료/규칙/캐시/계산은 유지되어 있다. 기존 코드는 운영 안정성 확인 전 삭제하지 않는다.

모델·출력 토큰·판단 수·요청 비용 한도·규칙 비활성화를 설정할 수 있다. 비용은 관리자가 입력한 USD 단가와 제공된 실제 토큰 사용량으로 추정하며, 반환 비용은 채택된 공급자 호출에 대한 값이다. 실패한 공급자 호출의 전체 청구 비용을 완전히 집계하지 않는다. 요청 제한 역시 기존 KV 카운터이므로 엄격한 동시 요청 일일 예산 보장을 의미하지 않는다. 공급자별 추론 설정은 아직 추가하지 않았다.

## 확인된 테스트와 남은 완료 조건

통과: 계산 기준선 120개, 신규 엔진 40개 명식/출처 조작·차단/독립 조건/반대 판단/참조/인증/캐시/비용 차단/관리자 AI 미리보기/기존 엔진 롤백, 기존 무빙툰·풀이 지식·문체·관리자 편집·AI 사용량·화면/PDF 데이터 회귀. 긴 본문의 마지막 문장과 인용문이 PDF에 남는 것도 검사했다.

로컬 브라우저: 신규 엔진 설정 표시, 비교 모드 저장, 기존 엔진 롤백 저장, 풀이 테스트의 신규 판단 표시를 실제 화면에서 확인했고 브라우저 콘솔 오류는 없었다. 별도 엔진 설정의 저장 전 변경 표시가 기존 설정의 변경 표시와 섞이는 문제를 수정했다. 이 확인은 운영 DB를 연결하지 않은 메모리 저장소 환경이다. 빈 자료 입력의 평가 도구 실행은 48개 사례/시간 미상 5개/억부·조후 차이 7개/근거 있는 해석 0개로, 자료 없이 내용을 채우지 않음을 확인했다.

신규 테스트 규칙은 **검사 전용 가상 자료**다. 계산 회귀와 배선 검증을 전통 규칙 정확도나 미래 예측 정확도로 보고하지 않는다. 40개 계산 결과의 차이는 실제 DB로 40개 심층 감정서를 검수했다는 뜻이 아니다.

아직 충족하지 않은 최종 완료 조건:

- 운영 DB/R2 백업·복구 확인 및 실제 연결 환경 감사.
- 실제 업로드 자료와 검수된 자미두수 규칙의 충분한 커버리지 확인.
- 고전 월령 격국·일간별 조후표 등 기존 엔진 미지원 계산의 전문 검수/확장.
- 17개 주제별 실제 심층 풀이, 8개 구성 요소와 필요한 분량, 현실 점검 질문의 충분성 검수.
- 시간 경계 및 두 체계의 의미적 충돌에 대한 독립 기준 정답 검수.
- AI 의미적 근거 이탈·전체 문장 반복·부정적 해석 확대 평가, 실서비스 비용 집계 강화.
- 실제 자료를 연결한 관리자 화면·무빙툰·PDF 레이아웃 검증과 별도 환경 운영 시험.

따라서 전면 재구축 완료나 운영 배포 완료로 판정하지 않는다. 구현된 새 파이프라인을 실제 자료와 검증 환경에 연결해 위 항목을 이어서 확인해야 한다.
