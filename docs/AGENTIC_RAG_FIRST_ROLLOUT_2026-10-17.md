# Agentic RAG 1차 운영 적용 승인안

현재 상태: 배포 준비 및 격리 검증 완료. 운영 SQL 적용과 사이트 배포는 아직 실행하지 않았다.

## 이번에 승인받을 범위

- 대상: Cloudflare Pages `mantramanse`, Supabase `devkslhggrkqtianjamj`.
- SQL: CAS 함수 추가와 `ik:agentic:runtime` 신규 상태 1개 생성. 기존 원본 159개 행의 ID·내용·출처·승인·게시·연결은 수정하지 않는다.
- 사이트: `output/rag-production-proposal-bb496616/site`의 161개 파일. 전체 사이트 정적 파일과 70개 경로를 포함한 Functions 묶음이며, 변경된 RAG 애플리케이션 소스는 16개다. 해시는 같은 폴더 상위 `SITE_MANIFEST.json`에 기록했다.
- 연구 OFF, 자동 게시 OFF, 기존 지식만 사용 ON. 일·월·작업 예산 모두 0, 모델과 허용 출처 목록 비움.
- 예약 Worker 배포, Cron 등록, 외부 API 키 업로드, 연구 활성화는 이번 범위에 포함하지 않는다.

이 설정에서는 신규 자동 연구 호출 비용이 발생하지 않는다. 기존 서비스 트래픽의 통상 요금까지 0이라고 보장하는 의미는 아니다.

## 확인한 결과

- 승인된 실제 RAG 백업 159개 행을 PostgreSQL 17 로컬 환경에 복원했다. 초기화 SQL 적용 후 원본 해시가 일치했고, 재실행 시 기존 연구 상태를 덮어쓰지 않고 중단했다.
- 실제 Brave 검색·원문 수집·OpenAI 연구 결과를 로컬 DB에서 검증·자동 게시·개별 롤백했다. 여러 시도에 걸친 단계별 검증이며, 마지막 수정 후 검색부터 전체 과정을 한 번에 재실행한 것은 아니다.
- 별도 Supabase 임시 브랜치에서 실제 HTTP RPC, 동시 갱신과 오래된 상태 거부, 권한 제한을 확인했다. 이 브랜치는 삭제했다. 전체 연구 실행과 호스팅 RPC 검사는 각각 수행했다.
- Pages Functions 빌드 성공. 배포 후보를 로컬 Wrangler로 실행하여 공개 화면 200, 미인증 관리자 API 401, 인증 후 대시보드 200과 연구·게시 OFF/예산 0을 확인했다. 이 실행에는 실제 API 키와 운영 DB 연결이 없다.
- 기존 실제 검증 API 비용의 보수적 상한은 US$0.0495256이다. 임시 브랜치 사용은 기존 승인 범위 내에서 종료했으며, 실제 청구서 금액은 확인하지 않았다. 이번 준비 과정의 유료 API 호출과 운영 쓰기는 0회다.

## 승인 후 적용 순서

1. 운영 배포 ID·바인딩·런타임 호환 설정을 다시 읽고 기록한다. 로컬 검증 설정은 compatibility date `2026-10-17`, `nodejs_compat`이다. 운영 설정과 다르면 영향 검토 없이 덮어쓰지 않는다.
2. 운영 RAG 원본 해시가 `b032d9871790dea1ccca4f8e91f30343`인지 확인한다. 원본이나 배포 상태가 바뀌었으면 중단하고 백업·검증·적용안을 갱신한다. 기존 백업은 Git과 배포에서 계속 제외한다.
3. `01-bootstrap-safe.sql`을 트랜잭션으로 적용한다. 잠금 대기 2초, 실행 제한 10초를 사용하며, 원본 해시 불일치 또는 기존 연구 상태 존재 시 전체 적용을 취소한다. 기존 CAS 함수가 이미 있다면 먼저 정의와 권한을 비교하고 차이가 있으면 중단한다.
4. 원본 해시와 OFF 설정을 재확인한 뒤, 기록한 동일 배포 후보를 사이트에 배포한다. 기존 DB/KV/R2 연결과 비밀 환경 변수는 유지한다.
5. 관리자 인증·대시보드·기존 공개 지식 응답을 읽기 전용으로 확인한다. 원본 승인·게시 수와 해시를 다시 비교한다. 연구 실행이나 자동 게시 테스트를 운영 데이터에 수행하지 않는다.

## 문제가 생겼을 때

- SQL 오류는 트랜잭션을 취소한다. 원본을 백업으로 일괄 덮어쓰지 않는다.
- 사이트 오류는 적용 직전에 기록한 이전 Pages 배포로 되돌린다. 이전 확인 ID는 `af43e068-9557-4614-9136-ab585f94f406`이며 적용 직전 현재 ID를 다시 확인해야 한다.
- 새 CAS 함수와 OFF 상태·감사 기록은 보존한다. 원본 삭제나 전체 DB 복원을 복구 수단으로 사용하지 않는다.
- 향후 연구 활성화에는 모델·허용 출처·예산과 일일 실행 시각에 대한 별도 결정이 필요하다. 기존 결론을 바꾸는 후보는 관리자 승인 전 게시하지 않는 정책을 유지한다.

운영 배포를 별도로 승인받으라는 사용자 지시에 따라 이 문서는 적용안이며 배포 완료 보고가 아니다.
