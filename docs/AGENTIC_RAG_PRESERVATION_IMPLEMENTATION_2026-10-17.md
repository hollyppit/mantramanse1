# Agentic RAG 보존 확장 — 1단계 구현 및 후속 계획

후속 실행 기능 구현: [AGENTIC_RAG_RUNTIME_2026-10-17.md](AGENTIC_RAG_RUNTIME_2026-10-17.md). 아래 미완료 목록은 1단계 당시 기록이며, 현재 구현 상태는 후속 문서를 기준으로 한다.

## 현재 완료 범위

이 문서는 전체 Agentic RAG 구축 완료 보고서가 아니다. 기존 데이터 불변 진단과 연구 준비 계층을 구현한 1단계 기록이다. 운영 배포·운영 DB 변경·운영 전체 진단은 실행하지 않았다.

## 1. 기존 시스템 분석

- `functions/_store.js`: Cloudflare KV 인터페이스로 Supabase `public.kv`를 사용. `ik:`·`src:`는 기존 라우팅을 공유하고, Supabase에 없으면 기존 KV로 읽기 폴백.
- `ik:d:<DOMAIN>`: 분야별 지식 배열. ID, version, reviewed/reviewedAt, status, subDomain, conditions, evidence를 보존해야 한다.
- `src:idx`: 자료 메타데이터·승인 후보 집계. `src:chunks:<id>`는 원문 청크, `src:cand:<id>`는 추출 후보. R2 `src/<id>`는 원본 파일.
- `functions/api/src.js`: 이미 추출·검증·중복/충돌 비교·관리자 승인·근거 추가/병합 기능을 제공. 이를 재개발하거나 대체하지 않았다.
- `functions/_ik.js`: 승인·게시 조건과 명리 조건을 필터링하는 기존 검색. 벡터 DB 추가 없이 구조화 검색을 사용.
- `functions/_interpretation-store.js`: 원문 인덱스 공급. `functions/_interpretation-engine.js`와 실제 서비스 API가 지식 ID·버전·출처를 추적.
- 관리자 인증은 기존 `isAdmin`을 재사용. 기존 AI 호출은 `_ikstore.llm`; 해당 반환값만으로 실제 사용 비용을 확정할 수 없으므로 이번 단계에서 유료 연구를 실행하지 않는다.
- 지식 이력 `ik:hist:*`는 기존 구현이 최근 20개로 자른다. 기존 편집 경로 전체의 영구 이력 보존은 아직 해결되지 않았다.
- 기존 도메인 배열은 get/put 방식이다. 동시 편집과 자동 연구를 안전하게 결합하려면 원자적 조건부 쓰기/트랜잭션을 먼저 구현해야 한다. KV read-then-write를 분산 잠금으로 취급하면 안 된다.

## 2. 신규 모듈

- `_agentic-rag.js`: 원문 대조를 포함한 전체 지식 진단, 우선순위 계획, 30일 재연구 대기, 변경 후보 보관·철회.
- `/api/agentic-rag`: 관리자 전용 GET dashboard, POST audit/plan/propose/withdraw. 미지원 메서드 차단, 요청 크기 제한, 버전 불일치 거절.
- `v2-agentic-rag.js`: 기존 AI 풀이 영역의 AI 자동 연구 화면. 집계·개별 지식·진단 필터·연구 과제 준비.

## 3. DB 변경과 보존 정책

DDL 변경 없음. 기존 저장소에 `ik:agentic:` 키만 추가한다.

| 키 | 내용 |
| --- | --- |
| `audit:<uuid>` | 변경하지 않는 진단 스냅샷, 원본 인벤토리 해시 |
| `latest` | 마지막으로 완성된 진단 ID |
| `task:<fingerprint>` | 지식 ID·기존 버전·진단 항목별 연구 과제 |
| `change:<uuid>` | 기존 지식 전체 스냅샷, 신규 제안, 출처, 이유, 실행 주체, 시각 |
| `event:<uuid>` | 변경 후보 철회 이벤트, 이전 상태와 다음 상태 |
| `withdrawn:<changeId>` | 철회 이벤트 연결 |

모든 키에 `ik:agentic:`를 붙인다. 원본 지식, 자료, 챕터, 승인·게시·기존 이력 키에는 쓰지 않는다. 기존 승인은 그대로 유지되며 AI 검증은 `not_validated`라는 독립 상태이다. 인용문 일치도 AI의 전체 검증 완료로 표시하지 않는다.

## 4. 진단의 의미

- 근거 부족: 기존 자료 메타데이터와 해당 chunk ID의 원문에서 연결 인용문을 확인하지 못함. 자료가 없거나 인용이 없을 때도 포함.
- 출처 불명확: 자료 연결 누락/끊김. 저작자·저작권 및 외부 URL 신뢰성 판정은 아직 미구현.
- 적용 조건 부족: 지원되는 명리 조건 및 자미 조건이 없음. 일반 개념에도 표시될 수 있어 관리자 검토 필요.
- 충돌 후보: 동일 분야·세부 구성·조건·예외·학파에서 반대 stance. 의미적 모순의 확정 판정이 아님.
- 중복 후보: 조건·예외·보정·학파가 동일하고 핵심 근거/해석이 정규화 후 동일. 의미 유사도 중복 검사는 후속 과제.
- 챕터 미연결: 기존 풀이 구성에서 subDomain 연결이 없거나 유효하지 않음. 모든 실제 챕터 계약의 연결을 보증하는 검사는 아님.
- 실제 풀이 미사용: 완전한 관측 기간·지식별 사용 횟수가 있을 때만 0회를 미사용으로 판정. 현재 운영 수집 미연결이므로 서비스 지식은 사용 이력 미측정으로 표시.

진단 중 저장소 읽기가 실패하면 완료 스냅샷을 만들지 않는다. 진단 결과는 삭제·비공개·승인 취소를 일으키지 않는다. 보안·법률 위험의 자동 탐지는 아직 미구현이며 구현됐다고 표시하지 않는다.

## 5. 외부 검색 API와 자동 승인

외부 검색 API는 미연결. 과제 상태는 `blocked_search_not_configured`이며 출처·검색 결과·연구 완료·비용을 꾸며 내지 않는다. 실제 유료 API 호출과 비용은 0이다. 과제당 5회 검색·10개 문서·2회 재시도 등 실행 제한 및 월간/일간 비용 예약은 후속 실행기에서 구현해야 한다.

현재 변경 후보는 관리자 검토 필요 상태로만 저장한다. 후보 저장은 원본 변경/게시가 아니다. 계산·핵심 규칙·적용 조건 확대·예외·결론 변경을 자동으로 게시하는 경로는 없다. 저위험 자동 승인·자동 게시 기능 자체는 아직 구현하지 않았다.

## 6. 관리자 UI

기존 메뉴를 보존하고 AI 풀이 영역에 AI 자동 연구를 추가했다. 현재 기능과 미연결 상태를 명시한다. 진단 목록은 관리자에게만 제공하며 제목 등 데이터는 HTML escape한다. 데스크톱과 390px 모바일에서 확인했으며 표는 자체 가로 스크롤을 사용한다. 진단 시각은 한국 시간으로 표시한다.

## 7. 검증

- `node tests/agentic-rag-sim.cjs`: 관리자 인증, 메서드 제한, 실제 저장 원문 인용 대조, 조건별 충돌/중복 후보, 반복 과제 재사용, 버전 검사, 후보 이력·철회 보존, 기존 저장값 바이트 불변.
- `node tests/agentic-rag-browser.cjs`: 실제 Edge headless, 빈 화면, 진단 실행, 필터, 미연결 과제 표시, HTML escape, 모바일 넘침, 인증 실패 시 결과 제거, 원본 불변.
- 기존 `admin-navigation-sim`, `admin-login-sim`, `research-review-api-sim`, `ik-sim`, `src-sim`, `interpretation-engine-sim` 통과.
- PDF·영상 전체 회귀, 실제 운영 자료 수/승인 수와 관리자 숫자 일치 검증, 운영 DB 전체 건강 진단은 미실행. 테스트는 메모리 저장소와 로컬 UI를 사용했다.

## 8. 비용·운영 제한

유료 AI·외부 검색 미호출. 실제 호스팅 읽기/쓰기·저장 비용은 환경 요금에 따르며 아직 별도 계측하지 않는다. 현재 전체 진단은 동기 실행하므로 대용량 DB에 대한 Pages 실행 제한 검증 및 분할 재개가 필요하다. 전체 자료 메타데이터와 전체 IK 지식은 읽지만 연결되지 않은 원문·원본 R2 파일·추출 후보 전체의 건강 검사는 아직 포함하지 않는다.

## 9. 철회·롤백

POST `?a=withdraw` `{ "id": "후보 UUID" }`는 해당 지식의 후보를 철회하고 이전 후보/이벤트는 남긴다. 원본은 적용 전후 모두 같으므로 이것은 게시된 보강의 롤백 기능이 아니다. 운영 보강·게시를 되돌리는 기능, 검색 인덱스 버전 복원 및 배포 묶음 롤백은 미구현이다.

이 단계의 기능 철회는 신규 관리자 메뉴·스크립트·API를 제거하면 된다. `ik:agentic:*` 기록을 삭제할 필요는 없다. 원본 복원이나 기존 지식 재승인은 필요하지 않다.

## 10. 후속 구현 순서 / 미완료 사항

1. 기존 편집·자료 병합 경로를 포함해 원자적 버전 검사와 영구 변경 이력을 적용. 운영 데이터를 복제한 검증 환경에서 ID/연결 보존 및 복구 시험.
2. 관리자 허용 출처·권리 등록, 실제 검색 제공자, SSRF 및 외부 문서 명령 차단, URL·원문·인용·저작권 검증. 실제 비용·토큰 집계와 비용 선예약/정산 구현.
3. 기존 후보 추출/비교 경로를 재사용하는 연구 실행기. 같은 해석이면 기존 ID에 근거 연결 후보를 만들고, 조건·예외·결론 변경은 별도 버전. 풀이 방법과 설명 지식의 분류/관계 그래프 구현.
4. 고정 원국과 원문 대조 기반 회귀 검증, 위험도 및 자동 승인/게시 별도 상태. 검증 환경에서 저위험 보강과 신규 지식의 기존 검색·검수 경로 통합.
5. 원자적 실행 잠금, 체크포인트, 실패 재시도, 일일/월간 예산 차단, 중단·재개. 매일 KST 실행 시간을 바꿀 수 있는 Worker 스케줄러와 설정 UI. 실제 운영 배포는 별도 승인 필요.
6. 실제 지식 사용 추적을 기존 풀이 생성 지점에 연결. 신규 자동 게시 지식과 기존 지식의 동일 조건 필터·정합성 검수·출처 추적 확인.
7. 게시 버전별 개별/묶음 롤백, 검색 캐시/인덱스 일관성, 장애 시 기존 승인 지식만 사용하는 모드. 출처 비교·승인·철회·비용·일일 보고서 UI.
8. 실제 운영 전체 진단 및 관리자 표시 수 대조, 기존 관리자/무빙툰/PDF 전체 회귀 후 배포 승인 요청.

첨부 지시서의 '실제 운영 배포는 별도 승인 후 진행' 정책을 유지한다. 현재 배포 승인을 요청하는 단계는 아니다. 위 후속 구현과 검증이 남아 있다.
