# 풀이 대기·자동 이탈·문체 및 호출 비용 수정 (2026-10-18)

## 원인과 관측 범위
- 남성 안내자의 고정 worldHook 문구에 반말이 남아 있었고, 생성 서버의 공통 존댓말 문체와 섞여 보였다.
- 신규 합성 입력 1995-03-14 09:20 남성으로 실제 운영 API에서 c02/deep_car 두 장을 최초 생성했다. 모두 200, cached=false, 7문단이었다. 약 43초/26초가 걸렸다. 이 두 요청에서 토큰 상한 초과는 발생하지 않았다.
- 본문이 준비되기 전에 읽기 타이머가 진행됐고, 문서 끝에서 주제 목록으로 이동했다. 비동기 주제 설정 응답도 읽기 중 문서를 다시 만들 수 있었다. 주제 제목을 적용하며 만든 복사본과 생성 작업의 원래 챕터 객체가 다른 경로도 있었다.
- FullReading은 진입 시 전체 챕터를 백그라운드 생성했다. 사용자 비용 지적 후 전체 운영 검증 작업을 즉시 중단했다. 전체 챕터 운영 검증이 이번 수정에서 완료됐다고 주장하지 않는다.
- 실제 신규 응답의 generation 기록: deep_car 입력 35,142 / 출력 1,062; c02 입력 36,302 / 출력 1,192 토큰. 범위는 accepted-writer-repair-and-review-calls이며 거절된 시도 전체나 청구 총액은 아니다. estimatedCost는 단가 미설정으로 null이다.

## 변경
- 남녀 안내자의 도입을 모두 존댓말로 통일했다.
- 미완성 장은 자동 진행을 멈춘다. 준비 대기를 compact 카드로 표시하고 실제 실패에는 원인 코드와 재시도 버튼을 표시한다.
- 늦은 주제 설정은 읽기 중 문서를 다시 열지 않고 홈 복귀 때 적용한다. 생성된 본문과 상태를 현재 챕터 객체에도 반영한다. 원래 supplementary의 정적 제목을 대기 문구로 바꾸지 않는다.
- 주제의 끝에서 자동으로 목록으로 이동하지 않는다. 미완성 장은 완료 처리하지 않는다. 신규 탐험 저장본의 자동 넘김 기본값은 꺼짐이다(명시적으로 저장된 선호는 유지).
- 전체 자동 생성 제거: 진입 시 AI 요청 0, 선택한 장만 생성한다. 세션당 동시 생성 1건, 빠른 이동은 최신 선택만 대기한다. 이미 완료한 장을 다시 방문해도 재생성하지 않는다. 실패 재시도는 사용자 버튼으로 수행한다.
- 동일한 존댓말인 남녀 안내자는 풀이 API 캐시를 공유한다. 이전 본문은 같은 주제의 최근 8개 생활 문단만 전달하고 근거 문단은 반복 전송하지 않는다. 출력 상한·모델·독립 의미 검수·요청 횟수 상한은 변경하지 않는다.

## 검증
- regression-verification.json: 실제 최초 생성 두 응답을 지연 재생한 결정적 UI 회귀 검사(새 AI 호출 없음). PC/모바일 대기 중 자동 멈춤, 읽지 않은 장 호출 없음, 본문 갱신, 이전 장 재방문 본문 유지, 존댓말, 문서 끝 유지, JS 오류 없음.
- reading-on-demand/failure/priority/topic-priority, reader-sim, explore-sim 통과.
- production-on-demand-verification.json: 운영 실제 응답, 모의 성공 없음. 진입 요청 0, 선택 두 장만 요청, 모두 실제 캐시된 7문단, 재방문 추가 요청 0을 검증한다. 추가 신규 생성을 피하여 비용을 줄인다.
- 배포는 직전 전체 운영 파일을 보존하고 이번 클라이언트 7개 파일만 교체했다. 서버 Worker/API와 관리자 설정은 유지했다. deployment.json 참조.
