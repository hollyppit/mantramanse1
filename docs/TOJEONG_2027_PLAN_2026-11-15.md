# 2027 정미년 토정비결 신년운세 — 구현 계획 (2026-11-15, 승인 대기)

운명의 타임라인과 따로 파는 독립 유료 상품. 이 문서는 구현 전 계획이며 코드는 아직 바꾸지 않았다.

## 1. 기존 구조 분석 — 재사용할 것과 새로 만들 것

새로 만들 것: 토정 계산 엔진, 144괘 원문·현대어 DB, 조건 조합 엔진, 신년운세 전용 화면(`/report/newyear/`), 관리자 탭, 서버 API 2개, 테스트.

## 2. 토정비결 계산법 조사 결과

### 2-1. 공통으로 확인된 골격 (한국민족문화대백과사전 「토정비결」, 이을호 집필)
- 상괘 = (나이 + 당년 태세수) ÷ 8 의 나머지
- 중괘 = (당년 생월 날수: 큰달 30·작은달 29 + 생월 월건수) ÷ 6 의 나머지
- 하괘 = (생일수: 초하루 1 … 그믐 30 + 생일 일진수) ÷ 3 의 나머지
- 생시는 쓰지 않음. 8×6×3 = 144괘, 괘상·괘사·월별 길흉 합쳐 6,480구.
- 백과에 없는 것: 나이 기준, 태세수·월건수·일진수 값표, 나머지 0 처리.

### 2-2. 전승본·현대 해설 간 차이 (확인한 범위)
| 쟁점 | 다수 해설 | 다른 해설 |
|---|---|---|
| 나이 | 세는 나이(당년 − 출생연도 + 1) | — |
| 나머지 0 | 제수 그대로(상 8·중 6·하 3) | 상 0→3 (산식 자체가 다른 간이식) |
| 날수·월건·일진 | **당년** 음력 생월·생일 기준 | 간이식은 날수·간지 없이 생월·생일만 |
| 하괘 생시 | 사용 안 함 | 일부 계산기는 '출생 시점수' 반영 |
| 수 값 | 선천수(甲己子午 9, 乙庚丑未 8, 丙辛寅申 7, 丁壬卯酉 6, 戊癸辰戌 5, 巳亥 4)로 간·지 합산 — 丙午 = 16 사례와 일치 | 한 상용 계산기 예시의 일진수(辛亥 16, 乙酉 18)는 선천수(11, 14)와 다름 → 미확인 표 |
| 월건 | 음력 생월 번호로 오호둔(寅월 시작) | 그 날짜의 절기 월주를 쓰는 듯한 예시 있음(癸巳 9 대신 甲午 18) |
| 윤달생·당년 30일 없음 | 원전 규칙 미확인 | 한 계산기는 계산 중단·날짜 바꿔 비교 안내 |

> **정정(2026-11-15):** 저본 판본(규장각 奎古 1077)의 「數理法」 표로 수 값이 확정됐다. 태세수·일진수는 선천수가 아니라 별도 표이고, 월건은 음력 월 번호 오호둔이다. 자세한 내용은 `docs/TOJEONG_SOURCE_2026-11-15.md`.

### 2-3. 채택안 (승인 필요, 모두 설정값으로 둬서 바꿀 수 있게)
- `tojeong-classic-v1`: 세는 나이, 선천수 합산, 당년 음력 기준, 월건은 음력 월 번호 오호둔, 나머지 0 → 제수, 생시 미사용.
- 윤달생: 같은 번호의 평달로 계산(당년에 그 윤달이 있으면 윤달 날수 사용 여부는 대조 후 확정). 화면에 '윤달생 처리 기준' 표시.
- 당년 생월이 작은달인데 30일생: 그믐(29일)의 일진으로 계산하고 생일수는 30 유지 — **원전 확인 전 임시안**, 화면·문서에 명시.
- 나이·대상연도 경계: 토정비결은 음력 설 기준 한 해(2027 정미년 = 음력 2027-01-01 ~ 12-말일). 사주 쪽 세운은 입춘(2027-02-04 무렵) 기준. 두 경계가 다르다는 것을 월별 화면에서 분리 표기.
- 출생시간 미입력: 토정 계산엔 영향 없음. 사주 쪽은 기존 엔진의 '시주 모름' 처리 그대로, 시주가 필요한 문장은 빠지거나 '시간 미입력' 문장으로 대체.
- 양력 입력 → 출생 음력 월·일로 환산 후 위 규칙 적용. 1899년 이전은 엔진 범위 밖이라 거절.

### 2-4. 검증 계획
- 대조 자료: 인쇄본 작괘표(명문당·남산당 판 등 '태세수·월건수·일진수표')와 최소 2개 공개 계산기. **인쇄본 표는 웹에서 확인하지 못해 사용자 확보가 필요**(아래 결정 사항 ①).
- 테스트 벡터: 대조 자료 예시를 그대로 넣고, 차이가 나면 어느 쟁점 때문인지 자동 분류(나이·0 처리·월건·일진).
- 경계 사례: 윤달생(1984 윤10월, 2020 윤4월, 2023 윤2월 등), 당년 작은달 30일생, 음력 설 전후·입춘 전후 출생, 12월생, 1900·1950·2010년생, 시간 미입력.

## 3. 144괘 문구 — 출처 원칙
- 전통 괘사(괘상 4자구·총론·월별 구)는 **출처를 확인한 판본의 원문만** 쓴다. 지어내지 않는다.
- 1918년 이후 인쇄본이 주류. 저작권은 판본·편자별로 따로 판단해야 하고, 현대어 번역본(시판 해설서)은 복제하지 않는다.
- 우리 문장은 '만트라 풀이'로 구분: 원문 → 쉬운 현대어 뜻(직접 작성, 관리자 검수) → 사주 보완.
- 원문 확보 전까지: 괘 번호·괘 구성(상중하 수)만 표시하고, 원문 칸은 '검수 중'으로 비노출(주역 모듈과 같은 draft 게이트).

## 4. 풀이 조합 엔진 (AI 실시간 호출 없음)
- 입력 두 갈래를 **따로 계산**: ① 토정(괘 번호, 월별 괘 길흉 표기) ② 사주(원국·통합 용신·2027 丁未 세운의 십성·합충형해·월운 12개·삼재·대운 위치).
- 해석 단계에서만 합침. 둘의 방향(길/흉)이 같으면 '같은 방향', 다르면 **'토정비결은 이렇게, 사주는 이렇게 다르게 봅니다'** 로 나눠 보여 주고 억지로 섞지 않는다.
- 문장 블록 순서 고정: 근거(무엇 때문에) → 기질·상황 → 현실 장면 → 실천 조언. 좋은 운·나쁜 운 각각 대응 문장 필수.
- 조건 축(예): 丁未와 일간의 관계(십성 10) × 원국과 未의 합충형해(축·술·자·묘·해·오 등) × 용신 부합(득/실) × 신강/신약 × 대운 전환 여부 × 토정 괘 길흉. 블록마다 조건 키를 달고, 같은 키 묶음 안에서 사주 해시로 변형 선택(겹침률 검사 도구로 확인).
- 건강·사고·재물: '살필 시기·습관' 표현만, 확정 예언 금지(금지어 검사 테스트).
- 연도 분리 구조: `report/newyear/years/2027/`(문구 팩·월 달력·상징·가격 기본값) + 연도 무관 엔진. 2028은 폴더 하나 추가로 끝나게.

## 7. 상품·결제·관리자
- `_commerce.js`: 상품 종류에 `annual` 추가 → `{ id: 'tj2027', kind: 'annual', worlds: ['tj2027'] }`. 권한 = 회원 × 사주 × `tj2027`. 묶음(전체 열기)에는 포함하지 않음(독립 상품). 재구매 차단·환불(7일·미열람)·메일·영수증·매출 CSV는 기존 그대로 적용.
- 반복 열람: 권한이 있으면 그 연도 본문을 언제든 서버에서 다시 조합(같은 입력 → 같은 결과, 결과 버전 고정을 위해 문구 팩 해시를 권한에 기록).
- 관리자 탭 `토정비결 신년운세`: 연도별 버전(2027 활성, 2028 초안), 가격·판매 여부·공개 범위(무료로 보일 장), 소개 문구, 원문·현대어·조합 블록 검수(승인≠게시, 롤백), 사례 미리보기(사주 여러 개 비교).
- DB: 새 테이블 없이 기존 `commerce_orders`/`commerce_entitlements` 사용(world 칸이 자유 문자열). 콘텐츠·설정은 KV.

### 아직 없어서 임의로 만들지 않고 보고할 기능
- 상품별 **기간 한정 판매**(예: 2028년 1월 이후 2027판 판매 종료) — 현재 상품표에 기간 칸 없음. 수동 '판매 안 함' 전환으로 대체 가능.
- 회원 비로그인 구매 불가(기존 정책 그대로).
- 할인 코드 미구현(메모상 다음 후보).
- KPN 서브몰 심사에 **새 상품 추가 신고 필요 여부** 확인(사용자 몫).
- 약관·상품 안내·환불정책 페이지에 신규 상품 추가(문구는 제가 작성, 게시는 배포 승인 때).
