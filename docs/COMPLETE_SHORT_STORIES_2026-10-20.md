# 주제별 완성 단편 검수·반영 — 2026-10-20

## 작성 범위와 선택 기준

현재 사용자 화면의 7개 주제(종합풀이·재물·커리어·인연·건강안전·전생·개운)에 사주 유형별 5편씩, 총 35편을 연결했습니다. 종합풀이에 통합된 기존 시기 세계 w4의 호환용 5편까지 저장된 원문은 40편·400장면입니다. 원문은 `report/v2/short-story.js`에서 버전을 붙여 관리합니다.

기존에는 주제별 공통 줄거리에 강한·약한 십성군, 강약, 오행에서 고른 문장을 끼웠습니다. 지금은 기존 엔진이 산출한 dominantGroup의 다섯 유형으로 완성된 이야기 한 편을 고릅니다. 동기와 사건을 고른 뒤 약점·강약·방문 횟수로 다른 결말 문장을 다시 섞지 않습니다. 따라서 같은 유형의 독자는 이름을 제외하면 같은 원문을 읽습니다. 모든 사주마다 고유 소설이 생성된다고 표현하지 않습니다.

사주 유형은 창작 소재 선택 기준입니다. 작품 속 성격·직업·관계·사건을 독자의 실제 이력이나 미래로 판정하지 않습니다. 전생의 시대·신분·사건도 허구입니다. 건강안전 이야기는 건강 상태·질병·사고 발생을 예측하지 않습니다.

## 장편 기획 플랜 적용

첨부 기획서는 인과 전개 기준으로 참고했습니다. 문서 안의 실시간 키워드 조사나 대화형 AI 제안 지시는 실행 요청으로 취급하지 않았습니다. 단편 분량에 맞춰 다음처럼 장면을 묶었습니다.

| 장면 | 기획서 기준 | 검수 초점 |
|---|---|---|
| 1 | 프롤로그·결핍 | 주인공이 붙잡는 것과 후반에 돌아올 물건·기록을 도입 |
| 2 | 문제·미끼 | 목표와 다른 사람의 요구가 충돌 |
| 3 | 검증·신념 | 되돌리려면 대가가 생기는 약속이나 선택 |
| 4 | 상승·가짜 승리 | 처음 선택이 맞아 보이는 짧은 성공 |
| 5 | 방심·실패 | 그 선택에서 비롯된 구체적인 손실·갈등 |
| 6 | 혼란 | 익숙한 대응으로 풀 수 없고 자기 오류를 인정해야 하는 순간 |
| 7 | 각성 | 초반의 복선을 다시 읽고 해결의 단서를 발견 |
| 8 | 초긴박·폭발 | 마감·관계·자원 압박 속에서 주인공이 대가를 감수 |
| 9 | 반전·해결 | 복선을 주인공의 행동으로 사용하며 사건을 해결 |
| 10 | 이완·에필로그 | 손실·후속 책임을 없애지 않고 달라진 생활을 보여줌 |

예: 종합풀이 비겁형은 혼자 대표하려는 선택이 작업의 실패를 만들고, 처음 지우려던 연필 선이 동료의 작업 지식임을 알아 공동 작업으로 바꿉니다. 전생 비겁형은 자기만 풀 수 있는 매듭 때문에 위기가 커지고, 그 매듭을 스스로 자르는 대가를 치른 뒤 공동 신호로 수문을 움직입니다. 같은 유형이어도 주제마다 사건과 해결 수단이 다릅니다.

모든 작품을 내부 편집 관점에서 작성·재독했습니다. 반복되던 열쇠 분실→지갑 분실의 연속 위기, 역할과 무관한 성향 문장 삽입, 문법이 깨진 약점 문장을 제거했습니다. 외부 문학 편집자나 명리 전문가의 승인을 받았다고 표시하지 않습니다. 자동 검사는 문학적 완성도의 객관적 보증과 구분합니다.

## 이름과 화면 연결

- 주인공은 사용자 입력 이름입니다. 원문에는 이름 대신 허용된 hero 자리표시자만 넣고, 브라우저에서 이름과 받침 조사를 적용합니다.
- 이름을 입력하지 않은 경우 기존 그/그녀 호칭을 사용합니다. 이름 치환에 정규식 치환 문자열을 사용하지 않아 `$&` 등의 문자가 변형되지 않습니다. 화면 출력에서는 HTML을 이스케이프합니다.
- 기존 84개 중 창작 8편 연작의 주인공 이름도 로컬에서 적용합니다. 입력 이름이 기존 조연 하람과 같으면 조연을 목수로 구분합니다. 서버에 저장된 공통 원문은 사용자 이름으로 덮어쓰지 않습니다.
- 모든 주제에서 텍스트 단편 진입 카드를 제공합니다. 전생도 별도의 고정 서윤 연작 플레이어 대신 유형별 완성 단편을 엽니다.
- 단편을 열기 위해 해당 주제의 풀이를 먼저 불러오지 않습니다. 정적 원문 선택과 이름 적용만 하며 추가 AI·풀이 API 요청은 없습니다. 이미지·영상은 사용하지 않습니다.
- 기본 84개 풀이의 서버 AI 무호출 정책은 그대로입니다. 이번 배포는 정적 파일 세 개만 바꾸고 기존 Worker·서버 설정·DB 원문과 자동 생성 비활성 설정을 유지합니다.
