# 풀이 블록·AI 비용 감사 및 전환 상태 — 2026-10-19

## 범위와 검증 수준

기존 원국 엔진, 승인 RAG, 명리·자미두수 근거 검증, 무빙툰/PDF, 관리자, 전생 생성은 유지한다. 이번 변경은 **전환 기반 구현**이며 요청문 전체가 운영에 적용된 상태가 아니다. 기존 작업 트리에 다수 수정 파일이 있었으며 해당 변경을 되돌리지 않았다.

확인한 것: 로컬 소스, 합성 명조 테스트, mock 제공자 호출, 기존 연구/저장소 테스트. 확인하지 못한 것: 운영 서버 로그·실제 사용량·제공자 청구서·배포된 환경변수·스케줄러 활성 상태. 공개 사용자/관리자 URL은 웹 읽기 도구에서 접근되지 않았다. 배포, 실제 유료 생성, 운영 DB 변경은 실행하지 않았다. 입력 요청문은 14절 비교 테스트의 `C.`에서 끝난다.

## 10개 비용 문제의 코드상 판정

1. **84개 모두 선생성:** 현재 full-reading은 입장 시 0회, 선택한 챕터만 생성한다. 기존 reading-on-demand 테스트로 확인. 운영 배포본은 미확인.
2. **챕터마다 원국 재해석:** 정밀 근거 선택 analyzeChapter 및 소스 검증은 매 요청 실행한다. 원국 계산 엔진 자체를 AI로 다시 계산하지 않는다. 챕터 간 해석 스냅샷 재사용은 추가 과제다.
3. **같은 RAG 반복 전달:** AI 폴백에서는 챕터별 근거를 다시 전달한다. approved 블록 적중 시 제공자 전달 자체를 생략한다. 전체 프롬프트 중복률은 미측정.
4. **같은 원국 반복 생성:** 기존 버전/문체/설정/챕터 기반 캐시가 있다. 캐시 miss·검수 실패·동시 실행은 추가 호출을 만들 수 있다.
5. **AI 반복 재작성:** 문체·후킹 repair와 의미 검수 및 최대 3회 작성 시도가 있다. 이번 변경은 계측하며 이 경로를 전면 제거하지 않는다.
6. **실패 시 전체 재생성:** 전체 리포트보다 해당 챕터를 재시도한다. 일부 repair는 문단만 수정하지만 후속 writer retry는 챕터 전체 JSON을 재작성한다. 부족 블록만 AI 생성하는 경로는 미구현.
7. **동시 중복:** 클라이언트는 단일 in-flight. 서버에는 이번 변경으로 동일 실행 인스턴스의 비개인화 요청 singleflight 추가. 여러 isolate/서버의 분산 중복 방지는 미구현.
8. **매일 전체 재연구:** 기존 연구는 후보 계획·중복/쿨다운·태스크/일/월 예산·검색 횟수·bounded retry·원자 CAS를 갖춘다. 실제 연구량/반복률은 운영 미측정.
9. **읽지 않는 챕터 선생성:** 현재 지연 생성 경로는 읽지 않는 챕터를 호출하지 않는다. 선택 전환 시 대기 중 이전 선택을 버린다.
10. **형식/문체 검사 AI:** JSON·출처·계산·중복·존댓말 등 로컬 검사가 이미 있다. 실패 후 AI 문체 보정도 여전히 존재하며 비용 scope로 분리했다.

## 이번 구현

### 승인 블록 우선 조합

- functions/_reading-blocks.js: 챕터/역할/문체별 후보 선택, 원국에 이미 적용된 claim 전체 SHA-256 서명 검사, 제외 claim·상호 충돌·동일/유사 문장 제외.
- claim 서명은 조건별 계산값, 판단, 예외, 출처, 반대 근거 등을 포함한다. 출처 비활성화·규칙/조건/예외 변경 시 현재 분석과 맞지 않아 재사용되지 않는다.
- 단일 일간 템플릿 매핑을 새로 만들지 않고 기존 복합 조건 엔진의 승인 근거를 사용한다.
- 모든 문단을 조합할 수 있을 때에만 기존 sanitize, validateWritten, inspectWriting, chapterQuality, hook 검사로 재검증한다. episode는 검증된 연속 장면 관리가 추가되기 전까지 기존 생성 경로를 쓴다.
- READING_BLOCK_MODE=prefer에서만 사용한다. 기본은 off. 블록 부족·부적합 시 기존 경로로 폴백하며 짧은 일반론으로 채우지 않는다.
- 블록 응답은 기존 result.paragraphs 계약을 유지하므로 무빙툰/PDF가 같은 데이터를 사용한다. 미디어 선택 로직 변경이나 새 이미지 생성은 없다.
- 블록 조합 결과 전용 영구 캐시는 아직 없다. 기존 AI 캐시는 유지하고 승인 블록은 요청마다 최신 근거/라이브러리를 검증한다.

### 관리자·후보 제작

운영 관리 → AI 비용·풀이 블록. `/api/reading-blocks`는 기존 관리자 Bearer 인증을 사용한다. 챕터별 후보/승인 블록, 역할, 출처 claim, 상태, 버전, JSON 편집, 이전 스냅샷 복구를 제공한다.

가상 명식의 sd/chapter로만 후보 사전 제작을 요청한다. 이름·생년월일·realityContext는 거부한다. 기존 grounded 작성/검수 경로를 사용하고 후보 상태로만 저장한다. 기존 AI 설정에 입력/출력 단가와 요청당 비용 상한이 없으면 실행하지 않는다. 승인 시 source/semantic/privacy/scenarios 검토가 필요하다. 관리자 후보 제작 요청이므로 AI 비용이 발생한다.

챕터 라이브러리 500개, 히스토리 20개로 제한한다. 저장 시 기존 블록 version을 증가시키고 수정일을 갱신한다. 전체 라이브러리 revision 충돌 검사는 있지만 KV에서 두 관리자 동시 쓰기의 원자성을 보장하지 않는다. 한 명의 편집자로 운영하거나 다음 단계에서 원자 저장으로 전환해야 한다.

### 개인정보·원장

실제 고민/현실 조건이 있는 요청은 공용 블록·공용 결과 캐시·공용 singleflight에서 제외한다. 현재 API에는 인증된 사용자 ID가 없어 사용자 전용 영구 캐시를 새로 만들지 않았다. 별도 사용자 인증/소유권 체계가 필요하다.

원장에는 본문·프롬프트·명식·이름·출생정보·고민·키·제공자 에러 메시지를 저장하지 않는다. 비용 원장은 ai:cost:, 결과 집계는 ai:outcome:에 별도 저장하고 93일 TTL을 설정한다. RLS가 적용된 기존 서버 전용 kv 어댑터를 재사용하며 브라우저에 service key를 노출하지 않는다. 원장 저장 실패는 고정 경고만 남기고 풀이를 중단하지 않는다. 따라서 원장이 유실 없이 완전하다는 보장은 없고 제공자 청구서와 대조해야 한다.

관리자 기간 조회는 UTC 기준 일/월이며 페이지 완주 여부를 표시한다. 정확한 KST 일/월 집계, 사용자당 비용, 조건별 활용률, 평균 재시도 비용, 품질 비교 점수는 아직 완성되지 않았다. 개인 식별 없이 현재 기록으로 제공할 수 있는 것은 호출·실패·캐시·블록 생략 건수와 단계/모델/챕터별 원시 비용 이벤트다.

## 운영 적용 순서

1. config/reading-blocks.example.json을 참고해 AI_COST_LOG_ON=1 및 실제 모델별 AI_PRICING_JSON 단가를 배포 환경에 설정한다. null 단가는 미계측이다. 모델/캐시 읽기/캐시 쓰기 단가를 제공자 계약과 맞춘다.
2. 기존 관리자 AI·서비스 설정에 사전 제작용 입력/출력 단가와 요청당 비용 상한을 설정한다. 저렴한 모델 교체나 분량 축소로 절감하지 않는다.
3. 대표 합성 명식·주요 챕터의 승인 근거로 후보를 제작한다. 최고/최악 시나리오·예외·행동 사례는 사람/전문 검수로 게시 여부를 결정한다. 일반화하지 못한 개인 문장은 승인하지 않는다.
4. 기존 경로 A와 블록 경로 B를 같은 명식/챕터/문체/근거 버전으로 비교한다. 길이·근거 추적·중복·모순·가독성·구체성·강약점·선택/환경·실천을 평가한다. B는 차트에 따라 근거가 맞지 않아 폴백할 수 있다.
5. 승인된 범위에서 READING_BLOCK_MODE=prefer를 켠다. 문제가 있으면 off로 되돌리면 기존 생성 경로가 유지된다. 캐시 전체 삭제는 하지 않는다.
6. 제공자 토큰·청구 로그와 원장을 대조해 누락률 및 실제 평균 비용을 측정한다. 베이스라인과 같은 챕터 소비 분포로 비교하기 전에는 절감률을 발표하지 않는다.

- 합성 통합 테스트: 기존 생성 1회 후, 승인 블록을 등록하고 AI API 키를 제거한 동일 조건 API 요청이 200/aiSkipped=true로 성공했으며 공급자 호출 수는 1에서 늘지 않았다.

- **운영 실측:** 사용자당 평균 비용·실제 실패율·캐시 적중률·AI 생략률·절감률은 모두 미측정.
- **추정 원리:** 승인 블록으로 전체 품질 검사를 통과한 요청은 생성/보정/검수 API 비용이 발생하지 않는다. 실제 적중 비율을 모르므로 전체 절감 %는 제시하지 않는다.

## 남은 요구사항 — 완료로 간주하면 안 됨

- 블록의 최고/최악/갈림길/환경 등 장면 의미를 별도 필드로 구조화하고 실제 챕터 계약과 대응하는 편집·검수 UX.
- 여러 조건군에 재사용 가능한 블록 범위 확장. 현재 전체 claim 서명은 보수적이므로 검증된 조건값이 달라지면 재사용률이 낮아질 수 있다.
- 부족한 문단만 선택 생성하는 hybrid 엔진, 챕터 전체 retry 축소, 형식 보정 AI 호출의 규칙 기반 대체.
- 조건별 검색 인덱스/유사도 중복 탐지 고도화, 챕터 간 RAG/원국 분석 스냅샷 재사용.
- 변경 지식 감지 → 부족 블록 탐지 → 중복 없는 연구 과제 → 예산 예약 → 블록 후보 제작 → 검수/게시의 자동 루프.
- 사전 제작 작업의 일/월 예산, 전역 호출/블록 수 상한, 자동화 스케줄러 연결. 기존 연구 예산은 있으나 신규 블록 제작과 자동 연결되지 않았다.
