# 챕터 책임·운명 선언 개편 — 수정 전 조사

2026-10-14. 기존 미커밋 변경을 보존하여 확장한다.

## 원인

- engine.js → report/v2/saju-data.js → content/IK 규칙 검색 → reading-flow.js의 15개 공통 카드 → full-reading.js → /api/movingtoon-reading → viewer.js/pdf.js.
- reading-flow.js가 모든 카드에 같은 우세 십성 TRAITS, 신강약·통근 소개를 삽입한다. 재물·연애 등의 문장 일부만 교체하므로 비 AI 경로에서도 반복된다.
- domainsFor는 재물/직업에 공통 ACTION을, 개운에 SELF를 추가한다. 주제와 무관한 일반 기질 규칙이 섞일 수 있다.
- 공통 AI 지시는 원국 전체 재검토와 초안 재작성이다. 챕터별 제외 항목·기질 비율·필수 항목과 독립 후킹 계약이 없다.
- full-reading.js의 챕터 간 검사는 문단의 공백 제거 후 완전 일치뿐이며, 동시 생성은 선행 챕터를 보지 못한다.
- 근거 기반 신규 엔진은 출처·조건을 검사하지만 기본 legacy 모드, 챕터 책임·후킹·의미 검토가 없다.

## 수정 범위

공유 챕터 정책, 주제별 사실/분석 슬롯, 관련 판단 선택, 전용 작성 지시, 기질 비율/의미 중복/근거 검토, 독립 후킹과 설정·검토 API, 관리자 편집·미리보기·재생성, 화면/PDF의 동일 결과.

## 보존

engine.js와 자미두수 계산은 변경하지 않는다. Supabase 스키마·기존 IK 및 모듈 DB·자료 청크·프로필·결제·이미지·영상·R2는 삭제/초기화하지 않는다. 기존 미커밋 파일을 덮어쓰지 않고 필요한 부분만 확장한다. 설정은 기존 ik:engine:settings 및 이력을 확장한다. 후킹 직접 수정은 검토된 판단과 계산 서명에 연결해 다른 원국에 전용 문장이 유출되지 않게 한다. 새로 생성하는 리포트에 적용하며 기존 저장 리포트는 재작성하지 않는다.

운영 DB 연결과 실제 모델 생성은 로컬 모의 검증과 구분해 보고한다. 기존 legacy/shadow/grounded 설정과 롤백은 유지한다.

## 구현 결과

- `report/v2/chapter-policy.js` / `functions/_chapter-policy.js`: 본래의 나·재물·연애/결혼·일/사업·운의 흐름·개운의 목적, 필수/제외 항목, 기질 글자 비율, 문체·분량·전용 프롬프트·후킹 계약을 화면/서버가 공유한다. 재물·연애·일의 일반 기질 설명은 최대 5%, 흐름·개운은 0%. 관리자 설정으로 이 상한을 올릴 수 없다.
- `reading-flow.js`: 기존 15개 읽기 섹션과 보조 챕터를 보존하며 재물·관계·직업·시기·개운 초안을 분리한다. 자료가 없는 전통 판단을 비중으로 만들어 대신하지 않는다. 원국·십성 위치·운 계산표 및 현실 점검 초안은 해석 자료와 구분한다. 극단 강약·학파 후보 차이·시간 미상의 검토 경고를 유지한다.
- 브라우저 조사에서 추가 원인을 발견했다. 보호된 `deep-*` 보조 챕터의 `aiEnabled:false`가 `list.every`로 집계되어 주요 챕터의 AI 생성까지 껐다. 이제 주요 챕터의 명시적 관리자 설정을 기준으로 하고 보조 계산 화면은 그대로 보호한다. 관리자 직접 OFF 설정을 강제로 켜지 않는다.
- `functions/_chapter-engine.js`: 확인된 판단에서 해당 주제의 근거만 선택한다. 재물에는 MONEY, 연애/결혼에는 LOVE/MARRIAGE, 직업에는 CAREER를 사용한다. 운의 흐름은 실제 시간 조건이 있는 판단, 개운은 앞선 판단의 행동 전략을 연결한다. 원국 사화를 시간 조건으로 오해하지 않는다.
- 생성 API는 챕터 정책을 전달하고 문장 중복·유사 성격 개념·기질 비율을 검사한다. 근거 기반 모드의 별도 AI 검토는 주제 이탈, 근거 이탈, 계산 불일치, 확정적 시기 주장, 후킹 재설명, 의미 중복 및 필수 항목의 covered/missing-evidence/not-covered를 검사한다. covered는 전달한 판단 ID를 요구한다. 근거가 있는데 빠진 항목과 초과 기질 비율은 거부한다. 빈/잘못된 검토 응답도 채택하지 않는다.
- 일반 기질의 유사 의미 검사에는 책임 지속·실행 주도·세밀함·기준 고수·숙고의 동의 개념 정규화 및 문자 n-gram을 사용한다. 같은 원국 근거를 실제로 다른 분야의 작용으로 확장하는 것은 허용하며, 독립 AI 검토가 단순 문자열 검사의 한계를 보완한다. 후속 챕터는 선행 결과를 전달받도록 순차 생성한다.
- 후킹은 실제 조건과 자료 인용을 가진 단일 판단에서 선택한다. 문장을 중간에서 잘라 조건을 없애지 않는다. 길이가 맞지 않거나 관리자가 문체를 변경하면 AI가 근거 범위 안에서 별도 작성하고 검증한다. 반대 판단과 예외를 해설에 보존한다. 사용자 이름은 기기에서 붙이고 외부 모델에 이름·원본 생년월일을 보내지 않는다.
- `functions/api/chapter-hook.js`: 인증된 관리자 미리보기, AI 재생성, 직접 수정 저장, 수정 해제를 지원한다. 수정은 계산 서명·판단 서명에 묶는다. AI 재생성은 미리보기만 반환하고 자동 저장하지 않는다. 직접 수정은 독립 의미 검토가 통과해야 저장한다(검증된 규칙의 원문을 그대로 채택하는 경우 별도 모델 호출 불필요). 저장 전 자료와 설정을 다시 읽고 변경된 근거는 거부한다.
- 관리자 → **AI 풀이 → AI·서비스 연결 → 신규 해석 엔진 → 챕터별 책임과 후킹 설정**에서 6개 정책을 편집한다. **풀이 테스트**에서 원국 분석 후 후킹 미리보기·근거 검토·직접 수정·재생성한다. 본문 설정과 후킹 수정의 미저장 상태를 분리했다. 풀이 테스트는 의미 검사, 기질 비율, 필수 항목 커버리지와 계산·근거 경고를 표시한다.
- 화면 첫 장은 챕터명·한자 → 이름을 붙인 선언 → 2~3문장 해설 → 본문 순서다. 아직 읽지 않은 장의 비동기 후킹도 갱신한다. PDF는 동일한 `chapterHook`과 채택된 본문을 사용하고 예전 서두를 중복 삽입하지 않는다.

## 저장 및 적용

새 테이블·파괴적 마이그레이션은 없다. 기존 `ik:engine:settings`에 `chapters`, `semanticReview`, `hookOverrides`를 추가하고 기존 `ik:engine:history`로 이전 설정을 보존한다. Supabase/KV의 기존 `ik:` 라우팅을 그대로 사용한다. 자료 비활성화·계산/판단/정책/문체/선행 문장 변경은 캐시를 분리한다. 저장 리포트를 일괄 재작성하지 않는다.

설정이 없는 환경의 기본값은 **grounded + 독립 의미 검토**다. 이미 저장된 `legacy`/`shadow`와 `INTERPRETATION_ENGINE_MODE`의 우선순위는 유지한다. 운영에 명시적인 legacy 설정이 있다면 자동 전환되지 않는다. 관리자에서 실제 자료 검수 후 모드를 바꿀 수 있고 legacy로 롤백할 수 있다. 자료가 부족하거나 생성 검증에 실패하면 그 사실을 표시하며 근거 없는 새 풀이를 채우지 않는다.

동시 설정 저장의 버전 확인은 기존 KV 어댑터의 기대 버전 검사다. 트랜잭션 수준의 원자적 compare-and-swap은 아니므로 기존 제한은 남는다. AI 사용량이 누락되면 비용을 0으로 표시하지 않는다. 본문·검토 호출의 사용량을 합산하며 비용 상한을 보수적으로 예약한다. 실패한 모든 공급자 호출의 청구 비용을 완전히 집계하는 것은 이번 변경 범위 밖이다.

## 남은 운영 검수

이 작업에서는 운영 DB나 R2에 쓰거나 배포하지 않았다. 실제 운영 자료 백업, 각 주제의 검수 자료·자미두수 규칙 커버리지, 실제 AI 결과의 깊이·의미적 근거 함의·챕터 간 반복, 운영 이미지/영상 재생과 실기기의 PDF 다운로드는 실제 연결 환경에서 확인해야 한다. 빈 DB를 검수된 자료로 채우는 것은 자동으로 수행하지 않았다.

자동 검증·독립 AI 검토가 명리학의 학술적 정확성이나 미래 예측 정확도를 입증하지 않는다. 구현과 로컬 연결·회귀 검증은 완료했지만, 실제 자료를 연결한 모든 사용자 리포트의 품질과 운영 배포 완료까지 주장하지 않는다.
