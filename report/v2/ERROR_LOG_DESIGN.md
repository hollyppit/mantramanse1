# 뷰어 오류 수집 설계안 (NEXT_PLAN D · "챕터별 오류 로그")

작성 기준: `main`(9be3d93 이후). **코드 변경 없음 — 설계안.** 확인하지 못한 항목은 "확인 못함"으로 적었다.
목적: 사용자 화면(무빙툰 뷰어·허브)에서 난 오류를 **개인정보 없이** 모아, 관리자 "서비스 점검" 탭에서 "어느 챕터·어느 기능에서 얼마나 자주 나는가"를 본다.

## 1. 지금 상태 (코드로 확인)

| 항목 | 확인 내용 |
|---|---|
| 전역 오류 처리 | `report/v2/*.js`·`report/hub/*.js` 에 `window.onerror`/`unhandledrejection` 핸들러가 **없다**. 개별 요소(`video.onerror`, `img` 오류)만 각자 처리 |
| 조용히 삼키는 곳 | `try { … } catch (e) { }` 가 뷰어에 다수(예: `viewer.js:62` 심층 챕터 `Deep.augment` 실패, `ik-deep.js` 호출 실패 시 `null`, `exploreEntry` 실패 시 `console.error` 후 대체 흐름). 실패해도 운영자는 모른다 |
| 이벤트 분석 | `report/v2/analytics.js` 는 메모리 집계·`dataLayer`·`window` 이벤트뿐이고 서버로 보내지 않는다. `funnel()` 이 `gtag` 를 **있으면** 부르지만 이 저장소의 HTML 에 GA/GTM 스크립트는 없다(운영에서 주입되는지는 **확인 못함**) |
| 서버 쪽 패턴 | 공개 쓰기 API 의 선례가 있다: `api/ik.js` `deepForService` 는 IP·시간당 한도(`rl:ikdeep:<ip>:<시각>`, 기본 20)를 KV 로 센다. 저장소 어댑터(`_store.js`)는 접두어 `rl:`·`ik:`·`src:` 등을 Supabase 로 라우팅하고 `expirationTtl` 을 지원한다 |
| 관리자 읽기 | "서비스 점검"(`report/admin/v2-quality.js`)은 이미 읽기 전용 섹션을 모으는 화면이다 |

→ **결론**: 오류를 보내는 채널이 없어 새 공개 쓰기 엔드포인트가 필요하다. 이것이 이 설계의 핵심 위험이다(§6).

## 2. 범위

**수집한다**
- 잡히지 않은 오류(`error`), 처리되지 않은 약속 거절(`unhandledrejection`)
- 코드가 이미 잡았지만 기능이 꺼지는 곳의 명시적 보고(`R.ErrLog.report('caught', {where})`): 심층 챕터 삽입 실패, 탐험 홈 진입 실패, 계산 결과 정리 실패, 영상·이미지 에셋 로드 실패(슬롯 id 만)

**수집하지 않는다**
- 이름·생년월일·성별·입력값·풀이 문장·`localStorage` 내용·쿠키·계정 식별자·IP 저장
- 스택의 전체 URL(쿼리 포함)·사용자 에이전트 원문

**이번 단계가 아닌 것**: 성능 지표, 사용자 행동 분석, 재현용 세션 기록, 알림(메일·메신저).

## 3. 데이터 모델

### 3.1 클라이언트가 보내는 한 건 (POST 본문, 합계 2KB 이하)

| 필드 | 값 | 규칙 |
|---|---|---|
| `kind` | `error` \| `rejection` \| `caught` \| `asset` | 열거형 |
| `where` | 기능 이름(예: `deep.augment`, `explore.entry`, `asset.video`) | 영문·숫자·`._-` 40자 |
| `msg` | 오류 메시지 | **정리 후** 160자 이하(§4) |
| `src` | 스크립트 파일 이름(디렉터리·쿼리 제외, 예: `viewer.js`) | 40자 |
| `line` | 줄 번호 | 정수 |
| `ch` | 지금 보던 챕터 id(예: `c06`, `deep_car`) | `[\w.-]{1,40}` 만 |
| `world` | 세계 id(`w1`~) | 선택 |
| `flow` | `explore` \| `classic` \| `preview` | 열거형 |
| `v` | 콘텐츠 버전(`rep.meta`·`content.version`) | 40자 |
| `env` | `{ mobile: bool, br: 'safari'\|'chrome'\|'edge'\|'firefox'\|'other', saveData: bool }` | 사용자 에이전트를 **분류만** 한다 |

### 3.2 서버 집계 (일 단위, 원문 로그를 쌓지 않는다)

```
err:day:YYYY-MM-DD → {
  total: n, dropped: n,                      // dropped: 상한 초과로 버린 건수
  sigs: { <sig>: { n, first, last, kind, where, msg, src, line,
                   ch: { <chapterId>: n }, env: { mobile: n, br: { … } }, v: { <version>: n } } }
}
sig = 짧은 해시(kind + where + src + line + msg 앞 80자)
```
- 하루 `sigs` 는 **최대 200종**. 넘으면 `dropped++` 만 한다.
- `expirationTtl` 14일(결정 D1). 접두어 `err:` 를 `_store.js` ROUTED 에 추가해 Supabase 쪽에 두는 안을 권장(쓰기가 잦은 키 → 기존 관례).
- 키가 하루 하나라 KV 의 "같은 키 1초 1쓰기" 제한과 읽고-쓰기 경합(마지막 쓰기 승리)이 있다. **카운터가 약간 덜 세어질 수 있음을 받아들인다**(정확한 집계가 목적이 아니라 "자주 나는지" 가 목적). 대안은 시간대별 키 분산(`err:day:…:HH`)이며 경합을 24분의 1로 줄인다.

## 4. 개인정보 보호 규칙 (가장 중요)

1. **스크러버**(순수 함수, 클라이언트·서버 양쪽에서 같은 규칙):
   - 날짜 모양(`1992-06-23`, `1992.6.23`, `19920623`)과 4자리 이상 숫자 열 → `#`
   - 이메일·URL → `<url>`, 쿼리 문자열 제거
   - 따옴표 안의 값은 12자까지만 남기고 `…`
   - 160자 절단
2. **허용 목록 방식**: 서버는 본문의 알려진 필드만 읽고 모양을 검증하며 나머지는 버린다(`cleanItem` 과 같은 방식).
3. 서버는 IP 를 **저장하지 않는다**. 한도 계산용 카운터 키에만 해시 없이 일시적으로 쓰고(`rl:` 접두어, 1시간 TTL) 집계에는 넣지 않는다.
4. 오류 메시지에 사용자 값이 섞일 수 있는 곳(예: 계산 입력을 문장에 넣는 `throw`)은 보고 지점에서 `where` 만 보내고 `msg` 를 비운다(`caught` 보고는 `msg` 를 **쓰지 않는 것**이 기본).
5. 스크러버는 테스트로 고정한다(§8): 이름·날짜·이메일이 메시지에 들어간 합성 오류가 정리 후 남지 않아야 한다.

## 5. 인터페이스

### 5.1 클라이언트 `report/v2/errlog.js` (신규, 가볍게)
- `window.addEventListener('error' | 'unhandledrejection')` + `R.ErrLog.report(kind, ctx)`.
- **상한**: 세션당 최대 5건, 같은 서명은 1회, 보고 중 발생한 오류는 무시(재귀 방지).
- 전송: `navigator.sendBeacon`(없으면 `fetch(keepalive)`), 실패해도 재시도·사용자 알림 없음. 응답을 기다리지 않는다.
- **끄는 조건**: `?preview=1`(관리자 미리보기), `navigator.doNotTrack === '1'`(결정 D2), 서버가 `204`+헤더로 꺼짐을 알린 경우(다음 세션부터).
- `?debug=1` 이면 보내지 않고 콘솔에만 출력(`analytics.js` 와 같은 방식).

### 5.2 서버 `functions/api/errlog.js` + 순수 로직 `functions/_errlog.js`
- `POST /api/errlog` (공개)
  - 본문 2KB 초과 → 413, 잘못된 JSON → 400, 같은 출처(`Origin`/`Referer` 호스트) 아니면 204 로 조용히 버림
  - IP·시간당 한도(기본 30, `env.ERRLOG_HOURLY_LIMIT`), 초과 시 429 (클라이언트는 무시)
  - `env.ERRLOG_ON` 가 있으면 즉시 204(끄는 스위치)
  - 항상 `204` 로 응답(성공·거절 구분을 외부에 주지 않는다)
- `GET /api/errlog?days=7` (관리자) → 일별 집계 목록. 인증은 `isAdmin`.
- 순수 로직(`scrub`, `signature`, `cleanReport`, `merge`)은 Node 테스트 가능하도록 `_ik.js` 처럼 import 없는 파일로 둔다.

### 5.3 관리자 화면
"서비스 점검" 탭에 읽기 전용 섹션 **"뷰어 오류 (최근 7일)"**:
- 총 건수·종류별·서명별 상위 20(메시지, `where`, 파일:줄, 발생 수, 챕터 분포, 모바일 비율, 콘텐츠 버전)
- "특정 콘텐츠 버전부터 늘었는가" 를 볼 수 있게 버전별 건수
- 마크다운 내보내기에 포함, 아무것도 수정하지 않음

## 6. 위험과 완화

| 위험 | 완화 |
|---|---|
| 공개 쓰기 엔드포인트 악용(스팸·저장소 부풀리기) | 본문 2KB, IP 시간당 한도, 같은 출처 확인, 하루 서명 200종 상한, `err:` TTL, `ERRLOG_ON` 스위치. 집계만 저장하므로 쓰기 한 번의 크기가 고정 |
| 개인정보 유입 | §4 스크러버·허용 목록·메시지 비움 규칙·테스트. 수집 항목을 `PRIVACY` 문서/개인정보 처리 안내에 반영해야 하는지는 **확인 필요**(법적 판단은 이 문서 범위 밖) |
| 오류 수집이 오류를 만든다 | 모든 전송을 `try/catch` 로 감싸고 응답을 기다리지 않음, 재귀 방지, 세션당 5건 상한 |
| KV/Supabase 쓰기 증가 | 요청당 쓰기 2회(한도 카운터 + 집계). 세션 5건·IP 30건/시간 상한으로 제한. 쓰기 증가량은 운영 트래픽을 모르므로 **확인 못함** — 첫 주에 `dropped`·`total` 로 점검 |
| 집계 경합으로 부정확 | 허용(§3.2). 필요하면 시간대별 키 분산 |
| 사용자 환경 차단(브라우저 확장·광고 차단) | 수집이 비는 것은 정상으로 본다. 절대 수치가 아니라 변화·상대 비교용 |

## 7. 단계

| 단계 | 내용 | 사용자 화면 영향 |

## 8. 검증 계획

- **순수 로직**(`tests/errlog-sim.js`): 스크러버(날짜·숫자 열·이메일·URL·따옴표 값·길이), 서명 안정성, `cleanReport` 허용 목록(알 수 없는 필드·잘못된 열거형·긴 값 거절), 집계 병합(서명 상한 200·`dropped`), 한도 카운터.
- **API**(`compose-api-sim.js` 방식): 모의 KV 로 413·400·429·204·`ERRLOG_ON`·관리자 GET 인증.
- **클라이언트**: 합성 `error`/`unhandledrejection` 으로 상한(세션 5건)·중복 제거·재귀 방지·미리보기에서 꺼짐을 DOM 없이 검사할 수 있게 전송 함수를 주입식으로 만든다.
- **브라우저**: 개발 서버에서 의도적으로 오류를 일으켜 집계가 점검 탭에 나오는지 확인(로컬 모의 서버는 `functions/api/errlog.js` 를 실제로 실행하도록 `.claude/report-dev.js` 에 라우트 추가).

## 9. 결정이 필요한 것

- **D1 보관 기간**: 14일(제안) / 7일 / 30일.
- **D2 Do Not Track**: 존중해서 수집 안 함(제안) / 무시. 수집 항목에 개인정보가 없어 필수는 아니다.
- **D3 에셋 로드 실패 포함 여부**: 영상·이미지 실패는 소음이 클 수 있다(느린 네트워크). 포함하되 슬롯 id 별 집계로만 보는 것을 제안.
- **D4 개인정보 처리 안내 반영**: 수집 항목(오류 종류·챕터·브라우저 분류)을 안내 문구에 넣을지 — 운영 정책 결정.
- **D5 알림**: 지금은 점검 탭에서만 확인(제안). 급증 알림은 후속.

## 10. 확인 못한 것

- 운영 환경에 GA/GTM 이 주입되어 있는지(있다면 `exception` 이벤트로 대체 가능하나 이 저장소만으로는 확인 불가).
- 운영 트래픽 규모(쓰기 증가량 추정 불가).
- Supabase 라우팅이 운영에서 켜져 있는지(`SUPABASE_URL` 설정 여부).
- 개인정보 처리 안내 문서의 현재 내용.

## 11. 구현 기록 (결정 D1~D3 "제안대로" 반영)

### 결정
- **D1** 보관 14일 · **D2** Do Not Track 존중(수집 안 함) · **D3** 에셋 로드 실패 포함(슬롯이 아닌 `asset.video` 기능 단위, 메시지 없음)
- D4(개인정보 처리 안내 반영)·D5(알림)는 미결 — **D4 가 정해지기 전에는 서버 수집을 켜지 않는다.**

### 설계 대비 변경점
- **수집 스위치를 반대로 했다**: `ERRLOG_OFF` 대신 `env.ERRLOG_ON === '1'` 일 때만 저장한다(기본 꺼짐 = 안전한 쪽). 꺼져 있으면 `204` + `x-errlog: off`, 클라이언트는 그 세션에서 더 보내지 않는다. 문서 본문의 `ERRLOG_OFF` 표기는 모두 이 이름으로 바꿨다.
- **스크러버를 더 엄격하게 했다**(시험으로 드러난 한계): 날짜·4자리 이상 숫자·**시각**(`14:30`)·이메일·URL·긴 따옴표 값에 더해 **한글·한자 연속은 `<ko>` 로 바꾼다**. 이름 같은 사용자 값은 문장 속에서 모양만으로 가려낼 수 없기 때문이다. 오류 위치는 `where`·`src:line` 이 알려 준다. 그래서 한국어로 쓴 우리 코드의 오류 문구는 메시지에서 읽히지 않는다(의도된 손실).
- 저장소 라우팅에 `err:` 접두어를 추가(`functions/_store.js` ROUTED). Supabase 가 꺼져 있으면 기존대로 KV.

### 검증
- `tests/errlog-sim.js` 통과, 전체 `*-sim` 65개 통과.
- 로컬 서버에서 실제 브라우저 확인: 의도적 오류에 이름·생년월일·시각·이메일을 섞어 던졌을 때 서버에는 `Uncaught Error: boom <ko> <ko> # # <email>` 로만 저장, IP 는 집계에 없음, 관리자 점검 탭에 "수집 켜짐 · 2건"으로 표시.

### 켜는 방법·되돌리는 방법
- 켜기: Cloudflare Pages 환경변수 `ERRLOG_ON=1`(선택 `ERRLOG_HOURLY_LIMIT`). **D4 결정 후에 켠다.**
- 끄기: 환경변수를 지우면 서버가 즉시 저장을 멈춘다. 클라이언트는 다음 세션부터 요청을 보내지 않는다.
- 롤백: `report/v2/index.html` 의 `errlog.js` 스크립트 태그 제거 + 환경변수 제거.

### 한계
- 허브(`report/hub`)는 전역 오류 핸들러만 붙였다(`flow: hub`, 챕터 칸에는 화면 이름 `today`·`tarot` 등). 허브에는 명시적 보고 지점이 아직 없다.
- `Origin`/`Referer` 를 모두 지우는 환경에서는 수집되지 않는다(조용히 버림).
- 오류의 `src` 는 브라우저가 알려 줄 때만 채워진다(교차 출처 스크립트는 "Script error." 로 가려질 수 있음).
