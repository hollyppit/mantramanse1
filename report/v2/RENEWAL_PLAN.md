## 3. 지시서와 현재 코드·기존 결정의 충돌 지점

1. **구조**: 현재는 사용자가 직접 요청한 "자동 스크롤 단일 문서"(STORY_REDESIGN 4·5차). 지시서는 ACT 후 "탐험 홈 → 임의 챕터 선택". 방향이 반대라 정책 결정이 필요하다.
2. **분류 명칭**: 지시서의 "6분류"는 현 구조(4+2+4)와 다르다. 현 명칭을 기준으로 삼는 것을 제안한다.
3. **유료화**: 서버 권한 검증을 하려면 사용자 식별(계정 또는 토큰)과 결제 연동이 먼저 필요하다. 가격은 지시서대로 확정하지 않는다.
4. **DB**: `kv` 하나만 있다. 풀이 규칙·근거·에셋을 관계형으로 옮길지, kv 위에 네임스페이스로 얹을지 결정이 필요하다.
5. **텍스트 애니메이션**: 인트로 외 제거는 현재 본문 구현과 대체로 부합하나 `fx.js`(51KB) 사용처 점검이 필요하다.
6. **TTS**: 위 표 참고.

### 3단계(운명 타임라인 + 옛 6분류 복원) — 완료
- 6분류 복원은 **표시 계층**(`report/v2/luck6.js`)으로만 했다. 엔진 값·규칙은 불변(engine-baseline 통과). 판정 순서는 옛 구현과 같다: 방어(강) → 변동 → 방어(약) → 주 흐름. 임계값은 `Luck6.CONFIG` 한 곳.
- 옛 구현(e68a17d 직전)과 비교(`tests/luck6-compare.js`, 120차트×대운·세운·월운 4,200건): 흐름 점수·작용 강도·변동성 100% 동일, 변동기·방어기 판정 100% 동일, 4종 활동 분류 98.9% 일치(나머지 1.1%는 이후 추가된 시간 단위별 배율 LEVEL_WEIGHTS 로 인한 주 흐름 차이).
- 타임라인(`timeline.js`): 대운 → 10년(세운) → 12개월(월운). 시간의 회랑 세계 상세 화면에 표시. 카드마다 판정 근거·분야 점수(재물·직업·애정)·"근거 보기"·읽는 법(점수 의미)·면책 문구.
- 관찰: 변동기가 전체의 약 32%로 많이 나온다(옛 구현도 동일). 사용자 체감상 과다하면 `Luck6.CONFIG.volatility` 임계를 조정하는 것이 아니라 엔진의 VOLATILITY_CONFIG 를 검토해야 하며, 이는 비교 테스트를 먼저 만든 뒤 결정할 사항.
